另外运行了真实 Chromium 浏览器流程，结果通过：页面登记 TEST 来源 → 创建原卡审查请求 → 下载身份任务卡 → 导入两方回执 → 本地核对来源 → PASS/FAIL 材料自动进入收件箱 → 原监看“裁决中心”标签可见双方材料。最终人工批准记录数为 0，原生事件哈希链通过。

新接入口覆盖：

- 缺 DSH/缺第二方不提交，未确认来源不计票，自称 identity_verified 不被信任。
- 非 DSH 固定方、同实际来源别名、未知后台拒绝；任意注册的独立测试后台能够接入。
- 正文/初审漂移失效；不合格正文、工具标记、缺证据、旧哈希与无效时间退回并保留。
- 并发回执幂等、内容冲突、并发投递单一 ACK；离线重试与接收端写入后异常回滚。
- 更换第二方沿用有效 DSH 卡，历史 FAIL 保留在材料中，不通过换人变成全 PASS。
- 最新无效回执不能继续沿用旧成功；重启保留队列、来源和确认。
- 评分如实保留，不补造缺失维度或分数；不会批准、发布或增加正式复用计数。
- 原生事件链损坏时拒绝双审接入写入。

两个前端 JS 文件通过 node --check。浏览器实际加载并操作新增页面，也验证了旧监看页面的裁决标签接线；不是只检查静态 HTML。浏览器与 HTTP 流程全部使用隔离 TEST 夹具，不是真实 DSH 结论。
