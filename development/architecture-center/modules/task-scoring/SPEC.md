# 任务综合评分与Agent＋模型周阶段评估

模块ID：task-scoring。2026-10-28用户最新修订；本地候选，不表示已部署生产。

2026-11-08 卡51补定：评分对象是整条业务任务，宿主与Worker在任务结算时自动为每个参与池节点记分，不等待用户交付，不依赖经验应用记录。回执被统一入口接收且任务完成记1；超时、无进展被停、拒收或任务放弃记0。用户事后要求修改不扣分。宿主自身、健康探针与测试运行不计分；经验初审和终审仍由用户决定。

同一任务＋同一节点＋实际执行角色只记一次。配置模型在派单时冻结，review与collaborate分账，both仅表示两种角色均可承担。多个步骤、重复回执、重复结算与重放不重复加分。手动接口更正自动评分须使用当前修订号，保留前值与调整量，不新增样本、不移动周桶。旧外部工作回执的手动核验接口保持兼容。

按Asia/Shanghai自然周（周一至周日）汇总累计分、任务数、成功率和任务类型。不同模型分别记录，不形成永久能力总分。执行事实与历周记录保留，查询和选择须明确周次及任务范围。不记录资源投入：不采集token、费用或算力消耗；工作起止时间和耗时是过程记录，本版不按耗时加权。

择优先按授权、实际角色、启用、当前测试资格及独立性筛选，不按dsh/peer厂商槽位筛选。选择两个同角色节点时：第一位按同角色本周分；第二位优先近四个自然周（本周及前三周）少于三次记分的独立可用节点，低样本不止一个时按最近同角色派单时间从早到晚轮换；否则也按周分。只有一个可用节点时不留位，仍不得绕过双审独立性门禁。旧dsh/peer可读，没有固定默认审查名单。所有分数同时显示任务数及成功率；分数不能宣称跨任务通用能力。

数据库保存核验后评价和可验证事件链，日工作文件保存过程及完整回执。评分表必须与最新审计事件及原工作证据相符；先前日志被覆盖、证据失效或评分缓存被篡改时拒绝用于择优。已发布长期经验仍按原批准流程进入第二大脑。

新经验价值分单独记：各审查员只提供0–10分；均分≥6进入初审，<6丢弃（候选仅留摘要和分数）；分差≥4或重复经验直接进入初审并携带依据。评分中心的准入判断不替用户批准，也不替换真实隔离验证门禁。

共享结算和排序实现位于development/integrated-candidate/src/xiaoba_agentos/task_scores.py；价值分判定在value_scoring.py。接入口task_scoring.py保留周查询和手动更正，node_runtime.py与核心pool_dispatch.py使用同一排序。HTTP入口保持task-assess、weekly-scores和workday-inputs；原物理模块拆分仍属B6后续范围。
