# 任务综合评分与Agent＋模型周阶段评估

模块ID：task-scoring。2026-10-28用户最新修订；本地候选，不表示已部署生产。

评分对象是整条业务任务。主入口核验任务产物、测试、返工及必要的用户验收后，针对当次Agent＋配置模型记good或not_good；后台写在当日Markdown中的内容是证据输入，不是自评分授权。健康探针不计业务能力分，经验初审和终审仍由用户决定。

候选初始量化口径：good每任务＋1，not_good为0，不另扣失败分。以实际来源、配置模型和任务ID去重；多个步骤、重复回执和重放消息不能重复加分。更正原评价须使用当前修订号，保留前值与调整量，不新增第二份任务分。

按Asia/Shanghai自然周（周一至周日）汇总累计分、任务数、成功率和任务类型。不同模型分别记录，不形成永久能力总分。执行事实与历周记录保留，查询和选择须明确周次及任务范围。不记录资源投入：不采集token、费用或算力消耗；工作起止时间和耗时是过程记录，本版不按耗时加权。

择优先按授权、启用状态、当前配置健康资格和适用条件筛选，再参考同类任务的周数据。在当前接入口，多名合格节点且有唯一正分优胜组合时可直接选择；没有样本或无法区分时沿用已有补问机制，不伪造排序依据。周总分会受到派单量影响，因此必须同时保留样本量、成功率及任务类型，不能据此宣称跨任务通用能力。

数据库保存核验后评价和可验证事件链，日工作文件保存过程及完整回执。评分表必须与最新审计事件及原工作证据相符；先前日志被覆盖、证据失效或评分缓存被篡改时拒绝用于择优。已发布长期经验仍按原批准流程进入第二大脑。

实现位于development/review-ingress/xiaoba_review/task_scoring.py，依赖同包workday.py、agent_workspace.py和node_runtime.py；候选HTTP入口包括task-assess、weekly-scores和workday-inputs。原物理模块拆分仍属B6后续范围。
