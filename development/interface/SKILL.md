# 小八 AgentOS v1.6.6

审查和协作只来自 Agent 池里用户打开的节点。要审查的任务需要至少两份彼此独立的合格结论才进入本地确定性裁判。独立性看入口程序和模型。宿主可以补一票，条件写在 `docs/STANDBY_POLICY.md`。配置模板不带默认节点。模型由用户写在节点上；小八不替用户改模型，也不读取各家桌面。

## 三条执行底线

- B09 配置一致：会话、已安装入口、后台进程和裁决中心必须使用内容一致的配置；发现分歧就拒绝执行。配置结构与读取它的代码同批修改。
- B19 非答案不算成功：空输出、只有工具调用标记或泄露思考过程的输出不得交付、复用或进入记忆；检测不能误伤正常正文。
- B20 恰好结算一次：任务完成与经验候选登记必须原子成功或一起失败，重复调用不能重复结算；状态变化进入可校验事件链，链坏则停派任务，异常须释放租约。重试只补失败侧且不超预算。

## 上下班和消息路由

- “上班了小八助理”：`session-start`。只查本地 doctor、节点是否开启、测试是否通过、入口是否还在，不发真实探针。审查节点不足单独报告，不把 doctor 的 ok 打成假。要审查的任务在池里凑不够两份独立结论之前不入队。本地检查不等于实时模型可用。
- 工作会话的新消息：调用 `intake "消息" --message-id 唯一消息ID`；有动作需求加 `--requires-action`，用户明确要求小八加 `--explicit-agentos`；需要任务时同一次调用加 `--submit`，不重复提交。返回 `blocked_local_health` 表示后台当前无法执行、任务未入队：按 `blockers` 向用户说明原因并先恢复（通常是重新“上班”，或者在对应 CLI 里登录、选好模型），不要自行加 `--queue-when-blocked`，除非用户明确要求先排队。
- `direct`：会话模型直接回答；`agentos_multi`：跟踪同一个任务等待两个后台合格结果；`review`：进入用户审核；`ask_user`：只问必要边界。不能把后台文字当已执行补丁。
- 可拆分实现走 `collaborate`，为 AGY/DSH 分别分工；宿主集成后，冻结新证据走 `collaborate-review`。两阶段都必须两者成功，审核不得复用工作阶段输出。参数见当前 `docs/COLLABORATION.md`。
- “下班”：`session-close`，展示待终审清单；下班不代表批量批准。

## 审核、恢复与边界

`review-list --stage all` 是动态审核入口；用户在浏览器里裁决的入口是小八监看中心的「裁决中心」标签 `http://127.0.0.1:8799/#review`（未开启时双击 `/Users/suzhizhou/Documents/私人助理/工具/小八监看/启动监看中心.command`），原 `127.0.0.1:8797` 独立页面已停用。监看中心没开时不能在浏览器里裁决，待审队列也不会同步到第二大脑，重新开启后补同步；CLI 的 `review-list`/`review` 不受影响。`review TASK_ID --stage delivery|final --decision approve|reject|revise|retire` 仅用于用户针对该候选明确作出的决定。两次批准绑定相同候选哈希；重建索引或正式发布软件版本都不批准待审经验。终审发布还必须完成敏感检查及 KnowLP 复验。

失败不静默换账号，也不静默启用其他后台。没有固定备用后台。审查员不够时按 Agent 池规则改派或停下问用户，不回退到任何写死的名字。历史任务里的 `standby.substituted` 事件仍能读出。账户额度、限流、503、超时、网络属外部故障，报告并写入该节点的健康，在有限次数内退避重试，不反复热改代码。认证失败不在原节点重试、不切账号，报告并等用户处理。单轮输出预算耗尽属任务级失败，不自动原样重发，手动恢复时提示拆分任务。同伴自动诊断与修复、Headroom 自动重启已退役。冻结任务只在用户显式 `task-resume TASK_ID --freeze-hash HASH` 后解冻。上班不发真实探针。

不得修改登录材料，也不得改动用户在各 CLI 里（或 DSH 桌面上）选定的模型来修复后台任务；不保存密钥、OAuth、原始聊天或未审核模型输出到第二大脑。这两条是 `/Users/suzhizhou/Documents/私人助理/AGENTS.md` 第 4、5、6 节的摘要，完整规则以那里为准。发布更新先候选验收，再经用户授权提升。

Agent池节点的常规任务没有总时长截止。掉线只看工作日志有没有变化：连续无进展默认300秒，可在节点资料里调整；人工转交和tmux等待不判掉线。运行时续租，执行权丢失须停旧CLI且不得结算。没有备用补位：节点掉线或失败时停下问用户，不自动改派固定后台。

## 用户公共规则：备份授权

- 没有用户直接、明确的备份要求，不得自行新建备份文件、备份目录或备份快照。
- 可以提醒用户是否需要备份；提醒、一般操作授权或发布授权都不等于备份授权。
- 本用户规则优先于工作流、技能和发布脚本的默认备份建议；未经明确授权，不得执行内置备份步骤。
- 本规则不授权自动删除已有备份。

## 失败恢复保留物（v1.6.2）

失败恢复只保留已认领原对象，不复制为备份；不自动清理、过期删除或进入检索。doctor与session-start显示待人工核对提醒，普通待核对不阻断接单、版本切换或新经验发布；真实发布门禁及索引错误仍按原规则拒绝。

用 xiaoba memory-retained-list 列出位置、身份与异常，重启后仍可查。用户亲自核对后逐个运行 xiaoba memory-retained-resolve ABSOLUTE_PATH --trash 移入废纸篓，或确已手动删除后运行 --confirm-deleted。两选一，无批量/自动清理。无身份的旧记录须先从清单核对并给出 --expect-dev DEV --expect-ino INO，不凭文件名盲目处理。失败按返回的实际位置、原因与重试条件处理；误捕获对象按清单人工核对。详见 docs/MEMORY_RECOVERY.md。


## 经验分类与受控验证（2026-10-17用户确认）

技术审查必须使用 submit --memory-kind audit；官方生成的技能审查说明自动识别。技术审查结果只保留审计，不自动进入经验裁决。B20在此明确审计分支：审计任务完成与审计回执原子结算，恰好一次；方法和规则仍与候选原子结算。不能用审计分类隐藏有复用价值的方法。

登记新经验默认 --kind method；只有用户明确偏好或规则依据时才选 --kind rule。方法初审后还须真实授权案例的隔离执行及AGY/DSH独立双审，才能由用户终审。两个模型重读旧文本不算再次验证。主力按任务卡写目标、材料、范围、验收、停止条件和回执；外派由用户转交，主力重核实际执行，不能把任务卡当完成报告。

遇到同类问题，使用稳定problem_key（问题标识）调用 memory-trial-match；问题标识未知时可 --query 关键词按原问题提出建议，必须再人工核对同类条件；只取得建议，不把未发布候选混入正常检索，不自动执行候选文字。主力在当前用户已授权范围内准备最小试验夹具和任务卡，显式 memory-trial-run TASK_ID --card FILE；memory-trial-status TASK_ID 读取新执行回执和两个独立审查结果。缺证据、失败、仅一侧或运行中不能终审。结果关联原候选；验证任务本身不产生第二张经验候选卡。

历史无分类候选保留旧流程并明确标注；不擅自清理或替用户重新裁决。完整可执行输入、沙箱限制及页面安装见 docs/EXPERIENCE_TRIALS.md。正式切换和包外页面安装仍由用户在自己的终端执行。
