# v1.6.5 当前架构

宿主 → 受发布校验保护的 CLI → 审计路由/冻结任务 → AGY 与 DSH 独立结果 → 确定性裁判 → 用户交付初审 → 用户终审 → 正式经验与索引复验。

AGY 经 agy CLI 本地登录、模型写在小八的节点配置里（`cli_routes.local_agy.model`），DSH 经 DeepSeek Harness 并复用其桌面当前设置，备用 Qoder 用用户在 qodercli 里上次选定的模型（v1.6.5 起，见 `docs/RELEASE_V1.6.5.md` 第十四节、第五十八节）。AgentOS 不选择模型、不查询上游列表、不维护本地后台的备用模型池。凭据留在各客户端，AgentOS 不打印或转存。

Worker、候选、双审、冻结恢复、审计链与可回滚发布的职责分离。用户裁决界面在小八监看中心（`127.0.0.1:8799`）；裁决后端沿用 `integrations/review-center` 的同一份审核代码，由监看中心按需拉起，不再是常驻的独立服务。监看中心没开时不能在浏览器里裁决，待审队列也不会同步到第二大脑，重新开启后补同步；CLI 的 `review-list`/`review` 不受影响。源清单、不可变 FILES 清单和运行指纹共同防止版本漂移；本地 doctor 不等于远程可用。

## 现行信任链

稳定入口是信任根：它只依赖发布索引与标准库，先校验不可变发布的全部文件，再加载该发布自身的代码。工作区源码不参与校验，也不被 Worker 执行；它仍须与发布逐文件一致，否则绑定检查失败并停止。审核流程只有 `review_flow.execute_review` 一条路径。

## 恢复机制

同伴自动诊断与自动修复、Headroom 自动重启退役；探测失败后不得**自动**再探测，也不得让同伴去诊断失败方，探测失败只允许记健康状态。Worker 不再租修复任务，历史修复记录与审计事件保留但不参加调度。AGY+DSH 的正常分工、独立审核与确定性裁判继续保留，两侧都须合格结果。

单侧故障继续保存成功侧输出、执行回执与冻结快照及各层哈希。新鲜真实健康探针只更新健康结果，不自动改变任务冻结状态，也不解冻任务；被冻结的任务保持冻结，由用户带 `--freeze-hash` 显式恢复，遗留的 `resume_ready` 记录同样只在用户显式恢复时推进。两种入口都只补跑失败侧，哈希、回执与环境复核不得省略。

恢复所要求的“失败侧当前有效的健康探测记录”，来自用户重新“上班”（`session-start`）时跑的真实探针，不是系统自动补探出来的结果。所以“探测失败后不得自动再探测”与“恢复要有新鲜健康记录”并不冲突：前者禁止的是自动重探和同伴诊断，后者要求的是用户下次上班时留下的真实探针记录。

外部故障与单轮输出上限是两件事，分开处理，不混为一类：

- 账户额度、限流、超时、网络、容量属于外部故障（分类为 `external_upstream`）：除下面的备用补位外，写入全局健康、拦住队列，允许在有限次数内有界退避重试，不反复热改代码或切账号。
- 认证失败也是外部故障（`external_auth`）：在原后台不重试、不切账号、不做退避；除下面的备用补位外，写入全局健康、拦住队列，报告并等用户处理。
- 备用补位（v1.6.5 起）：AGY 或 DSH 因上述外部故障或健康探针不通过而不可用时，备用后台 `qoder_review` 补上那一侧；被补位的主后台记为 `external_blocked`，后续任务在分派前就换成备用，直到用户下次“上班”的真实探针恢复它。补位公开留痕（`standby.substituted` 事件、结果字段、裁判记录、通知），每任务最多一次；两个主后台都不可用、或启用的主后台少于两个时不补、照常挡住。
- 健康状态的来源也是门禁：内部或未知类别的任务降级、未探针，都不能被解释为真实探针失败。接单、派发与构包共用 `standby_health` 判定；分派前事件保留 `health_evidence` 的状态、类别及探针标记白名单。事件标签与来源不一致或缺失时拒绝，不改变冻结任务。
- 模型来源（2026-10-20 定，2026-11-01 用户改判）：DSH 跟随 DeepSeek Harness 桌面的配置，小八不传模型参数。AGY 的模型由用户写在小八的节点配置 `cli_routes.local_agy.model` 里，配置里的模型就是实际使用的模型，小八不再读取 agy CLI 的设置文件、不做模型比对、不核实实际作答的是哪个模型；`model` 缺失或形状不合法（须以字母或数字开头、不是开关名形状）时拒绝发起调用。备用 Qoder 仍每次调用前读自己的 `~/.qoder/settings.json` 取模型名与思考强度，这是现状，读不到明确模型或思考强度不受支持就停止；回报里的 `modelUsage` 只保留在原始输出中，不再用于核对或作为执行回执的模型身份。小八不再读取 Antigravity 和 Qoder 的桌面。CLI 原生登录仍由各 CLI 持有；Qoder CN 不作替代。
- 单轮后台调用的输出预算（代币上限）耗尽属于任务级失败：不得原样重发，因为重发只会再撞同一个上限；用户手动恢复时返回拆分任务的提醒。

现行治理表述以第二大脑 `10_治理与裁决/故障自愈与任务恢复.md` 为准，其固定正文模板存放在 `docs/second_brain/v152_extra_nodes.json`；构建第二大脑时读取该模板，不读取线上正文。


新增经验分类与受控验证的运行契约及验收条件见 docs/EXPERIENCE_TRIALS.md；技术审计仅结算审计回执，方法必须真实新执行与独立双审后用户终审。历史候选不批量迁移。
