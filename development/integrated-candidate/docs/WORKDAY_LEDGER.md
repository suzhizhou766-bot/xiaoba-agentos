# 共用工作日台账（v1.6.12 候选）

SQLite 表和可校验事件链是唯一记录。台账、索引、引用和接续清单均为可重新生成的阅读视图，不参与周分、成功率或 14 天未用判定；不增加表或列。

根目录取当前配置 `memory.obsidian_vault` 的父目录。CLI、监看接入口和带 `--config` 的独立接入口使用相同位置；未配置时跳过生成并告警，不使用 runtime 或历史绑定作为默认目录。首次成功生成时将根目录绑定写入现有事件链，后续位置冲突只跳过本次生成，不另开第二本；doctor 和 runtime 本地检测报告显示“台账根目录与已绑定位置不一致，需要用户决定”，命令仍正常完成。

## 使用

通过已验证入口调用：

```sh
xiaoba workday-rebuild
xiaoba workday-read
xiaoba workday-rebuild --day 2026-11-09
xiaoba workday-record /absolute/project/output.md --node NODE --task-id TASK --agent AGENT --model MODEL --kind 回执 --status completed
```

`workday-record` 用于宿主直接产出的文件；类型可为 `回执`、`新经验`、`复用经验`、`产出`。命令先将原路径和当时内容哈希保存为待登记元数据并标记待刷新，重建时归入事件链后生成视图；同日连续登记同一版本的引用不会增加重复记录。原生执行回执、接入口的节点执行回执、tmux 在场通道的任务卡和执行回执自动登记，已有候选、复用记录、实际应用和交付事件也从数据库投影，不需要模型手写索引。

`session-start` 和接入口 `start_workday()` 使用同一生成器；后者不再派发测试任务或初始化节点日文件。它们输出本地节点开关、入口是否存在、配置/模型/实现与既有测试资格是否相符的检查报告，并落 `本地检测报告.json`，不验证远端推理可用性。节点自己的日 Markdown 回执机制保留。

## 文件与恢复

每日视图位于 `工作区/YYYY-MM-DD-小八台账/`。`_索引.jsonl` 按事件链顺序排序，记录时间和稳定记录 ID 用于定位；每行包含原路径、节点、任务 ID、Agent、模型、类型、登记状态、时间和文件哈希。三类引用子目录只存路径和哈希等元数据，不复制正文。登记快照保留原状态；接续清单按 SQLite 当前任务及经验审核状态过滤，按任务 ID 跨天接续；没有原生 tasks 行的外部任务与 tmux 等待任务也从事件链接续。读取最近台账日期和任务状态均不依赖旧目录是否存在。

总目录位于 `工具/每日台账索引总目录/`，每日位置、分类数量和未完成数来自 SQLite；已清理的日目录标注“已清理、可重新生成”。旧版本未保存 Agent/模型或原文件哈希的记录明确显示“未记录”或“历史记录未保存文件哈希”，不以文件当前内容冒充历史证据。新复用记录在登记时保存原文件哈希。

业务写入后只更新 runtime 的 `.workday-pending` 标记，不扫描事件或同步重建。自动引用登记只保存原路径、哈希和元数据到待处理队列，不复制正文；敏感元数据跳过并告警。生成入口为 `session-start`、接入口 `start_workday()`、`workday-rebuild`、Worker 已有的无任务空闲周期，以及 `workday-read` 发现待刷新标记时。重建完成只确认开始时的标记，期间有新写入仍保持待刷新。

生成先取得跨进程文件锁，默认最多等待 0.25 秒；超时跳过并告警。只读快照内校验一次事件链并读取投影所需数据，关闭快照、结束短元数据写事务后才渲染。文件使用同目录临时文件、fsync 和原子改名。事件链异常跳过生成。台账任何异常都只告警，不改变业务事务、节点测试资格或命令退出码；doctor 的 `workday` 和 runtime `.workday-local-check.json` 留下可见状态。没有本次本地检查时，可通过 doctor 查看告警；告警不参与 doctor 的业务健康判定。

清理视图不会清理原产物、数据库、事件或评分；重新执行重建即可恢复。`本地检测报告.json` 是上班时的本地检查，不是 SQLite 投影：普通重建保留已有报告，日目录被清理后不会凭空再造报告。
