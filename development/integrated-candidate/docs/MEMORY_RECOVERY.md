# 经验发布恢复与人工核对

## 本版边界

- published/retired候选不得重新登记，不覆盖其内容、批准证据与历史；其它状态重新登记语义沿用旧版，不提供正式修订入口。
- 发布前验证同一个候选哈希的初审与终审批准；Agent和脚本不得代用户批准。
- 失败恢复只撤回可归属本次写入的内容。被认领原inode保留，旧fd继续写入不会因恢复主动unlink而被销毁。保留物不算备份；无自动清理/过期/发版清除。
- 扣留释放提交未知时保留当前证据，报告reconciliation_required、retry_safe=false与人工处理要求，不把未知当未提交。

## 查与处理

用已安装入口的 memory-retained-list 列清单，doctor --json 与成功上班正文也显示提醒。普通待核对不使全局doctor失败，不阻断接单/切换/继续发布。清单模块本身的枚举异常仍单独报告；不得把枚举失败说成“没有保留物”。

用户看过单个真实对象后，亲自在终端二选一：

    xiaoba memory-retained-resolve ABSOLUTE_PATH --trash
    xiaoba memory-retained-resolve ABSOLUTE_PATH --confirm-deleted

第二项仅确认用户已经自行删除，命令本身不删除。默认身份来自发现记录；没有身份的旧记录须先核对list的dev/ino，再显式给 --expect-dev DEV --expect-ino INO。路径上被替换的新对象不得依旧记录处理。

--trash使用macOS原生RENAME_EXCL保留同一inode，不覆盖已占名字，不以copy+delete冒充移动；无此原语、不同设备或拿不到串行锁则拒绝。重复已处理返回already_resolved；移动已完成但记录未写成时，先按错误修复条件，再用同命令补记，不再移动。每种冲突以本次返回的真实位置/原因/重试条件为准，不能把任意失败一律当可安全重试。

误捕获放不回的对象保持原inode，清单列实际位置。留痕追加失败时，派生名绑定公告inode与捕获inode以供重启核对；不能把普通占位文件认成捕获对象。对象不自动清理，误捕获对象的处置按清单由用户人工核对，本版不增加自动退役工具。

## 如实保留的限制

只在macOS本地文件系统做了有限同步并发及故障注入，不承诺网络文件系统、跨设备、无限并发、断电级持久性、真实inode复用或蓄意伪造自校验名的抵抗能力。旧形状派生名不自动推断归属；任意手动改名不是全盘inode跟踪，须人工登记/核对。多级I/O同时失败时以实际错误为准，不宣称未写成的记录已落盘。

废纸篓普通目录项移动可保留对象，不提供Finder put-back元数据保证。固定版本切换的原内容只在切换进程内存中，强杀/掉电仍需人工检查；本版没有把该切换恢复扩写成备份系统。
