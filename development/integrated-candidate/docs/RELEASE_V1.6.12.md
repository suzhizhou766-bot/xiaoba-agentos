# v1.6.12 共用工作日台账

本版基于已上线的 v1.6.11（2026-11-09）。数据库结构仍为 7，没有新增表或列，切换步骤也没有增加。`docs/DEPLOYMENT.json` 里的前置源码清单哈希是已上线 v1.6.11 的值 `65a1c138…`。

## 共用工作日台账（卡 62）

- 台账由 SQLite 和事件链生成，只是给人看的阅读视图，可以随时重建。台账不参与周分、成功率或 14 天未用的判定，用户清理工作区也不会影响任何记录。
- 每天一本台账，放在 `工作区/YYYY-MM-DD-小八台账/`，包括：
  - `台账.md`：给人看的当天汇总；
  - `_索引.jsonl`：当天每条产出一行，记原路径、节点、任务 ID、Agent、模型、类型、状态、时间和文件哈希；
  - `接续清单.md`：按任务 ID 跨天串起未完成的条目，读最近一本台账，不限于前一天；
  - `回执/`、`新经验/`、`复用经验/`：只放路径和哈希，不复制成品；
  - `本地检测报告.json`：上班时本地检查的结果。
- 总目录放在 `工具/每日台账索引总目录/`，记录每天台账的位置、各类条数和未完成数。某天的台账已被清理时，总目录会标“已清理、可重新生成”。
- 什么时候生成：
  - `session-start` 和接入口 `start_workday()` 用同一个生成器，并且只做不调用模型的本地检查。`start_workday()` 不再派测试任务。
  - 节点回执、tmux 在场通道的任务卡、候选、复用记录和交付事件，会自动登记到台账。
  - 宿主自己产出的文件，用 `xiaoba workday-record` 登记。
  - 需要手动重建时，用 `xiaoba workday-rebuild`。
- 卡 64：业务写入只标记待刷新，自动引用先排队；由上班、手动重建、Worker 无任务空闲周期或读取台账触发重建。只读快照校验一次事件链，渲染不占写事务，文件锁默认等待上限 0.25 秒。
- 根目录统一取 `memory.obsidian_vault` 的父目录，未配置则跳过。绑定冲突显示“台账根目录与已绑定位置不一致，需要用户决定”。异常、锁超时和敏感元数据只告警，在 doctor 或 runtime 本地检查报告可见，不改变业务结算、节点资格、命令退出码或开工记录完成状态。
- 历史缺哈希显示“历史记录未保存文件哈希”；运行要求与解释器口径统一为 Python >=3.11。
- 普通重建原样保留已有的本地检测报告；删除当天台账后只恢复 SQLite 投影，不再造上班检查报告。
- 已知代价（卡65）：每次重建仍读取全量快照并校验事件链，成本随事件总量增长，C11 再做索引。本版不增加 events 索引；队列每次最多500条，单事务批量登记、一次引用事件扫描，剩余条目留到下次；连续失败3次移入死信目录并告警。本机固定 Python 3.14.7、5000条历史事件加2000条排队引用的合成规模实测：4轮处理完毕，总耗时0.476秒，单轮最慢0.122秒；每轮500条，只扫描一次既有引用事件（共4次），结构未变化。这是临时库的观测值，不是生产耗时上限；全链校验和全量快照成本仍随历史增长。
- 卡 64 复查补修：只给台账用的原文件哈希读不到时，直接省略这个字段，不再回滚业务事务；doctor 遇到不完整的台账状态不会出错；上班时本地检查失败会单独报出“本地检查失败”，不再显示成台账失败；`workday-record` 参数不合法时返回具体原因；数据库路径不是绝对路径时，不再在当前目录下生成诊断文件。
- 节点自己的日 Markdown（交回执的通道）不变。
- 详见 `docs/WORKDAY_LEDGER.md`。

## v1.6.11 审查员的非阻断项

- 派审查的记录事件不再更新条目的 `updated_at`。以前派审查后，已经打开的页面要刷新才能提交，现在不用了。
- 监看中心的页面警告测试改成直接断言，去掉了跳过分支。
- B4 的 admitted 分支：事件里的结果哈希改为写入后从库里重算。
- 待处理通知的列表和计数共用同一个过滤函数。
- `memory.value_unscored`：原因变化时追加一条新事件，并标明前一次的原因。

## 怎么上线

按 `docs/RELEASE_SWITCH.md` 构包、演练、切换。监看中心仓库副本的 `agent_pool.py` 有改动，切换时同步到线上。切换后要做三件事：重启监看中心、重测全部节点、提交一个真实小任务。
