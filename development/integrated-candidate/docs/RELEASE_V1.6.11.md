# v1.6.11 小修：评分作废、验收显式标记与一批小修

本版基于已上线的 v1.6.10（2026-11-09）。数据库结构没有变（仍为 7），切换步骤也没有增加。`docs/DEPLOYMENT.json` 里的前置源码清单哈希，填的是已上线 v1.6.10 的值 `1b2aa8ab…`。

## 评分作废（A2，卡 59）

- 干活分的手动更正接口新增 `outcome: "void"`，用来把一条已经结算的自动样本标为作废。作废必须写明原因（`void_reason` 不能为空）和证据引用。
- 作废的样本不再计入周分、样本数和成功率，择优选人和周统计都把它排除在外。
- 作废时会写一条 `task_scoring.assessed` 事件，delta 是原分数取负，事件里标明 void。
- 作废只会把这条样本清零。不能借作废把失败任务改成 +1，作废后也不能再改回计分。账本一致性检查认得作废的样本。
- 用途：v1.6.9 上线后，普通任务 `3e5514f5…` 因卡 57 的缺陷失败，三个节点被连带记了 0 分。这三条样本在本版上线后由主力用作废处理。

## 发布验收显式标记（B3）

- 新提交的任务都会在快照里冻结 `review_context.release_acceptance`（布尔值）。发版工具 `scripts/submit_release_acceptance.py` 提交时固定声明为 true，普通任务为 false。
- `requires_review_vote` 改为认这个标记。只有缺这个字段的历史快照，才沿用旧口径：题面同时出现两个验收结论标记。v1.6.10 说明里提到的已知局限（普通题面恰好引用这两行会被误判）对新任务不再存在。
- 构包新增一道检查：验收任务快照里的 `review_context.release_acceptance` 必须是 true，否则拒收。这样即使有人手动提交时漏了 `--release-acceptance`，也会在构包时被发现，不会让验收票按普通任务结算。这一条是卡 59 复查时 Qoder 提出的。
- `memory.value_unscored` 记录真实原因，共五种：无评分来源、分类不适用、mock 或旧非池协议、宿主草稿、尚无审查回执。`store.py` 不再重复调用 `requires_review_vote`。

## 其他小修

- **B4**：已完成但缺候选行的修复分支，现在会检查插入是否成功。价值分被丢弃时不写 `memory.candidate_staged`。原结果和既有完成事件的结果哈希保持不变，不重写历史，也不重复结算。
- **B5**：构包判票时，PASS 与 NEEDS_INFO 并存不算通过。
- **B6**：恢复记忆索引时，链接改为逐行精确匹配。正文里出现的同名子串不再被当成索引条目。
- **B7**：已放弃或已取消的任务，它名下的恢复类通知不再被列为待处理。做法是读取时过滤，原通知和事件都保留。
- **B8**：卡 52b 派审查遇到软失败（执行没报错，但没交出合格回执）时，下一个空闲周期按同一请求版本最多自动重派一次。还是失败就停下，显示“待人工补派”。硬错误和状态不确定的情况一律不自动重跑。
- **B9**：页面安装清单的 before 哈希改为线上 v1.6.10 实际安装的值。新增测试，要求清单的 before 必须等于上一已发布版本清单的 after，上一版清单固定在 `tests/fixtures/review-ui-v1.6.10.json`。
- **工作日志瞬时状态**：节点的编辑器保存工作日志时，文件可能有一瞬间是两个链接。以前读取回执时遇到这种情况会直接判永久失败，现在会在约 2 秒内重读。持续存在的硬链接或符号链接仍然拒绝读取。这个问题是 v1.6.11 第三轮验收中 Qoder 那一票暴露的。
- **B10**：新增仓库级测试，禁止任何测试文件在 `if __name__ == '__main__'` 之后再定义类或函数。原有的违规已全部改正。

## 监看中心仓库副本（卡 60）

线上监看中心已经在用、但仓库副本里没有的能力，都收回了仓库副本：Agent 池加载、portprobe、Key 绑定代理、关闭脚本的诚实探测、页面警告横幅，以及对应的测试。`taskcards` 的默认路径改为相对监看根目录的写法，线上配置仍可覆盖，线上行为不变。仓库副本的页面与候选 `review_ui_assets` 保持一致。

本版只同步了仓库，线上监看中心不需要新增或改动任何文件。

## 怎么上线

按 `docs/RELEASE_SWITCH.md` 构包、演练、切换。切换后运行 `review-ui-install`：清单的 before 已经对齐线上，不需要再改基准。
