# v1.6.13 Agent 池节点思考强度

本版基于已上线的 v1.6.12（2026-11-10）。数据库结构仍为 7，切换步骤没有增加。`docs/DEPLOYMENT.json` 的前置源码清单哈希是已上线 v1.6.12 的值 `c6c74efb…`。

## 节点思考强度（卡 66）

- Agent 池节点新增可选字段 `reasoning_effort`，新增和修改节点时都能设置，页面上能看到。不加表、不加列，仍存放在节点资料里。
- Qoder 节点传 `--reasoning-effort`，界面上的 Extra High 对应 `xhigh`；CodeBuddy 节点传 `--effort`（它的参数名不是 `--reasoning-effort`）。可用的取值按两种 CLI 实际接受的值做白名单，填了不合法的值，在登记节点和测试节点时都会给出明确错误。
- 这个字段计入节点的调用摘要：改了它，节点就要重测，和改模型的规则一样。没有设置这个字段的旧节点，命令参数和调用摘要都和上一版完全相同，升级后不需要重测。
- 用户 2026-11-10 定的配置：Qoder 用 Qwen3.8-Flash、思考强度 Extra High；CodeBuddy 用 deepseek-v4.1-flash、思考强度 high。上线后由主力在 Agent 池里填好，并重测这两个节点。

## 卡 65 复核遗留的小修

- 台账写文件时如果替换失败，会清理掉留下的临时文件。
- 接入口回执改为在业务事务提交之后才登记到台账队列。业务事务回滚时，队列里不会留下这条；提交后登记失败只告警。
- CLI 的 `session-start` 在本地检查失败时会单独报出“本地检查失败”，和接入口的行为一致。
- 监看中心和接入口导入台账模块时加了保护：导入失败只告警，不影响模块挂载。
- 两条测试改成真实断言：解释器矩阵测试改为在真实临时文件上调用 `hashlib.file_digest`；页面警告测试改为先请求健康接口、再检查页面上的横幅。

## 已知局限

- 接入口回执改为提交后才登记，会多出一个很窄的时间窗口：如果进程恰好在提交之后、登记之前被杀掉，这条台账引用就会丢失。业务记录本身不受影响，可以用 `workday-record` 补登。下一版考虑改成先写日志再重放。
- 台账临时文件在 fsync 失败时仍可能残留。

## 怎么上线

按 `docs/RELEASE_SWITCH.md` 构包、演练、切换。监看中心仓库副本的 `agent_pool.py` 有改动，切换时同步到线上，复制前后都核对哈希。切换后照例要做三件事：重启监看中心、重测全部节点、提交一个真实的小任务。
