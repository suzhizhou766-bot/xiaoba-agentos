# B4：待验证经验、真实应用与交付回流

2026-10-28，v1.6.5 本地开发候选。承接第一批已修好的两轮核验；不修改原冻结材料和生产。两轮执行、独立审查、敏感检查、人工裁决及发布门禁继续生效。

## 独立索引与回读

`memory-pending-index [--problem-key KEY] [--query TEXT]` 是候选数据库的只读派生视图，不新增数据库表或权威文件。每次重查事件链、方法分类、当前初审回执及其审计事件、暂存正文哈希和技术核验状态；排除未初审、拒绝/退役、正文漂移、已发布、旧无分类、待人工核对、结构异常及已有技术终审资格的条目。第一轮失败仍可为第二轮召回；不重置轮次。

返回 index_sha256、事件链头、候选 ID、正文摘要、初审回执 ID、problem_key、标题、验证状态和原文/证据入口。精确问题标识优先；标题关键词只表示相关性。旧数据没有结构化适用条件、排除条件、任务类型或环境时返回 null，主力必须在当前任务核对并记录，不从标题猜测。`memory-trial-match` 复用过滤，仍保持原三个字段。

`memory-pending-read ID --candidate-sha256 SHA --delivery-review-id REVIEW_ID` 回读当前绑定的正文，标为“已初审、待验证”。索引和回读不写应用事件、派后台、增加复用计数或注入长期记忆。

## 显式记录实际应用

主力在当前用户授权范围内真实应用后，调用 `memory-application-record --receipt /绝对路径/application.json`。不是从命中自动推断。输入形状如下，示例值必须换成真实值，不能把占位摘要当作证据：

```json
{
  "candidate_id": "原候选ID",
  "candidate_sha256": "索引返回的64位摘要",
  "delivery_review_id": "当前初审回执ID",
  "real_task": {
    "id": "host:真实任务ID（或已有队列任务ID）",
    "problem_key": "实际问题标识",
    "description": "本次任务目标",
    "task_type": "任务类型",
    "workspace": "/明确授权的项目目录",
    "authorization_ref": "用户授权的证据入口"
  },
  "conditions_checked": {
    "applicability": "本任务符合哪些条件",
    "exclusions": "如何排查排除条件",
    "environment": "实际环境及必要条件"
  },
  "application_location": "实际应用位置",
  "steps_applied": "采用的具体步骤",
  "deviations": "偏离及原因；没有也须明说",
  "artifact": {"path": "/项目目录/成品", "version": "明确版本", "sha256": "实际64位摘要"},
  "execution_evidence": [{"path": "/项目目录/执行证据", "sha256": "实际64位摘要"}]
}
```

文件必须在声明的项目目录内；拒绝路径穿越、软链与摘要漂移。只保存引用和摘要，不复制成品。应用事件绑定当前候选、初审及另一个真实任务；宿主任务不必排队或创建假后台任务。application_id 从输入稳定计算，重复/并发只登记一次。

将返回的 trial_binding 原样置于现有隔离任务卡的 `experience_application` 字段，再走 `memory-trial-run`。预检和入队事务再次核对绑定。已记录应用却缺此绑定时，在实际执行和消耗轮次前拒绝；无应用的旧任务卡维持原流程。应用应早于隔离核验，不能把旧 PASS 事后改标。宿主应用报告和文件存在本身不能证明方法有效，仍须核对执行内容与独立意见。

## 接入交付

主力先完成既有交付记录、资产清单与 Playbook 回流，再向现有入口传入明确的任务和版本：

```sh
xiaoba intake '交付' --message-id 稳定用户消息ID --delivery-receipt /绝对路径/delivery.json
```

delivery.json 提供 real_task_id、artifact（与应用的路径/版本/摘要一致）、source_ref（真实用户消息来源）、delivery_record（项目内交付记录的 path/sha256）。入口绑定原始用户消息及 ID，不启动会话或后台；不可与 --submit 或强制路由合用。宿主适配也可调用 `memory-delivery-record --receipt FILE`，额外提供 origin=user、user_message、message_id；不得伪造用户来源。此为可信宿主的事件登记契约，不是独立的人类身份认证服务。

保守识别单独的“交付”及句号/感叹号；引用、否定、问句和口令讨论不触发。任务/版本不明确时先澄清，不从整段聊天猜测。没有实际应用的经验不能回流。成品采用不证明每条方法都有因果贡献。

同一事务保存交付事件，逐条回挂原候选：应用位置、执行证据、成品版本、用户验收事件、当轮执行摘要、审查任务及各来源原文/定性 PASS/FAIL。失败和分歧保留。缺数值评分标 null，不用相关性、回答排名或模型赞同补分。交付先到、审查后完成时，原生审计结算自动追加更新的回流材料；不重复建经验卡。

既有技术门禁通过且当前应用、成品、交付记录、用户验收及隔离任务绑定一致，才具备人工终审资格。`review-list --stage final|all` 和原卡面板展示应用、回流及阻断。证据变化更新候选修订时间，旧浏览器快照需刷新。人的终审另外绑定本次应用/验收摘要，撤回后再接受不能复活旧终审。`decision=withdraw` 配合真实用户“撤回验收”记录撤回，成品返工或丢失也可留撤回记录。内容、初审、成品变化不得自动清空两轮历史或覆盖人工拒绝。

## 兼容和待用户决定

- 没有新应用事件的旧候选、旧隔离试验和无分类候选保留原门禁；已发布经验的检索、复用计数、退役和恢复未改；新经验仍先初审。
- 不新增表、迁移版本或审批入口，只用既有事件链。Agent/脚本登记材料，不创造人的初审/终审决定；批准和发布继续走原唯一入口。
- 数值评分量表、维度、权重及择优策略属于总纲 B5，仍待用户裁定；本批回流真实定性结论和原文，不加自动分数阈值。
- 已通过的核验若因返工/新版本需要再验证，按既有两轮门禁停下，另行明确授权修订/迁移方案；不提供清轮次或沿用旧批准的旁路。
- 本地测试不代表真实模型双审、原生批准后台完整浏览器联调、受审构包、包外页面安装或生产切换。共享技能、规则、生产配置未修改；宿主调用指引正式接入随受审升级安排。
