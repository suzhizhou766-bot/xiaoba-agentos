# v1.6.3 候选：核心解释器改为 Python 3.14

基线为已上线 v1.6.2。用户 2026-10-14 定下“小八 AgentOS 核心从系统 Python 3.9.6 改为 Python 3.14，随下一版本切换”，2026-10-19 指定主力（Claude Code）亲自做。

## 改了什么

- 固定解释器：`src/xiaoba_agentos/interpreter.py` 的 `PINNED_PYTHON`，即 `私人助理/配置/python/cpython-3.14.7-macos-aarch64-none/bin/python3.14`。写真实路径，不写 `.runtime` 下的兼容链接，也不写 `cpython-3.14` 这个指向链接的别名。
- `bin/agentos` 用这个解释器启动 CLI 和后台 Worker；解释器不在或不可执行时以 78 退出并在标准错误写明原因，不回落到系统 Python。
- 两个入口脚本（`xiaoba`、`verify-release`）首行改为同一个绝对路径，入口自己的发布校验也在 3.14 上跑。
- 笔记索引重建的三处子进程调用改用当前解释器（`sys.executable`），不再写死 `/usr/bin/python3`。
- 构包脚本用运行它的解释器做清单校验、第二大脑校验和全量测试；命令行入口先核对运行它的解释器就是被构建源码里声明的固定解释器，不是就拒绝构包。
- 经验试验的 macOS 沙箱：在原有规则之上，只读放行固定解释器的三样东西：解释器文件本身、`lib/libpython3.14.dylib`、标准库目录 `lib/python3.14`，其中 `site-packages` 再次拒绝。安装目录里其它文件、`/Users` 下其它位置的读、工作区以外的写、网络仍然拒绝。
- `doctor` 多一个 `interpreter` 字段，报告正在运行的解释器、版本、固定路径以及两者是否一致。只作报告，不改变 `ok` 的判定：生产路径总经 `bin/agentos` 启动，测试环境用别的解释器跑时不应因此失败。

## 没改的

数据库仍为 schema 7；配置结构、认证、模型、路由不变；没有新的部署步骤。系统自带的 `/usr/bin/python3` 不改不删。监看中心、裁决页面后端、`工具/治理` 这些包外程序仍用系统 Python，不在本版范围。

## 为什么不用 3.15

2026-10-14 的隔离测试里，3.15.0 连跑 5 次有 1 次多出一个失败（单独运行通过，原因未查明）；3.14.7 与 3.9.6 各 5 次结果一致。

## 验收要点

- 全量测试分别在 3.14.7 和 3.9.6 上跑；新增 `tests/test_interpreter_pin.py`（固定路径一致且真实存在、启动器缺解释器时失败关闭、包内不再写死系统 Python、构包拒绝非固定解释器）和沙箱放行范围的实测。
- 验收顺序：两份代码范围（interpreter_core、sandbox_trials）先由 AGY、DSH 各自独立审查；都通过后构演练包，做复制现场演练（现场放在 `Documents` 下，核对由签名 Runner 经 launchd 拉起的 Worker 用 3.14 运行、能读写 `Documents` 下的运行目录和第二大脑，并逐阶段注入故障确认能退回）；演练报告再交最后一份集成审查（integration_release），三份都通过才构正式包。
- 切换由用户在自己的终端执行；不创建备份。
