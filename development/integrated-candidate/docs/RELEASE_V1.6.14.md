# v1.6.14 检索热路径索引，监看中心脱离会话启动

本版基于已上线的 v1.6.13（2026-11-10）。`docs/DEPLOYMENT.json` 的前置源码清单哈希是已上线 v1.6.13 的值 `830f9ea2…`。

## 检索热路径索引（卡 68，候选 C11）

- events 表新增两个复合索引，用于按事件类型、按任务查找。索引用 `CREATE INDEX IF NOT EXISTS` 幂等建立；表和列都不变，事件内容也不变。
- 结构版本仍然是 7，但 schema 指纹变了，所以本版属于**迁移档**：构包后要做复制现场演练，切换后要做 readback。复查已实测：切换到本版时，线上旧库能正常建索引；回退到 v1.6.13 也干净（旧版本不认识这两个索引，但不受影响）。
- `formal_review` 里原来用 `OR ... LIKE` 写的事件查询，改写成能用上索引的形式，查询结果不变。
- 收益：按线上约 2246 条事件实测，全量查询从全表扫描变成走索引。目前的数据量下差别是毫秒级，规模越大收益越明显。

## 撤回的部分（卡 68 复查，Qoder CN）

- 原本还做了“事件链增量校验缓存”和“监看后台没有新事件就跳过”。复查实测发现两个问题：
  - 增量校验查不出“缓存区间中间的历史行被改写”（改 payload，或者另一个进程改写后再正常追加），也就是说防篡改能力比 v1.6.13 弱。补救用的“定期全量”在持续有数据写入时也不会触发。
  - 跳过空转会让修订条目不再自动补派。
- 按现在的数据量，这两项只能把监看后台的占用从约 0.24% 降到 0.03%，不值得用防篡改能力去换，因此**整体撤回**：事件链校验恢复为每次全量，监看后台每轮照常投影。
- 新增三条防回退测试（中间行改 payload；改 payload 并重算本行哈希；另一个进程改写后再正常追加），断言全量校验都能查出来。

## 监看中心脱离会话启动，以及台账小修（卡 69）

- 监看中心的启动脚本改成脱离调用方的会话和进程组。v1.6.12 切换后，监看中心曾随着调用它的终端命令一起被关掉，停了约 2 小时。复查实测：调用方的进程组被结束后，监看中心仍然健康；关闭脚本照常能关掉它；连续启动两次、或者 PID 文件已经过时，都只会起一个。
- 台账登记：只有 SQLite 的 locked、busy 这两类算瞬时竞争，不计失败次数；其他数据库错误（例如表不存在、磁盘 I/O 错误）照常计数，满 3 次移入死信目录。
- 台账写文件时，fsync 失败也会清理掉临时文件。
- 补了“台账模块导入保护”的真反例：修复前会失败的测试。

## 已知局限

- 接入口回执改为提交后才登记，留下的窄窗口（v1.6.13 已写明）本版没有改。卡 69 只评估了“先写日志、再重放”的做法，评估写在回执里。
- 接入口有一条时序敏感的测试（`test_stdout_events_do_not_reset_300_second_worklog_deadline`），在机器负载高时偶尔失败，重跑能通过。

## 怎么上线

按 `docs/RELEASE_SWITCH.md` 构包、演练、切换（本版是迁移档，必须做复制现场演练和 readback）。监看中心仓库副本的 `xiaoba_monitor.py` 和启动脚本有改动，切换时同步到线上，复制前后都核对哈希。切换后要做三件事：重启监看中心（用新的启动脚本）、重测全部节点、提交一个真实小任务。
