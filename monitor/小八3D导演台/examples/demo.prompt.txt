## 官方资料核验摘要

- API 模型标识为 gemini-omni-1.1-flash；支持首尾图片插值。<FIRST_FRAME> 和 <LAST_FRAME> 指定端点；尾帧标记需配合首帧。图片/视频参考使用从 0 起的 <IMAGE_REF_N> / <VIDEO_REF_N>。来源：Google API。
- API 当前不接受音频参考上传，不提供独立 negative-prompt 参数；约束写入普通提示词。英语已评估，其他语言未评估。不要把官网的多模态概览当作每个接口都已开放的能力。来源：Google API。
- 官方提示指南建议说明景别、运动、场景、光线和动作；连续镜头应明确声明。首尾控制要交代起始画面、连接路径和最终揭示；局部编辑聚焦要改的部分。来源：DeepMind。
- 延长功能按 10 秒追加，累计上限为 40 秒；这不等于支持一次直接生成 40 秒。产品功能因入口、地区及套餐而异。来源：DeepMind。

## 本项目推荐操作步骤

1. 在导演台选 Omni 1.1 Flash，设计轨迹并导出交接包。
2. 助手按包内构图参考和用户外观素材生成最终首尾图，交付中英两版提示词。
3. 用户在实际使用的平台选相应模型与首尾帧工作流，核实可选时长后上传最终图片。
4. 有首尾槽位就使用槽位；支持官方媒体标记的入口可使用对应标记。仅输入文件名或标记不等于上传了图片。
5. 生成后先核对空间与运镜，再进行局部迭代；较长方案按平台支持的分段或续写流程处理。

## 本项目整理：五类任务别混写

新建视频描述整段意图；首尾帧任务描述两端如何连接；参考生成只继承指定外观/风格；编辑任务指出修改范围；续写任务接续上一段结束状态。下面模板是本项目原创写作框架，不是官方固定语法或实测成功率结论。

## 本项目模板：连续首尾帧

绑定最终首图与尾图后：起始为角色 A 在画面左侧的中景。镜头沿角色前侧缓慢横移，A 保持站位，背景柱体产生自然视差。到结尾形成与尾图一致的三分之二侧面构图。单个连续镜头，保持人物外观和柱体布局。声音按用户要求另写。

## 本项目模板：双人调度与建筑保真

起始 A 在前景左侧，B 在后景右侧。A 沿走廊向 B 走近，镜头后退维持 A 的中景；B 留在原处。结束 A 停在 B 左前方。保留同一走廊的柱距、门洞和地面高差。用可见空间关系说明运动，避免把角色自身左侧写成画面左侧。

## 本项目模板：局部编辑 / 续写

局部编辑草稿：只把背景灯光调整成柔和暖光，人物身份、动作、机位、时长和其他内容沿用原片。续写草稿：从上一段停止的位置继续，A 先停步再回头，机位继续沿原方向横移，声音接续。续写的时间从新追加片段的起点说明，先核实所用平台是否开放该功能。

## 本项目实践：声音单列

为环境声、音乐、对白分别填具体意图。没有对白需求时不擅自编写对白；需要静音时明确注明。不要将参考视频里的声音自动当成声音参考，也不把原生声音生成和上传音频参考混为一谈。

## 导演台实践：先把三维数据翻译成可见结果

世界坐标供助手重建路径，不应直接堆进视频提示词。把坐标变化解释成主体位于画面左/中/右、景别如何变化、前后景如何遮挡。机位向目标靠近是推进；镜头焦距变化才是变焦，不能混为一谈。方向同时说明是画面方向还是角色自身方向。时间线不是对生成模型的逐帧约束。

## 导演台实践：明确素材职责

first-frame-blocking.png 与 last-frame-blocking.png 只控制取景和站位。由助手根据角色/建筑/风格参考制作 final-first.png 与 final-last.png，再交给视频平台。人物占位模型不代表最终服装、肤色、性别或画风；当前包不包含运动视频，不要声称已有白模参考视频。

## 导演台实践：首尾图制作约束

两张最终图使用同一组角色与场景参考，统一人物数量、服装、道具归属、建筑几何、材质和光照方向。分别匹配首尾投影与画面裁切。移动机位可以改变透视与可见区域，不应为了凑尾帧重排物体。先核对首尾图是否能由一段连续空间运动连接。

## 导演台实践：排错顺序

先查参考槽位是否用错，再查动作和镜头描述是否矛盾，再检查首尾空间是否连续。身份漂移时具体列出要保持的外观；左右互换时补充画面坐标关系；运镜跳跃时减少同一时段的运动指令。一次只改一类问题；这些是本项目的制作建议，不是官方成功率承诺。

## 导演台实践：提交与验收

用户在所选平台打开对应视频模型，把最终图像绑定到首尾槽位或明确指定图片职责，再粘贴成品提示词。画幅、可选时长和画质以该入口为准。验收人物身份、数量、建筑、动作方向、运镜连续性、结尾构图和声音。精确商标/字幕可在后期合成。
