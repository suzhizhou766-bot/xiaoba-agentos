## 学习要点

这是一套代码动效短片的导演规则、Skia 绘图引擎、Python 配乐引擎和质量检查脚本，面向 30–60 秒的知识解释、产品介绍、数据演示与动态排版。它不控制剪映草稿，也不替代真实素材剪辑。

1. 先把必须出现的原文、观众、时长、口播要求写入 BRIEF；再设计三个概念，确定重音表、物变表、接力表和时间表。
2. 用具体物体的变化解释抽象概念，遮住文字后仍应看懂含义。段落之间有物体接力，摄像机在持续存在的世界中推拉、追随。
3. 声画使用同一时间源：有口播时按逐词时间戳对齐，无口播时先排配乐，画面读取 `cues.json`；默认无口播节拍 120 BPM。
4. 运动有预备、冲击、过冲、回稳和余震；进场约 0.25–0.35 秒，出场约 0.15–0.25 秒。重音前适当留静止和声音停顿，避免全程同一强度。
5. 默认竖版 1080×1920，也支持横版 1920×1080；同一代码需要按 W、H、安全区布局。上游 6 秒示例使用竖版固定坐标，不能直接当作横版成片。
6. 逐段查看拼板，检查语义、构图、连续性；完成后找最弱的三个时刻修改，做两轮并记录前后截图。正式创作仍需完成这些步骤。
7. 自动检查响度、静止段、能量变化、文字阅读时间、文字重叠、裁切和数字比例。退出码为 0 不等于内容全部通过，要阅读输出中的 FAIL/WARN；自动检测不能替代视觉判断和听审。

## 本机使用

在私人助理根目录新建一个尚不存在的项目：

```bash
工具/motion-explainer/bin/new-project AI视频管线/我的动效短片 9:16
```

此入口调用上游脚本，额外接好统一运行环境和共享绘图库，拒绝覆盖已有项目。项目中先读生成的 `AGENTS.md`，按技能九步制作；`demo/` 只供参考，需要自行编写项目根目录 `film.mjs` 和 `score.py`。

在项目根目录运行命令时使用环境入口：


## 实际验证与限制

运行了仓库自带的 6 秒喝水示例，生成 `安装验收/out/final.mp4`：1080×1920、30fps、6.000 秒、H.264 + AAC。合成配乐和最终视频响度约 −14.2 LUFS，真峰值检查约 −1.4 dB。检查输出无 FAIL，读字时间、文字重叠与 4 倍水量比例通过。

但示例并非没有缺点：检查报告边缘和平台遮挡区告警、t=4.8 秒“500 ml”半截字告警，粗略卡点率 50%。已实际打开六帧拼板，看到水杯缩入日历、两杯水按四倍高度比较、推进便签的连续画面；边缘告警和示例固定坐标均需正式创作时逐项处理。本次仅验证安装及上游示例，不把它作为用户定制成片，也未声称完成两轮创意修改或完整听审。
