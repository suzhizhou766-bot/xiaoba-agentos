# 导演手册

> 由 motion-explainer skill 提供，路径都相对项目根目录。根目录的 `frame.md`（风格规范）和本手册冲突时，以 `frame.md` 为准。
> 运动、声音、版式的具体数值在 skill 的 `references/craft.md`，写代码时再打开。

## 0. 目录里有什么

| 路径 | 用途 |
|---|---|
| `BRIEF.md` | 这次要做的片子 |
| `aspect.txt` | 画幅：`9:16`（竖版，默认）或 `16:9`（横版） |
| `frame.md`、`style/` | 风格规范和参考图 |
| `engine/world.mjs` | 主引擎：一个世界 + 一台摄像机 + 接力动作 + `words()` 把时间锚在配音的字上 |
| `engine/lib.mjs` | 零件：缓动 `E`、文字、高亮、数字滚动、快门模糊 `withShutter` |
| `engine/musiclib.py` | 配乐和音效 |
| `engine/run.sh` / `engine/sheet.mjs` | 渲染全片 / 缩略图拼板（你的眼睛：每次都打开图片看） |
| `checks/check_all.sh` | 体检 |
| `demo/` | 用世界引擎写的 6 秒示范，从这里起步 |

## 1. 八个词（全手册只用这几个名字）

| 词 | 意思 |
|---|---|
| **重音** | 全片 3–5 个最重的时刻，只给剧情节点：开场、揭晓、转折、结论。重音那一秒的运动量是平时的 5 倍以上。 |
| **主重音** | 重音里最大的那一个，放在全片 55–70% 处。 |
| **停顿** | 重音前设计好的静止：画面几乎不动 0.5–1.5 秒，镜头完全不动，配乐撤掉或压低。全片 1–4 处。 |
| **变天** | 最大转折那一刻，整个场景一起变：换底色、换亮度、换主题、换到另一个空间。全片 1–2 次。 |
| **物变** | 说到某个意思的那一刻，画面里的**东西本身**变成那个意思：说「冰化了」，那块冰真的化成一摊水；说「翻了四倍」，那根柱子真的长到原来的四倍高。字只是标签，东西才是演员。 |
| **接力** | 段落之间，上一段的某个物体被带进下一段继续用（缩进、长成、推进、当尺子量）。 |
| **一个世界** | 全片的东西都持续存在于同一个空间，镜头在里面推、拉、穿越；段落靠接力相连。 |
| **遮字检验** | 把字全遮住，只看画面，能说出这一段的意思。 |

## 2. 写 PLAN.md

按顺序写这五样：

1. **3 个概念**：中心思想不同的 3 种做法，每个一句话说清「画面是由什么构成的」（例如：一个物体贯穿全片不断变形 / 一个镜头从一个字推到整个世界 / 一串连锁反应）。每个写：第 0 帧是什么、段落之间靠什么接力、用这个风格的哪几招。能和用户对话时让用户挑；不能对话时自己选，写明理由。
2. **重音表**：每个重音一行：秒数、触发它的词（有口播时）或拍点（无口播时）、那一刻画面里发生什么、前面有没有停顿。标出主重音和变天。
3. **物变表**：BRIEF 里每一句话或每个要点一行：意思 → 用哪个东西演 → 前是什么样 → 后是什么样 → 在哪个词的那一帧变 → 遮字检验能不能过。找东西的方法见 skill 的 `references/visual-metaphors.md`。
4. **接力表**：每个段落边界一行：用哪个接力动作（见第 5 节），哪个物体被带过去。没有物体被带过去的边界就是换页，全片最多 2 处。
5. **时间表**：每一段的起止秒数。

## 3. 整支片的原则

1. **起伏**：平时收着，小动作；力气集中在重音。每个重音前想一想要不要停顿。
2. **转折处变天**：观众一眼感到「世界变了」，而不只是原画面里改一个小地方。
3. **一个世界**：一个场景接住好几句话；全片明显硬切 6 次以内；镜头长度拉开差距（最长和最短至少差 4 倍）。
4. **物变**：每个重音都是一次物变。用观众在生活里见过、数得出、会变化的东西演，前后差别一眼看见。
5. **重点做大**：需求里点名的记忆点（方法名、金句、结论）占画面 60% 以上，或者整屏变色。
6. **第 0 帧就是正在发生的场景**：观众熟悉的那个场面或那个损失已经在动（一桌没洗的碗正在变多、一条进度条卡在 99%）。标题和答案留到后面揭晓。
7. **画面只放内容本身**，加上风格规范要求的版式元素。
8. **闭环**：开头出现过的物件，在结尾带着变化回来；最后 1 秒画面还在动。
9. **有摄影师的镜头**：镜头在世界坐标里推、拉、追；要对准落点时提前到位（`E.outExpo`），要跟随时比主体早约 0.1 秒；平时几像素手持漂浮，停顿时完全不动；落地、撞击加一次轻震。主体始终留在画面里。
10. **看得见的原因**：每个变化都有一个看得见的触发者：光标点了、角色撞了、上一拍的东西掉下来了。

## 4. 时间

- **有口播**：重音跟着人声的关键词走。用 `const T = words(new URL('./whisper/narration.json', import.meta.url))`，写 `T.at('词')`、`T.end('词')`，重音和说出这个词的那一帧对齐（误差 ≤ 2 帧）。配乐去配合人声。
- **无口播**：120 BPM（1 拍 0.5 秒，1 小节 2 秒）。`score.py` 是时间的唯一来源，画面读它生成的 `cues.json`；切换、进场、重音落在拍点上（误差 ≤ 1 帧）。
- **读字时间**：中文句子停留 ≥ 字数 ÷ 5 + 0.8 秒；4 个字以内的冲击词 ≥ 0.5 秒。字多就少放字，停留时间保住。
- **停留超过 1 秒**：要么是设计好的停顿，要么画面里有一个在推进的变化（慢推、数字滚、逐条点亮、角色在动）。
- **数字按比例**：台词里有数字对比时，画面的高度或面积比和数字对得上。在 `film.mjs` 里 `export QUANTITIES`，体检会量。

## 5. 用世界引擎写画面

- 所有东西都是持续存在的物体：`WORLD.add(id, { x, y, w, h, z, draw })`；`WORLD.to(id, t0, dur, {...})` 让它变；镜头用 `WORLD.camTo` / `WORLD.hold` / `WORLD.hit`。
- 接力动作（`carry.*`）：

| 动作 | 用在什么时候 | 例子 |
|---|---|---|
| `shrinkInto` | 一样东西变成更大整体的一部分 | 一杯水缩进日历的一格 |
| `pullOut` | 揭示「原来前面是局部」 | 拉远看到一整个月 |
| `growInto` | 小东西展开成下一个场景 | 卡片展开成整页 |
| `pushInto` | 镜头推进一个东西，直到它成为下一个场景 | 推进网页 |
| `snapTo` | 镜头快速对准将要落地的点 | 数字砸下来的位置 |
| `makeWay` | 其他东西让位，给主角腾地方 | 内容依次让开，露出结论 |
| `scaleAs` | 用前面的东西当尺子 | 2000 ml 的水位 = 500 ml 的 4 倍高 |

- 甩镜、换页这类兜底转场才用 `lib.mjs` 的场景函数。
- `drawFrame(ctx, t)` 是纯函数：随机数用 `rng(seed)`。`film.mjs` 导出 `DURATION`、`TIMELINE`（每段屏幕文字）、`WORLD`、`QUANTITIES`。

## 6. 检查表（找「最弱 3 秒」时逐条过）

每一条都要能指着拼板上的某几格回答：

1. **物变**：每个重音，拿说出关键词前 0.2 秒和后 0.5 秒两帧对比，画面里的东西本身变了吗？还是只有字变了？
2. **起伏**：`check_all` 的能量曲线里，超过 5 倍的秒对准重音表了吗？重音之间收住了吗？
3. **变天**：转折那一秒前后两帧并排，整屏变了吗？
4. **接力**：每个段落边界前后两帧并排，有同一个物体在两边吗？
5. **遮字**：遮住字，每一段能说出意思吗？说不出来的写下秒数。
6. **满屏**：主体占画面高度 1/3 以上吗？下半屏空着的时间，`check_all` 报了多少秒？（横版看第 8 节）
7. **开头和结尾**：第 0 帧在动吗？最后一帧和第 0 帧并排，是同一样东西的两种状态吗？
8. **风格**：用了 `frame.md` 里几招？每一招对上了哪句话？

## 7. 风格规范怎么用

- `frame.md` 管「长什么样」：材质、配色、字体、镜头语法、转场方式。照它做。
- 规范里列出的招式（native moves、变化空间里的例子）是这个风格的工具箱：挑能对上台词的用，越多对上越好。转折处用它允许的那种「整片变状态」的招式来变天。
- 规范里的限制只管它点名的那件事；它允许的事（例如「切换主题可以是剧情事件」），放心用。
- 没有 `frame.md` 时：深色底 `#07080C`、米白字 `#F4F2EC`、一个强调色 `#FFD43B`，强调色只给观众必须记住的那个词。

## 8. 横版 16:9 构图

`aspect.txt` 是 `16:9` 时，画布是 1920×1080，引擎的 `W`、`H`、`SAFE` 自动跟着变。坐标一律用 `W`、`H`、`SAFE` 算，同一份代码在两种画幅下都对。

- **没有平台遮挡**：四边各留 5% 边距（`SAFE` = x 96–1824、y 54–1026）就够，不用躲点赞栏和标题区。
- **左右分区**：横版的天然结构是左右两块。对比、前后、原因和结果，左右并排放比上下叠更好读；一屏一个焦点的规则不变，另一边压暗或留白。
- **镜头往横向走**：一个世界在横版里更宽，推拉之外多用横摇和横向跟随；接力常是「东西从左边带到右边」。
- **字一行写完**：横版一行能放更多字，标题尽量一行写完。
- **满屏的标准换成「中间那条带」**：主体占画面高度 1/3 以上；检查下半屏（y 540–1026）有没有长时间空着。
- **字号下限不变**：画面高只有 1080，同样的字在横版里显得更大，大字占屏的比例要按高度来算。
