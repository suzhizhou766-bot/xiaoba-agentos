# 宣传片与科普视频 Skill 的学习分析

日期：2026-10-22  
性质：源码学习、安装试运行与方法归纳；不是生产能力验收，也不是用户已采用的经验。

分类补充（2026-10-23，用户确认）：video-shotcraft 是**宣传片 skill**；anything2explainer 是**科普视频 skill**。本文分别分析两类用途，共同制作方法只作比较。两者均面向 Claude Code 和 Codex，并非 Codex 专用。

## 1. 我的判断

这两个项目放在一起，可以提炼出一条完整的制作思路：

**内容和证据 → 叙事关系 → 声音与节奏 → 镜头配方 → 可编辑的时间线 → 渲染与检查 → 反馈修正。**

video-shotcraft 解决“怎样把产品和页面拍得有表现力”；anything2explainer 解决“怎样把知识讲清楚并落实为画面”。对小八最有价值的学习对象，是它们怎样把内容、画面、参数、时间和验收连接起来。

本轮已经做完：读取入口与关键规范、抽查实现、观察样张与正反对照、核对全部下载源码、安装三个 Node 项目、通过两个模板的类型检查和工作台构建、各渲染一段 30 帧测试视频。尚未做完：用户真实题材的完整制作、配音生成、全片视听验收、OriginCut 原生组件适配。

## 2. 两个项目各自提供了什么

| 项目 | video-shotcraft | anything2explainer |

| Skill 分类 | 宣传片 skill | 科普视频 skill |

## 3. 从 video-shotcraft 学到的六件事

### 3.1 镜头应按“表达什么关系”组织

“旋转、缩放、发光”只是动作名称。“从整体定位到一个重点”“把组成部分展开”“从多个候选中找出目标”才接近可用的镜头意图。

例如，它的空间运镜卡明确区分：分解展示组成，与从全局落到焦点，是两种不同叙事。小八自己的配方可以先按比较、因果、筛选、层级、定位、回扣分类，再选具体运动形式。

收益：AI 选镜头时更接近内容需要；人寻找配方时不必先猜作者起的效果名。

证据：[space-camera-moves](https://github.com/Vincentwei1021/video-shotcraft/blob/43bd349a136651865ecfa6ea1cf012f6e957d304/references/shots/camera/space-camera-moves.md)。

### 3.2 配方需要同时保存适用范围、参数和失效条件

一张真正能复用的配方，至少要回答：讲什么、要什么素材、动作分几段、怎样调、什么不能乱改、怎样判定失败。

源码卡片记录了分层截图要求、特写纹理要求、速度分配和落定停留等条件。这说明“效果看起来差不多”不足以证明复现了同一种表现；某些时序与空间关系是效果成立的关键。

可以学习“可调参数 + 稳定约束”的结构。文案、颜色、主体位置可以开放；容易破坏阅读与动作重量的参数，应限定范围并提供解释。具体阈值需要用小八自己的样片重定，不能直接固化上游数字。

### 3.3 真实页面素材的准备，决定了后面的上限

整页截图适合整体展示；要拆层、侧看、特写，就要准备对应的分层、尺寸和纹理。把同一张小截图放大或倾斜，不能自动获得精细的空间关系。

这与小八已有的原图细节和建筑保真要求相通：先确定素材允许怎样动，再设计镜头。对真实楼体，可以移动镜头、加标注；没有依据的结构和遮挡后细节不能被当成真实信息补出。

### 3.4 品牌视觉应与运动结构分开

可以保留某种镜头的运动关系，同时用项目自己的字体、色板、材质和信息密度重新设计画面。

这能形成“小八配方的同一表达意图 + 不同项目视觉”的组合：青训、地产、软件演示各有自己的画面语言。它们不应该自动继承同一种科技紫光或某个模板的外观。

证据：[shotcraft 核心原则](https://github.com/Vincentwei1021/video-shotcraft/blob/43bd349a136651865ecfa6ea1cf012f6e957d304/SKILL.md)。

### 3.5 可编辑必须写清具体层级

本次直接核对了工作台实现：普通 demo 卡的 schema 为空，能调整片段时间和图层；需要组件把参数暴露出来，属性面板才能改文案、颜色等内部内容。模板与部分原生卡提供了这样的参数。

因此小八配方应逐项声明：

- 片段层：能否移动、裁切、变速。
- 内容层：能否改文字、数据、颜色、位置。
- 动作层：能否改幅度、曲线、时序。
- 工程层：哪些东西仍能在原制作工具里继续编辑。

剪映导出也有同样边界：镜头内部动效会烘焙为视频，字幕与声音等可分别保留为原生轨道。不能用“可编辑工程”概括所有层。

证据：[工作台契约](https://github.com/Vincentwei1021/video-shotcraft/blob/43bd349a136651865ecfa6ea1cf012f6e957d304/references/workbench.md)、[demo 卡实现](https://github.com/Vincentwei1021/video-shotcraft/blob/43bd349a136651865ecfa6ea1cf012f6e957d304/workbench/src/cards/demoCards.ts)、[剪映导出](https://github.com/Vincentwei1021/video-shotcraft/blob/43bd349a136651865ecfa6ea1cf012f6e957d304/references/jianying-export.md)。

### 3.6 预览、参数表与渲染应来自同一个定义

如果预览是一段手做视频、参数表是另写的文字、最终执行又是另一套代码，很容易逐渐不一致。上游用索引与时间线清单把组件、时长和素材联系起来，这个方向值得学习。

本机还发现：下载包里没有画廊动态样片文件，生成的工作台索引显示 **150 张 demo、0 张附带预览视频**。组件可以实时渲染，在线画廊另有动态样片；“有 150 个实现”与“离线带齐 150 段预览视频”是两件事。

## 4. 从 anything2explainer 学到的六件事

### 4.1 事实应在文案前成为可检查的材料

该项目先调研，给数字与陈述留出处，再写讲解与画面。这个顺序让后续返修有落点：改的是事实、说法，还是表现方式，可以分清。

对小八可推导出“事实条目 → 解说段 → 镜头 → 屏幕标注”的追踪关系。这样遇到一个数字变化，就能定位受影响的镜头。是否自动更新、是否需要重录配音，仍需单独判断。

### 4.2 先把一句话变成“可见的变化”

讲原因，就让观众看见作用与结果；讲筛选，就让条件改变候选的去留；讲组成，就让部分与整体保持对应。

“画面里出现了关键词”只是覆盖了文字。观众能否从动作中推理出关系，才是这类讲解画面的价值。可以用一个简单检查：暂时遮住标题，画面的变化是否仍传达了所要讲的关系。

### 4.3 配音是时间基础设施

配音脚本不只生成声音，还生成字幕与镜头可引用的时间信息。上游支持按句、字幕块和章节定位，分镜再引用这些标记。

重要限制也在源码里：后续镜头大量使用固定帧号；文案改动后，配音与镜头可能都要重新对齐。可学习的改进方向，是让小八尽量引用稳定的语义锚点，再在渲染前统一解析帧号。它是本次推导，尚未实现。

证据：[TTS 构建脚本](https://github.com/Vincentwei1021/anything2explainer/blob/735c79c8724e897e8971cd59dde7e5aa11e4d6ce/template/scripts/tts_build.py)、[文案与分镜](https://github.com/Vincentwei1021/anything2explainer/blob/735c79c8724e897e8971cd59dde7e5aa11e4d6ce/reference/narration-storyboard.md)。

### 4.4 镜头应围绕一个画面单元持续展开

短句可以在同一个空间中接着讲，一个对象可以从主角退成参照物，再引出下一个对象。这样更容易形成连贯的解释。

章节衔接也一样：上一段留下的问题、已经得到的结果或仍在画面的对象，可以成为下一段的起点。不要把“有转场效果”直接等同于内容承接成立。

### 4.5 动作需要发展，也需要让人看懂落点

上游复盘了两种失衡：元素入场后长期没有有效变化，以及元素刚落位就立即切走。它的修正是让内容相关的动作继续发展，并给结果留阅读时间。

小八能借鉴这一对约束，但需要按题材重定尺度。训练回放、建筑留景和观众需要读图的时候，静止可以有意义；持续运动也可能分散注意力。不要为满足变化率而加呼吸、漂浮或无关运镜。

证据：[构图与光的复盘](https://github.com/Vincentwei1021/anything2explainer/blob/735c79c8724e897e8971cd59dde7e5aa11e4d6ce/reference/composition-and-light.md)。

### 4.6 审美可以留下证据，数值要保留解释空间

已经目视查看上游六组正反帧对照。较明确的差别包括：细小时间轴与突出量级的数字、分散的小图形与有明确主体的构图、只列公式与突出结果项的画面。

这些对照支持“主体、注意力和内容表达比装饰数量更重要”的判断；它们不是同一素材的严格控制实验，也不能证明固定紫光或某个尺寸在所有题材中更好。静帧也不能替代完整观看节奏。

## 5. 把两者组合后，可以推导出什么

以下都是本次分析提出的方案，尚未作为新软件能力实现。

### 5.1 用语义关系组织的小八原创动效库

每个配方既有人能看的动态预览，也有 AI 能读的用途、输入、参数、限制、时间锚与验收标准。人可以挑选并精调，AI 可以按内容调用。

这与现有“小八自己的动效库”的方向一致。按已确认的学习边界，新配方由小八独立定义、独立实现；两仓库作为参考材料保留。

### 5.2 把文案意图转成分镜的规划器

可设计为：输入文案与事实材料 → 标出比较、过程、因果、范围等关系 → 选配方 → 分配主体和画面空间 → 输出可检查的分镜。

关键困难是判断关系是否真实成立。AI 不能因为看见一个动词，就机械套一个动画；找不到可靠画法时，应保留原片或简明说明。

### 5.3 同时理解语音与音乐的时间安排方法

有讲解时，以理解和配音为主；无讲解的宣传段，可以以音乐节拍为主。两者冲突时，要有明确优先级。

例如同一个动作可以记录“在某个词附近出现、优先靠近一个重拍、仍须满足最短阅读时间”。精确落帧要在已知帧率和真实音频上计算，不能靠估计。

### 5.4 跨工具的时间线交换说明

可先定义不依赖制作软件的数据：素材、对象、文字、关系、时间锚、镜头、声音、参数和可编辑层级；再分别适配工具。

它可能帮助 Remotion、AE 与 OriginCut 接收同一个创意方案，但各工具的渲染模型和能力不同，需要独立适配。当前没有验证这两项目存在 OriginCut 原生导出，也没有验证 Remotion 组件可以直接变成其原生组件。

### 5.5 从同一内容形成多种交付

一份经确认的主题材料，可用于长讲解片、短预告、图文关键帧、演示稿和交互图解。共享的是内容与关系，画幅、密度、节奏和交互方式仍要分别设计。

横转竖需要重新构图；长转短需要重新取舍论点；中英切换需要重新对齐声音与排版。改变输出尺寸不能替代这些工作。

### 5.6 把质量检查做成创作的辅助

检查可以覆盖：字是否溢出、主体是否遮挡、字幕是否撞区、时间线是否留缝、素材是否齐全、配音和重点是否对齐，以及不同交付格式是否兑现编辑能力。

审美判断仍需回答：为什么此时要动、观众是否看懂、声音是否支撑画面、最弱的几秒在哪里。机器结果提供线索，人的观看决定这些线索是否重要。

## 6. 可以实际产出的成果与优先级

| 候选成果 | 对你工作的直接用途 | 需要补齐 | 建议顺序 |
|---|---|---|---|
| 六张小八原创动效配方的小样 | 先证明预览、参数和调用确实一致 | 独立实现、真实素材、逐卡验收 | 1 |
| 实拍与图解的连续承接小样 | 活动、建筑、青训片里的说明段 | 对象标注、运动或遮挡处理 | 1 |
| 语音与节拍对齐的小样 | 让解说重点、动作落点和音效更一致 | 配音时间戳、节拍分析、容差规则 | 2 |
| 青训训练回放讲解片 | 原片回放与经过确认的路线、区域标注 | 原始录像、教练确认的分析内容 | 2 |
| 建筑空间与材质说明片 | 在真实画面上解释空间或调色选择 | 确认的结构和原图、遮罩、来源记录 | 2 |
| 小八功能演示短片 | 基于实际页面展示某个功能 | 演示数据、真实运行证据、品牌视觉 | 2 |

## 7. 哪些不能照搬

1. **外观不自动成为小八风格。** 科技紫光、固定黑底、故障闪烁都有适用范围；小八视觉任务仍先看审美手册和当前项目。
2. **项目规则不自动成为用户规则。** 上游写的“用户偏好”和复盘，属于上游项目语境，不能写入小八用户偏好。
3. **固定像素阈值要重新标定。** 720P 下的字高、主体尺寸和字幕区不能直接用于 1080P、4K 或竖屏。
4. **生成与检验分开。** 一次编译、静帧或一分钟内测试，不能替代完整片的内容、节奏和声音验收。
5. **源码可编辑与原生工程可编辑分开。** 渲染后的文字和图形可能已经烘焙，分辨率也不会改变其编辑结构。
6. **并行数不是固定生产规模。** explainer 文档的多 Agent 规模需要结合当前会话可用性、资源与授权；本轮没有启动子 Agent。
7. **授权分别核对。** shotcraft 代码文档标注 Apache-2.0，音频另有授权；explainer 工具包标注 PolyForm Noncommercial，作者明确要求商业使用事先授权。Remotion 自身也有单独条款。不能因“输出归创作者”就推断工具使用没有限制。
