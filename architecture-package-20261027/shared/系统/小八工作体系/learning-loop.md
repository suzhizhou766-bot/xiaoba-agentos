# 小八经验回流闭环

## 状态机

`任务结果 → 经验候选 → 交付初审 → 终审 → 发布进第二大脑 → 索引更新 → 检索复验`

## 谁做什么

| 步骤 | 谁 | 怎么做 |
|---|---|---|
| 登记候选 | 任意 Agent | `xiaoba memory-candidate-create --title … --body-file … --author <agent-id>`，附证据 |
| 交付初审、终审 | 只有用户 | 小八监看中心的「裁决中心」`http://127.0.0.1:8799/#review`，或 `xiaoba review TASK_ID --stage delivery|final --decision approve|reject|revise|retire` |
| 发布 | AgentOS | 两次批准绑定同一候选哈希后，写入第二大脑 `70_复利规则/经验/` 并更新索引 |
| 复用对账 | AgentOS | 复用失败达到上限的经验自动退役 |

## 什么值得登记

- 会影响后续工作的事实结果。
- 可以跨项目复用的方法、参数或成功机制。
- 错误现象、根因、修复和复验方式。
- 可能取代现行规则的用户纠错；未经用户确认只能是候选。

没有复用价值的不登记。项目素材、成片、草稿留在项目目录。

## 边界

- 任何 Agent 和脚本都不得替用户批准，也不得绕过候选直接往 `70_复利规则/经验/` 写。
- 用户明确指定的小修正可以直接改第二大脑原文，改完必须重建并校验索引（命令见 `AGENTS.md` 第 5 节）。
- 第二大脑是严格的树：新增笔记只在父笔记里被链接一次，不加横向的双方括号链接。
- 用户说“交付”时，一次交齐交付记录、经验候选，以及踩坑、打法、偏好三类条目。
- “检索到”“生成成功”“技术健康”都不等于“用户采用”。
