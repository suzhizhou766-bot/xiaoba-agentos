# Key 池余额接给第三方客户端（2026-10-18）

场景：某个客户端（例如 DSH 的鲸鱼余额挂件）只会读某家官方的余额接口，用户想让它显示 Key 池的余额。

## 步骤

1. **先查 Key 池已有的余额规则。** 位置在 `工具/小八监看/monitor_core/keypool_balance.py` 和 README 的“余额查询”。tierflow 节点的 API Key 查不了余额，要用网页会话（Session Cookie + TF-User）查；会话只放在 `keypool.json`（600），不交给任何客户端。
2. **读客户端源码，不只看 README。** 要弄清四件事：它请求哪个地址、能不能改地址、认证头怎么写、能不能加别的请求头、字段路径怎么取。鲸鱼挂件的「自定义 HTTP」只能带 `Authorization`，所以客户端直连站点的网页接口走不通。
3. **在 8780 代理上做兼容接口，由代理自己回答。** 现成的接口是 `GET /user/balance`：DeepSeek 格式、全池合计、要主 Key。读数来自监看中心已经推给代理的余额提示，不额外请求站点。别的格式需要时照这个加，不要把请求转发给节点。
4. **先在副本里改和测，给用户看过再上线。** 把 `monitor_core`、`tests` 复制到草稿目录（不复制 `keypool.json`）；用户确认后打补丁。上线前确认线上文件和草稿的原件一致，没被别人改过。
5. **用客户端同样的取数逻辑做模拟。** 把它解析字段的那几个纯函数（如 `pickJsonPath`、`apiNum`）照抄，对草稿接口跑一遍，分别看有读数、Key 错、没有读数这三种情况。
6. **上线后带正确的主 Key 验证。** 不带 Key 时新旧代码都是 401，证明不了接口生效。用存储的主 Key 在本机进程里请求一次，只打印状态和余额。代理是监看中心的子进程，要重启才加载新代码，重启前先告诉用户（会断掉正在进行的请求）。

## 交付时要提醒用户的

- 客户端按余额下降算的“今日已用”，是整个 Key 池所有客户端、所有账号的花费；充值、续期会让余额上跳。
- 监看中心没开时接口返回 503。
- 主 Key 由用户自己填进客户端。
