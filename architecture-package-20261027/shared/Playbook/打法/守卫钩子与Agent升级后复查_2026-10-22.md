# 守卫钩子与 Agent 升级后复查（2026-10-22）

## 做法

- 各 Agent 的执行前钩子只写一行固定命令 `私人助理/工具/治理/guard.sh`，规则只改 `系统/治理/policy.json`，钩子配置一个字节都不动。
- 作用范围（用户 2026-10-22 定）：读凭据的规则全局生效；rm、git push、mv、git commit、`/usr/bin/python3` 等命令规则只在私人助理和小八AgentOS 内生效。
- guard.sh 出故障就拒绝（fail-closed）：解释器、guard.py 或 policy.json 坏了，所有带钩子的 Agent 都会被拒；修复要用户在终端做，或从对应配置里去掉 hooks 键。
- 命令规则是对整条命令文本做正则，heredoc 或字符串里只要出现“git push”“rm ”之类字样也会被拦。要写含这些字样的文档，用 Agent 的写文件工具，不要用 shell heredoc。

钩子位置：Claude Code `~/.claude/settings.json`、Codex `~/.codex/hooks.json`、Qoder `~/.qoder/settings.json`、Antigravity `~/.gemini/config/hooks.json`。DSH 没有钩子，只靠沙箱档位。

## 每次 Agent 升级后必须复查

升级不会覆盖用户配置，但工具改名、配置格式改版、配置迁移都可能让钩子**静默失效**（不报错，照常放行）。所以每次有 Agent 升级，在它里面跑 V4 卡（`工作区/小八融合迭代-20261022/验证任务卡/任务卡/V4-各Agent-验证-钩子拦截实测.md`）的第 1 步（删靶子文件）和第 2 步（读 `假凭据.env`）。没被拦就是失效，先查工具名和钩子文件格式。Codex 升级后还要看钩子浏览器里有没有要求重新信任。

体检脚本：`工具/治理/钩子体检.sh`（只读，退出码 0 正常、1 有异常）一次查四家钩子是否还指向 guard.sh、比较各 Agent 版本、跑守卫自测、查两条全局 AGENTS.md 软链。升级提示只在检测到变化的那一次出现（随后版本记录就更新了），看到就当场去跑 V4 卡。
