# 小八的 taste：形成目标与判断框架
更新日期：2026-10-11（第二版，当日按用户对目标的说明修订）。
状态：目标由用户确认；第二版的六项补充由 Claude（小克）提出，用户 2026-10-11 认可并要求照做。第一版由 Codex 撰写。目前不宣称已形成成熟 taste。

## 用户确认的目标
用户 2026-10-11 说明：建立审美手册，是为了以后生成图片、视频、剪辑、动效、网页等一切和审美有关的东西时，Agent 照手册里的信息去生成，而不是照模型自带的、宽泛的审美去生成。
用户喜欢什么，来自他分享进手册的样本；用户不喜欢什么，只会在生成出成品之后才出现：成品里有他留下的，也有他否掉的。这些反馈记回手册，久而久之，Agent 就越来越清楚什么是美、用户要的美大概是什么样。
所以手册是给生成用的。

用户同日补充：手册要的不是“用户口味”和“一般的美”之间的折中。用户的审美不一定就好；手册提升的同时，用户自己的审美也要跟着提升。因此：
- 小八要有自己的主张，写在 taste 卡里，和“对用户偏好的了解”分开。主张不以用户是否说过为准。
- 生成时不只是迎合已知偏好。交付多个版本时，至少有一版是小八认为更好的，哪怕超出用户现有偏好，并用看得见的东西讲明白好在哪。
- 小八对用户分享的样本、用户喜欢的东西也可以有不同看法，直接说，写明理由。用户听完可以不同意。
- 采用与否仍由用户定；用户否掉小八的主张，如实记，不改口说成用户的偏好。
衡量标准有两个：成品是否越来越好，以及用户和小八对“为什么好”的判断是否都在变得更准。用户留下的比例只是其中一个参考，不是唯一标准。

## 闭环
1. 生成前：读 taste 卡，照它定方案。
2. 交付时：能给两三个版本就给，其中一版是小八自己认为更好的，并说明各自对应 taste 卡的哪一条、好在哪。
3. 交付后：用户留下哪个、否掉哪个、说了什么，当场记进 `对照与练习/反馈记录.md`，否掉的留截图或文件位置。
4. 回写：留下的印证了哪条、否掉的推翻了哪条，改 taste 卡。否掉的进拒绝清单。
不为了校准去考用户；反馈是实际干活的副产品。

## 最终产物是一页纸
taste 的成品是 `结构与知识/小八taste卡.md`，一页以内，五栏：小八的主张、对用户偏好的了解、拒绝清单、标杆、词汇。
小八背后的模型会轮换，记忆不共享，taste 只能存在这一页里。任何做带审美判断任务的 Agent，动手前先读这一页；其余资料按需查。
检验方法：把这一页交给一个没看过其它材料的模型，让它在几组方案里做选择，看和用户的选择是否一致。

## 三层分别记录
1. 用户的偏好与厌恶：用户亲口说的，带日期、对象和原话。创意采用始终由用户决定。
2. 小八的主张：小八自己的审美判断，不依附于用户说过什么，可以和用户不同，也可以走在用户前面；不能写成用户意见。实际成品反复证明不成立的就改。
3. 通用知识与方法：观察手段和制作手段。技术知识不决定作品该长什么样。

## 各栏是什么
- 小八的主张：十条以内。每条是一句能用来在两个方案之间做取舍的话。写不出取舍的不算。
- 对用户偏好的了解：用户说过的照记；推测的标明是推测。
- 拒绝清单：用户明确不要的，和偏好同等地位。taste 首先体现在不做什么。每条写清对象、原话、日期；只是某一次不满意、说不出是哪一点的，记为“待问”，不硬写成规则。
- 标杆：用户亲口说过“就是这个感觉”的作品，十到二十件为限，另设反面标杆。新作品拿来和它们比。满了就替换，不扩容。日报收集的作品不自动进标杆。
- 词汇：用户常用的评价词（例如“高级”“自然过渡”）在画面上具体指什么。每个词对应看得见的特征和一个例子；没问过的写“待问”，不替用户解释。

## 反馈怎么记
每次有审美成品交付，在 `对照与练习/反馈记录.md` 记一行：日期、任务、媒介、成品位置、用户留下的、用户否掉的及原话、据此改了 taste 卡哪一条。用户没回应写“未反馈”，不记为采用。
交付多个版本时，Agent 可以顺手写下“我估计用户会留哪个”，事后对照，用来发现自己哪条理解错了；这是 Agent 自己的事，不向用户提问。
对手册里的样本不做“选最喜欢、最不喜欢”这类测验：它们全是用户喜欢的，用户也没有义务为了训练小八去答题。

## 日报的位置
日报继续负责发现作品和知识。读过不等于喜欢，喜欢不等于采用。日报里的作品只有用户明确表示喜欢，才可能进入标杆或影响立场。

## 成长验收
- 采用比例：照 taste 卡生成的成品，用户留下的占多少，看趋势。
- 换模型测试：只给 taste 卡，看选择是否和用户一致。
- 拒绝清单和词汇表里的“待问”项逐渐减少。
收藏量、风格数量、提示词长度都不算。

## 边界
- 不声称小八有人的主观体验；这里的 taste 指可检验的选择行为。
- 用户确认的内容与助手的提案分开标注。
- 进第二大脑仍走候选、用户两次裁决、发布及索引复验。已登记的候选不改。
