# 小八整合、多个 Agent 与现有工具

共享路径均相对 `/Users/suzhizhou/Documents/私人助理`。权威入口是 `AGENTS.md` 与第二大脑根笔记；现场运行版本由 `~/.agents/skills/xiaoba-agentos/scripts/xiaoba doctor --json` 核对，不从本技能写死发布号。

调用关系：用户任务 → 宿主经理确认授权和目标 → REA CLI/MCP 采集证据 → 宿主整理问题与实现 → AGY/DSH 只读独立审查（需要时）→ 宿主验证 → 用户决定采用。REA 是分析工具，不是第三个投票 Agent，不替代两后台，也不改变其模型、认证、路由、权限或裁判规则。

1. 先读 `系统/小八工作体系/registry.json` 中 `rea` 模块的 manifest（模块清单），确认入口与健康证据。`implemented`（已实现）只代表安装入口存在；`partial`（部分实现）必须展开具体限制。
2. 一次调查使用单一任务输出根：目标摘要、授权范围、问题、REA 原始 Evidence（证据）、必要视图、命令/退出码与哈希。多个 Agent 共享证据文件，不共享会话句柄，不并行打开同一原生目标。Hopper 对相同目标有会话所有权限制，关闭 REA 会话不保证 Hopper 文档关闭。
3. 普通本地分析由宿主直接执行。确需双后台时按现行 `xiaoba-agentos` 技能生成任务；AGY 重点审查调用链/平台约束，DSH 重点审查证据完整性/替代解释，两者仍须独立看同一份证据并给出各自结论。不要自动向其他聊天发送任务，不把后台建议说成已执行修改。
4. 使用当前发布的 `docs/COLLABORATION.md`（协作规则）和 `docs/RELEASE_V1.6.1.md`（内容维护规则）解析实际参数。正式技能更新在草稿中完成，经 `skill-review-prompt`（审查说明）→ `submit`（提交双后台）→ `skill-publish`（按审核登记）完成。后两者不能被手改 `skills/index.json` 代替；使用当前发布内相应文档而非猜旧目录。
5. 后台未健康、认证失败、429/503（限额/服务异常）时保留单次失败证据，停止自动重试，不修改登录材料或路由，不绕过正式技能的审核门禁。已安装的独立 CLI 仍可在原授权内使用，正式技能状态必须如实标注。

与现有能力的边界：

| 现有能力 | REA 如何配合 |
|---|---|
| KnowLP（知识定位） | 定位技能/调查入口，命中后回读原文；不把大型 Evidence 塞进知识库 |
| assets（资产审计） | 对授权目标、证据、独立实现分别记录哈希和交付边界；原素材和目标不被分析脚本改写 |
| Remotion（视频合成）/本地工具 | 可研究已授权插件或项目的静态模块关系；不改其版本、不启动已有常驻服务 |
| director（导演编排）/macOS 控制器 | 将分析结论作为输入；实际应用操作仍走既有接口和本次授权 |
| 达芬奇/五工具 | 保持现有 MCP、端口与运行环境；不因为装了 REA 就替换控制链或动态注入 |

MCP 配置片段在 `工具/REA逆向/config/`。Codex、Claude Code、Antigravity、DSH（DeepSeek Harness）有不同配置格式，不能把通用 JSON 直接覆盖个人配置。DSH 官方适配是 Cordis YAML（插件补丁配置）中的 `@deepseek-ai/dsh-mcp-client`，启动 `bin/rea mcp`；本次仅提供片段，不注入现有 Harness 路由。

本模块 `publish_enabled=false`（禁止自动发布），无开机自启、无定时升级。第二大脑只放事实入口和已审核内容，原始调查材料留任务目录；新增经验走候选→用户初审→终审→敏感检查→索引复验，技能登记不等于批准经验。本部署不改全局 memory（记忆）策略、release（发布）指针或运行包。
