# REA 主动提问与选项

用于用户调用 REA 但需求尚不完整的场景。先读当前对话，删除已回答的问题，不把这些选项机械地全问一遍。默认按静态分析准备；不能把选项默认值当作用户提交的答案。

## 首轮最多三组问题

可先说：“我先按静态分析来准备，请选分析对象、重点和授权情况；也可以直接用自己的话补充。”有提问组件就使用组件；否则按下面的编号给选项。

**1. 需要静态分析什么？（单选或自述）**

- A. Mac 上已安装的应用（`.app` 应用包）
- B. JavaScript / Electron 应用目录或 ASAR（应用归档）
- C. 原生可执行文件或动态库
- D. 其他本地文件（例如 .NET、WASM、APK、已保存的离线网页）
- E. 还不确定，先帮我判断适合哪种分析

选择类别不等于已经指定文件。选 A 时接着要应用名或路径；选 B/C/D 时要文件或目录路径。选 E 时先询问文件名、扩展名或用户已知的应用信息，仍需完成授权确认才读取目标。若用户想分析在线网站，另明确网址、允许访问的范围和联网授权，不能把离线选项当作联网许可。

**2. 分析重点是什么？（可多选，也可写具体问题）**

- A. 整体结构、文件和资源清单
- B. 某项功能如何实现、相关代码与调用链
- C. 模块依赖、接口或通信关系
- D. 界面结构与交互实现线索（静态证据，不宣称观察了运行行为）
- E. 权限声明、敏感能力及安全风险线索
- F. 先做概览，再根据结果选择重点

选 B/C/D/E 时，只有具体对象或问题不清楚才追问，例如“你说的导出功能，是导出 PDF 还是视频？”用户拿不准重点但已明确允许静态概览时，可选 F，不因此要求他理解技术分类。

**3. 你对这个目标具有什么分析权限？（无默认肯定答案）**

- A. 尚未确认或未获授权
- B. 我拥有这个目标，并确认有权做本次静态分析
- C. 我已获得明确授权，范围包含本次静态分析
- D. 我有其他授权或限制，需要补充说明

若选择组件强制预选首项，保留 A“尚未确认”，仍须等待用户提交答案，不能将默认值当作答复。所有权/授权选项只覆盖用户确认的目标和操作，不能延伸成执行应用、附加进程、联网截流、复制受保护代码或分析其他软件的许可。D 只澄清影响本次任务的限制；A 暂不读取/分析目标，可说明需要确认哪些权限或用自建样例演示。不索要密钥、账号密码、完整合同等无关敏感材料。

## 后续补问与形成任务

只补问影响执行的缺口：具体应用名/路径、功能或文件、必要的授权范围。输出要求未指定时默认保存原始 Evidence（证据包），在对话中给中文结论、来源位置和局限；用户需要时可选择“简短概览”“完整报告与证据”“独立实现建议”。不要为选输出格式阻塞已经清楚的分析。

需求齐全时直接整理并执行，例如：“我会静态分析你已授权的 Example.app，重点看导出 PDF 的实现与模块依赖，保留原始证据并给出中文报告。”这句话是任务整理，不是再要求用户批准一次。随后按 SKILL.md 的工作流选择本机实际可用能力；缺少原生反编译引擎时说明限制，可先做已授权的包结构/依赖盘点，不伪称已反编译。

## 对话边界示例

| 用户输入/已知信息 | 应有行为 |
|---|---|
| 只有“调用 rea” | 给上面的三组选择；等待答案，不扫描应用或读取任意目标 |
| “调用 rea，看我的 `/目标/示例.app` 的文件结构，我确认有权做静态分析” | 已有目标、重点、授权，整理一句任务后直接执行，不重复问三题 |
| 已有授权目标和路径，但只说“帮我看看” | 只问分析重点；允许用户选择静态概览 |
| 已选“Mac 应用＋依赖关系＋已获静态授权”，未说哪一个应用 | 只补问应用名或路径；不用再确认同一授权 |
| “还没拿到授权，先分析一下再说” | 暂不读取目标，说明需要的权限或提供自建样例演示 |
| “静态分析后顺便运行它抓流量” | 对新增执行/联网捕获范围澄清授权；原静态授权不被扩展 |
| 询问“REA 能做什么”或要求修改本技能 | 正常回答或维护技能，不把问卷发给用户 |

本文件规定的是主入口加载技能后的对话行为；它不新增后台服务或独立表单网页。选项呈现形式由当前宿主支持的问答组件决定。
