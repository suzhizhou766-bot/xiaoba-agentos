# 达芬奇

工具目录 `工具/达芬奇/`（上游开源项目 davinci-resolve-mcp，MIT）。第二大脑卡 `20_能力与技能/达芬奇.md` 记着接入方式和已验证边界，以它为准。

## 第一步检查（每次都做）

1. 达芬奇已经开着，并且**打开了要操作的项目**（停在项目管理器拿不到项目）。没开就提示用户，**不开机自启、不替用户打开**。
2. 调用**一律走达芬奇 MCP**（`mcp__davinci-resolve__*`）。
3. **不要在 Bash 里用 `python3` 直接 `import DaVinciResolveScript`**：会落到系统 3.9.6，加载 `fusionscript.so` 后退出时段错误崩溃。确需写脚本，只用 `工具/达芬奇/venv/bin/python`，并在脚本末尾 `os._exit(0)`。
4. 带审美判断的工作（调色、画面、节奏）先读审美手册 `审美提升/审美手册.md`。

## 边界

- 删除素材或时间线、覆盖已有文件的渲染、丢弃未保存的工程，动手前先问用户。
- 渲染输出目录先和用户确认，不直接渲染进交付目录。
- 切换或关闭未保存的项目会弹窗，脚本关不掉，要用户手动点。
- 逐帧修剪、拖动剪辑点这类精细手工剪辑，脚本接口基本不支持，直接告诉用户。
- 默认 stdio 方式没有令牌。网络方式（`--transport sse/streamable-http`）的令牌走 `$DAVINCI_MCP_TOKEN`；没设时自动生成，并写进上游私有状态目录里的 `mcp_transport.json`（权限 600，见 `src/utils/mcp_transport.py` 开头）。这个文件按凭据对待，不读、不打印。
- 工具目录自带的 `AGENTS.md`、`CLAUDE.md` 是上游写的，和本技能冲突时以本技能和小八 `AGENTS.md` 为准。
