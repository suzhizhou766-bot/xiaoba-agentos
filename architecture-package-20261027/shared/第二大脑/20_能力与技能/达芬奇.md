# 达芬奇

达芬奇（DaVinci Resolve Studio）调用入口卡。Agent 通过达芬奇自带的脚本接口控制正在运行的达芬奇：项目、媒体池、时间线、调色、Fusion、渲染交付。它属于工具入口卡，不把工具本体复制进第二大脑。

关键词：达芬奇、DaVinci Resolve、调用达芬奇、剪辑、调色、渲染、交付、媒体池、时间线、MCP。

- 工具目录：/Users/suzhizhou/Documents/私人助理/工具/达芬奇（开源项目 samuelgursky/davinci-resolve-mcp，安装时为 v4.10.6，MIT）
- 解释器：小八统一的 Python 3.14.7（位置见 /Users/suzhizhou/Documents/私人助理/配置/环境索引.md）；虚拟环境在工具目录的 venv 下。系统自带的 python3 没有改动。
- Claude Code 入口：/Users/suzhizhou/Documents/.mcp.json 里的 davinci-resolve 服务，工作目录为 Documents 的会话会自动加载。
- 其他 Agent 接入：在各自的 MCP 配置里加同样的三项，命令为工具目录 venv/bin/python，参数为工具目录 src/server.py，环境变量见下。
- 不经 MCP 的直连方式：设置下面三个环境变量后，在 Python 里 `import DaVinciResolveScript` 并调用 `scriptapp("Resolve")`。

```sh
export RESOLVE_SCRIPT_API="/Library/Application Support/Blackmagic Design/DaVinci Resolve/Developer/Scripting"
export RESOLVE_SCRIPT_LIB="/Applications/DaVinci Resolve/DaVinci Resolve.app/Contents/Libraries/Fusion/fusionscript.so"
export PYTHONPATH="$RESOLVE_SCRIPT_API/Modules/"
```

## 使用前提

- 达芬奇必须正在运行，并且已经打开要操作的项目；停在项目管理器界面时拿不到项目。
- 达芬奇偏好设置里“外部脚本使用”保持为“本地”。
- 不开机自启，也没有常驻进程：MCP 服务由 Agent 会话按需拉起。

## 已验证的边界（2026-10-14）

- 达芬奇 Studio 21.1.1.10 上，直连方式和 MCP 服务都已连通；MCP 加载出项目、媒体池、时间线、调色、Fusion、渲染等 40 多组工具。
- 解释器用 3.14.7，属于该项目文档写明验证过的版本。最初装的是 3.15，2026-10-14 并回 3.14，与小八其余环境一致。
- 带界面模式下，切换或关闭项目时若当前项目未保存，达芬奇会弹出对话框，脚本关不掉，需要用户手动点。
- 逐帧修剪、拖动剪辑点这类精细手工剪辑动作，脚本接口基本不支持。
- 删除素材或时间线、覆盖已有文件的渲染属于不可逆操作，动手前先问用户。
- 仓库自带的 install.py 没有运行过；虚拟环境、依赖和配置是手动完成的。升级时在工具目录 `git pull` 后按 requirements.txt 重装依赖即可。
