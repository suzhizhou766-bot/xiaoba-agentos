# 恢复暂存对象需要独占命名，路径改名不能隔离打开的文件句柄

2026-10-11，第2步甲主力隔离复核事实与待审建议，修复未集成、未发布。

已核实：恢复流程把冲突用户内容留在“目标名+PID”的.rollback下，后续同进程同目标调用会用os.replace覆盖该保留对象并删除，memory与evidence两入口均复现。另一个真实进程如果事先打开文件，仍能在路径被改名认领之后，通过原文件描述符写入inode；本轮探针在认领内容读取之后放行写入，确认fsync与新字节，再继续撤销，最终新内容无路径保留且未报告冲突。

复用建议：恢复/暂存位置必须原子独占，保留过用户内容的位置不能再被后续调用复用覆盖；rename的原子性是目录项操作的原子性，不能宣传成“内容归属判断与删除原子化”。并发保证应明确覆盖路径重建、打开fd写入、同进程重复恢复的范围，逐个实测。不能由实现者把不满足用户保护要求的场景自行认定为可接受限制。

证据：工作区/小八AgentOS-架构第2步甲/reports/DeepSeek第8轮主力复核.md、reports/DeepSeek-保留文件碰撞与打开文件写入复核.json、work/recheck_deepseek_claim_safety.py。源码哈希绑定于JSON，临时夹具已删除，测试不证明线上发生过损失，也不估计概率。42项相关测试和两组原路径竞争探针通过，但不替代新场景的验证。
