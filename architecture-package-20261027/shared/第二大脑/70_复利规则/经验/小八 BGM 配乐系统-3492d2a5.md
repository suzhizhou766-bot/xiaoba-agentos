# 小八 BGM 配乐系统

把剧情、画面节奏和交付条件编译成可听见、可生成、可剪辑、可验收的音乐系统。默认先完成音乐设计与提示词；只有用户明确要求实际生成、当前交互界面可用且费用边界清楚时，才调用外部音乐服务。配乐生成平台使用用户指定的 ElevenLabs Music，具体模型、界面能力和消耗以执行时可见状态为准。BGM、SFX、旁白和对白始终分层设计。

## 选择一个主模式

- **剧情配乐**：剧本、场次、故事梗概或情绪片段 → cue card 与生成器提示词。读取 [剧情配乐](references/story_scoring.md) 和 [作曲框架](references/composition_framework.md)。
- **短视频 BGM**：产品片、广告、MV、宣传片或剪辑节奏 → 时长结构、高潮位置、落版与提示词。读取 [作曲框架](references/composition_framework.md)。
- **生成器提示词／实际生成**：按 ElevenLabs Music 当前可用的提示词、Composer 或 composition plan 输出与执行。读取 [生成器档案](references/generator_profiles.md)。
- **诊断与改写**：已有提示词或音频“太平、太弱、太满、太俗、压迫不够” → 证据、根因、重建或修补方案。读取 [作曲框架](references/composition_framework.md)；有音频文件时再读 [音频验收](references/audio_acceptance.md)。
- **SFX／混音／交付**：音效时间轴、分轨、预混、导出或文件验收。读取 [音频验收](references/audio_acceptance.md)。

混合任务选择一个主模式，其它模式只作为补充。不要为普通提示词任务加载所有参考资料。

## 音频决策卡

动手前先确认或合理推断：

- 内容类型、地域、时代、现实或超自然规则；
- 目标时长、有效主体区间、发布平台和画面节奏；
- 本段的叙事功能、人物关系、权力变化与情绪曲线；
- 对白、旁白、动作和静默的密度，以及音乐前景化或让位的位置；
- 音乐的开场、发展、高点、卸力和收尾；
- 目标生成器、交付格式、采样率、分轨和循环要求；
- 用户明确要求、已经否定的方向和允许保留的元素。

信息不足但不会改变核心方向时，做保守假设并标明。只有缺失信息会实质改变成品时才提问。

## 作曲设计闸门

提示词形容词不能直接变成乐器清单。先完成以下设计：

1. **功能**：音乐让观众或玩家感到、理解或做什么。
2. **运动**：速度、拍号、细分、重音和停顿如何对应画面与情绪。
3. **身份**：一个可辨认的短动机或节奏细胞，以及它怎样重复、回答或变形。
4. **重力**：调性中心／调式、和声稳定度、低音职责、张力与终止方式。
5. **结构**：短片按秒数规划；长 cue 按乐句与段落规划；循环音乐写明返回机制。
6. **织体**：点、线、面；主导、低音、和声、反线、节奏、色彩和留白各有职责。
7. **声源**：区分真实乐器、样本／SoundFont、MIDI、生成模型和合成近似，不虚报音色来源。
8. **空间**：距离、声场、混响、频段、动态和对白避让。

如果最初五至十秒不能建立内容身份，或静音鼓组后音乐失去全部辨识度，先重建设计卡，不靠加音量、加层数或堆形容词修补。

## 生成提示词原则

- 默认给出**一个最推荐方案**。只有用户要求多案，或不同方向确有决策价值时，才给 A／B／C；三案必须在动机、结构、和声、核心配器、高潮或空间中的至少三项不同。
- 提示词长度服从目标生成器和任务复杂度，不设置难以稳定验证的 1000—1024 字硬窗口。
- 写出可执行参数：用途、时长、BPM／体感速度、拍号、调性中心／调式、段落、动机、配器职责、动态、混音、结尾和禁用项。
- 情绪要落到机制：密度、音区、和声解决、重音、演奏压力、声场和留白，而不是重复“高级、电影感、震撼”。
- 不把调名机械等同于固定情绪；不把某件民族乐器机械等同于某种题材。
- 不模仿或点名在世艺术家、受版权保护的歌曲、旋律或编曲。把参考转译为年代、音色、节奏、和声与制作机制。
- 纯音乐明确写 `instrumental, no lead vocals, no lyrics`；只有用户要求时才允许非词义人声、吟唱或合唱音色。

## 生成器路由

- 配乐生成器固定为 ElevenLabs Music。只选择页面明确标为 Music 的实际可用模型，不依据记忆猜测版本，也不得把语音合成模型当成音乐模型。
- 有精确剪辑时间线时，优先把 cue card 编译成页面当前支持的分段 Composer／composition plan；快速试听才使用单提示词。
- 用户要求实际生成时，只在其已登录的 Chrome ElevenLabs 页面执行。遵守 Chrome 控制技能；不读取 cookies、本地存储、密码、会话文件或 API Key。
- 实际点击生成前，核对模型名称、纯音乐／人声要求、时长、结构和页面显示的消耗。一次先生成一个可评审批次，不自动循环重试或消耗额外配额。
- ElevenLabs Music 不可用时，保留已编译的音乐设计、错误类别和可继续的提示词并报告阻塞；不自动转投其它音乐平台。
- 不从浏览器登录态提取凭据，也不把 Cookie、令牌或 API Key 写入技能、记忆或项目。
- 用户明确说“生成”时，可以直接提交一个使用当前账号已有积分的生成批次。任何充值、购买、订阅或额外付费都必须在最终操作前另行询问用户。
- 当前账号未登录、积分不足、出现验证码或需要换号时，停在可恢复的页面并请用户手动处理，完成后再继续。不自动创建账号、存储凭据、轮换账号或规避平台限额。

## SFX 路由与偏好

- BGM 与 SFX 始终分开。不把可剪辑的动作音效焊死在音乐生成结果里。
- 用户只说“配乐”时，默认包含 BGM 设计、SFX 触发点和本地候选匹配；不因此自动消耗 ElevenLabs SFX 积分。用户说“生成完整配乐和音效”或明确要求生成音效时，才为本地缺口提交一个 ElevenLabs SFX 批次。
- 本地优先级：用户明确收藏 → 精选 → 同项目已采用 → 常用 → 其它语义与声学匹配。评分、使用次数、否定次数和项目亲和度只在语义相符的候选中加权，不允许精选素材跨类型插队。
- 本地候选必须通过动作、材质、时长、空间、干净度和遮挡检查。只有无合格候选、需要罕见／品牌化音色、精确 Foley 或无缝环境循环时，才使用 ElevenLabs Sound Effects。
- ElevenLabs 复合音效拆成独立 one-shot，分别生成后在时间线组合。环境底才启用 loop。下载时优先保留页面提供的原始 WAV；只有 MP3 时保留原文件，不把转 WAV 说成音质升级。
- 新生成音效先进入 `音效素材库/项目专用音效/<项目>/ElevenLabs/`，记录提示词、日期、用途、套餐／授权备注、哈希和是否采用；不记录账号身份。使用 `AI视频管线/scripts/sfx_register.py` 登记并刷新指纹与索引。
- 使用 1—2 次或评分 3/5 记为常用；使用至少 3 次或评分至少 4/5 进入精选候选。候选清单不自动移动文件；只有用户明确确认归档时才移入 `精选音效/`。

## 迭代规则

- 最新明确反馈优先。用户只改一个维度时，保留其它已确认维度。
- “换乐器”必须替换主导、铺底和色彩层的核心组合；不能只换近义音色。
- “更紧张／更轻松／更克制”必须改变产生该感受的音乐机制，而不是只增加形容词。
- 记录本轮核心动机、配器、结构、禁用项和失败原因，后续版本避免换词复现旧问题。

## 重新生成还是修补

- **重新生成／重编**：叙事功能错误、高潮过早、主体不足、动机缺失、结构机械循环、声源质量不够或尾奏拖长。
- **局部修补**：结构成立，仅有剪辑点、增益、频段、短淡化、接缝或个别音效问题。
- 禁止为凑时长机械循环、拉长尾奏或用长淡出填空白。

# 音频验收与混音

在用户提供音频文件、要求 SFX／混音、导出或判断是否可交付时读取。技术通过不等于音乐通过，三层验收必须分别报告。

## 技术层

检查：文件存在且非空、可解码、真实时长、容器／编码、采样率、声道、位深、峰值和削波。WAV 可运行：

```bash
python3 scripts/audio_qc.py file.wav [...]
```

正式剪辑交付默认 WAV PCM、48 kHz、双声道、16-bit 或更高。其它规格只有在目标平台明确要求时才视为通过。不要把网页预览、MP4 容器或损坏下载误认为音频母带。

## 结构层

按实际听感记录精确时间范围：

- 开场是否及时建立身份；
- 推进是否来自音乐变化而非只变响；
- 主体／高潮是否覆盖内容最重要区间；
- 卸力是否过早；
- 收尾是否简洁、完整并符合落版或循环需求；
- 是否存在明显机械循环、接缝、无意义尾奏或用淡出凑时长。

## 音乐层

检查动机、乐句、低音、和声、点线面、声部职责、内容辨识度和声源真实度。音乐没有身份时，即使波形和响度合格也应判为“需要重建”。

## 混音层

- BGM、SFX、旁白和对白层级清楚；
- 动作音效贴合动作，转场不过量；
- 对白频段不过度被中频旋律、铜管或密集打击遮挡；
- 低频不浑浊，高频不刺耳，立体声稳定；
- SFX 不用疼痛响度抢重要性，总轨不削波；
- 混响尾巴、动态处理和年代质感符合内容。

## SFX 时间轴

每个音效只对应动作点、转场点、信息点、空间点或品牌点之一。记录：时间、动作、素材来源、裁剪区间、增益、声像、淡入淡出、遮挡风险和验收结果。优先真实动作的短促放大，音效宁少勿多。

每个时间点先记录本地查询 profile、项目名和候选，再记录最终采用文件、评分与未采用原因。匹配分只是候选排序，不代替试听；语义或材质错误时，即使是精选也不采用。

ElevenLabs 生成素材的验收额外检查：是否干净孤立、是否意外加入人声／音乐，起音与尾音是否可剪，loop 是否无缝，授权备注是否已记录。

## 结论等级

- **PASS**：技术、结构、音乐和混音均满足用途。
- **PASS WITH FIXES**：结构成立，只需接缝、淡化、频段、增益或个别事件修补。
- **REBUILD**：叙事功能、动机、结构、声源或主体区间不成立，应重新生成或重编。
- **FAIL**：文件缺失、损坏、不可解码或技术规格无法进入目标工作流。

报告每层证据和精确问题，不把一个总分当作结论。

# BGM 技能校准用例

本文件用于维护或回归测试，不要求普通任务读取。测试关注决策是否正确，不匹配固定措辞。

## 用例一：对白密集的现实悬疑

输入：两人在狭小办公室平静交谈，其中一人逐渐意识到对方在撒谎；没有暴力动作，结尾保持怀疑。

通过条件：

- 识别为室内心理威胁而非动作或超自然恐怖；
- 中频旋律为对白让位；
- 张力来自共同音错调、空间收窄、短动机失败或不解决，而非默认低弦轰鸣；
- 结尾悬置，不加入治愈或胜利。

## 用例二：35秒产品宣传片

输入：5秒建立产品，6—26秒展示核心操作与结果，27—32秒用户反应，33—35秒品牌落版。

通过条件：

- 主体持续到32秒，不在结果展示时提前进入 outro；
- 写明前五秒识别点、主体 hook、高潮和约2秒收束；
- 不用机械循环凑满35秒；
- 给出对白／UI音效空间和干净落版。

## 用例三：民俗恐怖改稿

输入：上一版日式乐器被否定，用户要求保留压迫曲线但彻底换乐器。

通过条件：

- 保留已认可的情绪和结构；
- 主导、铺底与色彩层不复用尺八、三味线、箏等核心组合；
- 新方向有明确文化依据，或转为地域中性的实验声学体系；
- 不用近义乐器替换冒充“彻底换乐器”。

## 用例四：已有音频“太弱”

输入：用户上传一条音量不低但听感薄、没有推进的 BGM。

通过条件：

- 不把解决方案简化为提高音量；
- 检查动机、低音、乐句、点线面、音区、结构和声源；
- 给出局部修补或重建结论及证据；
- 有 WAV 时运行技术质检，但不把技术通过等同于音乐通过。

# 作曲与结构框架

在创作、改写或诊断 BGM 时读取。目标是先证明“这是音乐”，再处理音色与生成器措辞。

## Cue 设计卡

- 功能：音乐服务什么内容和行为。
- 时长：固定短片、长段落、循环或自适应。
- BPM／拍号：体感脉冲、细分与重音分组。
- 调性中心／调式：骨干音、色彩音、避免音和终止状态。
- 动机：3—8个音或一个节奏细胞；写轮廓与节奏指纹。
- 低音职责：持续音、行进、反向运动、压力脉冲、固定低音或刻意缺席。
- 和声：功能走向、调式 vamp、悬挂链、半音压力、持续音或开放终止。
- 乐句与段落：陈述、回答、变奏、对比、回归、卸力和收尾。
- 发展手法：移位、倒影、增减时值、碎片化、换音区、再和声或中断。
- 织体：点／线／面和前中后景。
- 空间：距离、宽度、混响、频段、动态与对白空间。

## 音乐成立的最低条件

1. 动机至少以可辨认形式返回一次，而不是每段重新开始。
2. 乐句形成问题与回答，或建立明确的推进与回归。
3. 和声按横向声部思考：保留共同音、挂留、预备、延迟解决或反向运动，避免所有声部同时跳动。
4. 不协和有准备、压力、色彩或解决职责，不用随机噪声冒充深度。
5. 低音承担重力或运动，不只是机械弹根音。
6. 结尾服务用途：短片要干净落版；循环要用 pickup、持续音、低音回转或未解决和声指向开头。

## 短视频结构

按内容实际时长分配，不固定套比例：

- 铺垫：尽快建立世界与观看呼吸。
- 推进：增加信息密度、运动或和声压力。
- 主体／高潮：覆盖最重要的展示、结果、动作或情绪答案。
- 卸力：给品牌、字幕或结论留空间，但不能过早变成尾奏。
- 收束：通常约1.5—2.5秒，完成 sting、短尾音或干净停止。

约30—40秒短片中，内容展示、作品完成和人物反应仍属于主体，不应被误判为 outro。

## 长 cue 与循环

- 4小节：陈述／回答／变奏／返回。
- 8小节：A／A'／B／返回或填充。
- 16小节以上：每4或8小节改变密度、音区、和声或配器职责。
- 循环音乐写清可忍受的重复时长、接缝和疲劳控制；避免完全闭合的强终止反复出现。

## 点、线、面与角色

- 点：击打、短音、断奏、stinger、稀疏色彩。
- 线：主旋律、低音线、反线、分解或 ostinato。
- 面：持续和声、弦乐颤音、合唱音色、运动中的 drone 或节奏场。

给每层一个职责：主题、反线、和声面、节奏面、低音、威胁身份、事件冲击或空气层。没有职责的层删除。噪声、风、磁带和纹理不能成为免费的“氛围层”。

## 诊断顺序

当音乐“弱、薄、平、俗、重复或不像真实配乐”时，依次检查：

1. 功能和内容身份是否正确；
2. 前五至十秒是否建立可识别动作或场景；
3. 动机、乐句、低音与和声是否成立；
4. 结构是否有变化而非静态循环；
5. 点、线、面和音区是否失衡；
6. 声源是否达到所需真实度；
7. 最后才调整增益、效果器和层数。

重建触发：功能错误、没有动机、没有乐句变化、声源路线不够、三项以上核心维度明显失败。不要用更多混响、噪声或鼓点掩盖作曲问题。

## 自检

- 不看标题，听众能否在十秒内猜到内容功能？
- 静音鼓组后是否仍有身份？
- 每件核心乐器是否写明音区、演奏法、职责和进入阶段？
- 主导声部与对白是否争夺中频？
- 高潮是否来自结构变化，而非只变响？
- 收尾是否符合落版、悬念、余震或循环需求？

# 音乐生成器提示词档案

在用户点名音乐生成平台，或需要可直接粘贴的生成提示词时读取。动态能力、价格和版本必须以现场或官方资料为准；本文件只保留稳定的提示词原则。

## 通用单提示词结构

把最重要的信息放前面，按以下顺序组织自然语言：

1. instrumental 与内容用途；
2. 主类型、子类型、地域和年代质感；
3. 时长、BPM／体感速度、拍号和整体能量曲线；
4. 调性中心／调式、动机、和声与低音职责；
5. 主导、铺底、色彩、节奏和高潮声部的演奏法；
6. 段落、转折、收尾或循环返回；
7. 声场、距离、混响、频段和制作质感；
8. 必要的禁用项。

避免超过两种互相竞争的主风格、超过两件主奏乐器、多个互相冲突的年代或空间，以及无法执行的形容词堆叠。

## ElevenLabs Music（小八唯一生成器）

小八只使用用户指定的 ElevenLabs Music 生成配乐，并且只通过用户当前已授权的交互界面执行。页面字段、模型、能力与价格可能变化，以当次可见界面和官方文档为准。模型名称不清晰时停止生成并报告，不猜测，也不把语音合成模型当成音乐模型。

- 有镜头时间线、旁白让位、精确高潮或落版点时，优先 **composition plan**；每个 chunk 对应一个 cue，写明段名、时长、正向风格、少量负向风格和与前后段的连续性。
- 快速灵感稿才用单提示词；写明总时长、用途、BPM、主乐器、能量弧线、落版和 `instrumental only`。
- 需要可靠纯音乐时，在界面中启用对应的 instrumental 设定；不只依赖提示词否定人声。
- 分段风格用作曲机制表达，例如 `sparse low-register pulse`、`rising string ostinato`、`brief impact then immediate dialogue space`；负向项只禁止会真正破坏镜头的元素。
- 一次先生成一个批次并试听。重试前判断是作曲设计错误、段落时间错误还是音色偏差，不盲目反复生成。
- 下载后保留原始生成文件，再进行 48 kHz WAV 转码、剪辑、对白避让和质检；不把转码说成音质升级。

- Composition plans：https://elevenlabs.io/docs/eleven-api/guides/how-to/music/composition-plans
- 生成提示词建议：https://elevenlabs.io/docs/overview/capabilities/music/best-practices

## 两栏或结构化平台

若平台把 Style、Lyrics、Arrangement、Key、BPM 或 Exclude 分成多个字段，按页面当前结构拆分，不把所有内容塞入一栏：

- 纯音乐模式：Lyrics 留空；结构提示放 Arrangement 或平台允许的结构区。
- Style：类型、年代、情绪机制、核心乐器和制作质感。
- Arrangement：段落、能量、动机、转折与结尾。
- Key／BPM：仅在平台支持独立字段时单独提供。
- Exclude／Negative：只放会真实破坏方向的少量禁用项。

## 多方案

默认一个最强方案。只有需要比较时输出多案，并改变音乐机制而不是换同义词：

- A：最贴合内容和生成稳定性；
- B：强化人物主观、地域或类型身份；
- C：极简、反向动态或实验声源。

评分衡量与当前内容的适配，不代表音乐高低。不要把三案都评成满分。

## 版权与真实性

- 不要求复刻在世艺术家、受保护作品、旋律、bassline 或编曲。
- 用户提供参考时，提取抽象机制：速度、节奏语法、和声压力、音色职责、段落、空间和年代制作。
- 合成器或程序音色写成 `string-like`、`choir-like` 等近似；只有真实样本、SoundFont、录音或可信渲染器才能直接称为真实乐器演奏。

# 剧情配乐编译

在用户提供剧本、剧情片段、故事梗概或场次文本时读取。目标不是复述剧情，而是找出音乐在这一段为什么存在。

## 剧情到音乐的转换

先识别：

1. 叙事功能：建立关系、暗示危险、推动行动、进入主观心理、承接余震或留下悬念。
2. 情绪曲线：起点、首次变化、累积方式、核心转折、峰值类型和结尾状态。
3. 权力变化：谁控制节奏，何处失去控制，何处需要抽空音乐。
4. 对白与动作：对白密集处减少中频旋律与强重音；动作和静默处才允许音乐前景化。
5. 规模：极简、室内、小编制、群像、大编制或混合电子。

同一种标签要拆成具体机制。“恐惧”可能来自现实暴力、心理怀疑、民俗禁忌、身体失控、不可见威胁或巨大尺度；“悲伤”可能是麻木、悔恨、尊严、思念或崩溃。不同机制不能共享同一套低弦与轰鸣。

文本中若包含音乐功能完全不同、无法由同一条动态曲线承载的独立段落，按戏剧连续性拆成多个 cue。不要强迫一个提示词覆盖互相矛盾的段落。

## 调性与节奏

- 绝对调名不等于固定情绪。情绪由调式、音程、和声稳定度、速度、重音、音区、音色、织体和文化语境共同决定。
- 写明中心音与调式；传统调式不确定时，给出实际音集、骨干音和装饰规则，不编造名称。
- 调性变化要写方法与戏剧功能：共同音／共同和弦、平行大小调、同主音调式转换、三度或半音关系、持续低音叠置、调性侵蚀、无调性化与重新定调。
- 快不必然快乐，慢不必然悲伤。缺拍、提前重音、延迟落点、不同周期叠加和留白都能改变心理压力。

三分钟以上 cue 使用开场、发展、高点、收尾的全局弧线；短视频按真实秒数设计，但不要逐秒堆满事件。

## 地域与乐器边界

地域风格来自真实乐器体系、音阶、演奏法、节奏和录音空间，不来自片名或刻板印象。

- **中国**：二胡／板胡／京胡、琵琶／古筝／古琴／阮／扬琴、笛／箫／笙／唢呐等要按构造与地方语境区分。扬琴是击弦，古筝与日本箏不可互换。
- **日本**：三味线、日本琵琶、箏、尺八、篳篥、龍笛、能管、笙及各类太鼓属于不同合奏传统。雅乐、能乐、歌舞伎、民谣和现代恐怖不是同一语法。
- **韩国**：伽倻琴、玄鹤琴、牙筝、奚琴、大笒、觱篥、杖鼓等需结合正乐、散调、农乐或巫俗语境；奚琴不能写成二胡替代品。
- **西洋与电子**：弦、木管、铜管、打击、键盘、模块合成、颗粒、磁带和卷积空间都要说明音区、演奏／控制动作与结构职责。
- **稀有或实验声源**：写“名称＋构造／动作＋可听结果”，并给模型熟悉的替代组合。无法核实的器名不要当成事实。

## 类型提示

- 青春／友情：用呼吸、停顿、轻型节奏与可记忆动机决定明亮、腼腆、躁动或遗憾，不能自动等于甜美钢琴。
- 爱情／家庭：用独奏、二重奏、声部距离、错位或抽空体现关系，不无条件煽情。
- 悬疑／犯罪：现实威胁偏近、干、硬；心理威胁偏音高漂移、空间矛盾和不解决。
- 恐怖／怪谈：先判断文化与威胁来源，再选择音集、反常演奏、微分音、拍频、留白与空间。
- 动作／追逐：区分潜行、逃亡、搏斗、失控和胜负余震；节奏跟随力量变化，不默认史诗铜管。
- 悲剧／创伤：区分克制、麻木、悔恨、尊严和崩溃；高潮可以抽空而非全编制爆发。
- 喜剧／荒诞：幽默来自精确停顿、节拍错位与音色反差，不靠廉价卡通音效。

## 剧情提示词禁区

生成提示词正文只写音乐，不塞入人物姓名、对白、摄影机、镜头复述或现实音效。剧情节点应被翻译为和声、节奏、配器、动态、空间或静默变化。

#!/usr/bin/env python3
"""Inspect PCM WAV delivery properties, peak level, and full-scale clipping."""

import json
import math
import struct
import sys
from pathlib import Path

WAVE_FORMAT_PCM = 0x0001
WAVE_FORMAT_EXTENSIBLE = 0xFFFE
# KSDATAFORMAT_SUBTYPE_* GUIDs share this tail after the 2-byte format code
# and two zero bytes (00000000-0010-0080-00AA-00389B71 in little-endian form).
_SUBFORMAT_TAIL = b"\x00\x00\x00\x00\x10\x00\x80\x00\x00\xaa\x00\x38\x9b\x71"


class WavError(Exception):
    pass


class _WavReader:
    """Minimal RIFF/WAVE reader: fmt chunk (incl. WAVE_FORMAT_EXTENSIBLE) and data."""

    def __init__(self, handle):
        self._handle = handle
        self._handle.seek(0, 2)
        file_size = self._handle.tell()
        self._handle.seek(0)
        header = self._handle.read(12)
        if len(header) < 12 or header[:4] != b"RIFF" or header[8:12] != b"WAVE":
            raise WavError("file does not start with RIFF/WAVE header")
        fmt = None
        self._data_start = None
        self._data_size = 0
        while True:
            chunk = self._handle.read(8)
            if len(chunk) < 8:
                break
            name, size = chunk[:4], struct.unpack("<I", chunk[4:])[0]
            start = self._handle.tell()
            if name == b"fmt ":
                fmt = self._handle.read(size)
            elif name == b"data":
                self._data_start = start
                # Streamed writers may leave 0 or 0xFFFFFFFF here; trust the file.
                remaining = file_size - start
                self._data_size = remaining if size == 0 or size > remaining else size
                if fmt is not None:
                    break
            self._handle.seek(start + size + (size & 1))
        if fmt is None:
            raise WavError("fmt chunk not found")
        if self._data_start is None:
            raise WavError("data chunk not found")
        if len(fmt) < 16:
            raise WavError("fmt chunk too short")
        tag, channels, rate, _, block_align, bits = struct.unpack("<HHIIHH", fmt[:16])
        if tag == WAVE_FORMAT_EXTENSIBLE:
            if len(fmt) < 40:
                raise WavError("WAVE_FORMAT_EXTENSIBLE fmt chunk too short")
            subformat = fmt[24:40]
            if subformat[2:] != _SUBFORMAT_TAIL:
                raise WavError("unknown WAVE_FORMAT_EXTENSIBLE subformat")
            tag = struct.unpack("<H", subformat[:2])[0]
        if channels == 0 or block_align == 0 or block_align % channels:
            raise WavError(f"invalid block_align={block_align} channels={channels}")
        self.format_tag = tag
        self.channels = channels
        self.rate = rate
        self.bits = bits
        self.width = block_align // channels
        self.block_align = block_align
        self.frames = self._data_size // block_align
        self._left = self.frames * block_align
        self._handle.seek(self._data_start)

    def readframes(self, count):
        size = min(count * self.block_align, self._left)
        raw = self._handle.read(size)
        self._left -= len(raw)
        return raw


def _samples(raw, width):
    if width == 1:
        for value in raw:
            yield value - 128
        return
    for offset in range(0, len(raw) - width + 1, width):
        chunk = raw[offset : offset + width]
        yield int.from_bytes(chunk, byteorder="little", signed=True)


def inspect(path):
    file = Path(path)
    if not file.is_file() or file.stat().st_size == 0:
        return {"path": str(file), "status": "FAIL", "reason": "missing or empty"}

    try:
        with open(file, "rb") as handle:
            audio = _WavReader(handle)
            frames = audio.frames
            rate = audio.rate
            channels = audio.channels
            width = audio.width
            compression = (
                "NONE"
                if audio.format_tag == WAVE_FORMAT_PCM
                else f"format_tag={audio.format_tag}"
            )
            duration = frames / rate if rate else 0
            issues = []

            if compression != "NONE":
                issues.append(f"compression={compression}")
            if rate != 48000:
                issues.append(f"sample_rate={rate}")
            if channels != 2:
                issues.append(f"channels={channels}")
            if audio.bits < 16:
                issues.append(f"bit_depth={audio.bits}")
            if width not in (1, 2, 3, 4):
                issues.append(f"unsupported_sample_width={width}")
            if duration <= 0:
                issues.append("duration<=0")

            peak = 0
            clipped = 0
            sample_count = 0
            if compression == "NONE" and width in (1, 2, 3, 4):
                full_scale = (1 << (width * 8 - 1)) - 1
                while True:
                    raw = audio.readframes(8192)
                    if not raw:
                        break
                    for sample in _samples(raw, width):
                        magnitude = abs(sample)
                        peak = max(peak, magnitude)
                        clipped += magnitude >= full_scale
                        sample_count += 1
                if clipped:
                    issues.append(f"full_scale_samples={clipped}")
                peak_dbfs = (
                    round(20 * math.log10(peak / full_scale), 3)
                    if peak and full_scale
                    else None
                )
            else:
                peak_dbfs = None

            return {
                "path": str(file),
                "status": "PASS" if not issues else "WARN",
                "duration": round(duration, 3),
                "sample_rate": rate,
                "channels": channels,
                "bit_depth": audio.bits,
                "compression": compression,
                "peak_dbfs": peak_dbfs,
                "full_scale_samples": clipped,
                "sample_count": sample_count,
                "issues": issues,
            }
    except (WavError, struct.error, EOFError, OSError) as error:

    def test_extensible_24bit_stereo_passes(self):

        self.assertTrue(result["reason"].startswith("decode: "))
