# 恢复与盘点必须验证写入归属、提交状态和对象身份

日期：2026-10-11。来源：第 2 步甲最新外部返修的主力隔离复核。仅登记复核事实和待审核建议，修复尚未集成、尚未发布，不能视为用户采用。

## 已核实事实

DeepSeek 的 31 项相关回归与上一轮三个恢复探针均通过，但独立进程在发布窗口写入的图文件、目录追加行和笔记内容仍被恢复代码撤销。发布锁不能约束不参与该锁的用户编辑器。另一个故障注入确认，扣留释放在真实提交后遇到维护异常与读回失败，CLI 仍恢复旧证据，造成数据库与文件哈希不同。

Gemini 的 13 项盘点测试通过，但共享目录存在同名对象时，另一私有物理技能在扫描入口被遗漏；内部越界软链直接访问被拒，而通过子目录别名或折叠链被登记为合法外部声明。

## 待审核的复用建议

1. 回滚必须证明本次写入归属；持锁期间发生变化、与原字节不同，都不足以证明。无法安全恢复时保留其他写入者的新内容并明确人工核对。
2. 提交状态区分已提交、明确未提交、未知；读回失败时禁止按未提交执行破坏性恢复。逐个入口验证，不能只测共用发布函数。
3. 盘点去重和排除以真实对象身份与明确范围为准；后置精确匹配救不了扫描入口的同名过滤。软链边界要检查实际展开链路。
4. 通过测试数量与探针退出码都不等于验收通过。诊断脚本可以成功执行并观察到失败，必须读取观测字段，绑定源码哈希。

## 证据与限制

工作区/小八AgentOS-架构第2步甲/reports/接续复核-写入归属与路径身份.md；DeepSeek-并发归属与未知提交复核.json；DeepSeek-失败恢复独立复核.json；Gemini-外部同名与子目录别名复核.json。可重复执行的脚本保存在同工作区 work/。

所有复现都在临时文件和临时 SQLite 中进行，被测实现源码未改，临时夹具已清理。没有据此断言线上已经发生同样的数据损失，没有执行正式切换，没有后台独立验收通过结论。修复交由原实现方通过任务卡继续，主力待回执后复核。
