# 经验发布要保留可检索标题，并在代码层执行备份授权

来源：2026-10-10 用户要求核查两条已审批经验的遗留问题，再要求修复并纳入 v1.5.2 清单。宿主 Codex 核查实际数据库、已发布笔记、索引和发布代码。

问题一：宿主创建候选时提供的标题只保存在任务记录，没有进入候选文件。正文无一级标题时发布回退为“经验”，虽然两阶段审批、发布和结构索引校验都成功，用原题和“工作搬家 版本号”仍找不到目标。

问题二：提示词和运行宪法已有“没有明确备份要求不得新建备份”，经验发布代码却无条件复制目录备份，索引更新也复制旧索引用于回滚。文本规则存在不能证明执行程序遵守它。

做法：
1. 把用于发布和检索的显式标题写进候选文件，纳入两阶段审批的同一哈希；只改标题也必须重新审核。发布保留原题，验收同时检查文件、索引与原题/关键词找回。
2. 授权边界必须落实到实际执行代码。普通审批和发布不应触发备份；失败回滚优先保留内存中的原文和索引字节，不落盘复制旧数据。已有备份不自动删除或覆盖。
3. 区分线上笔记修正、代码候选、离线测试、独立审核与正式发布，报告每一项的实际状态。

本轮验证：线上搬家经验只改生成的标题、文件名、数据库路径和父笔记链接，原审批稿及哈希不变；原题和关键词查询都命中，索引及生命周期复验通过。v1.5.2 两项程序修复已在候选实现，全部 440 项离线测试通过，包含 5 项新增回归，覆盖标题漂移、无自动备份、已有备份保留和失败回滚。

未完成门槛：v1.5.2 完整范围尚未定稿，未进行本版 AGY/DSH 独立审核、构包和正式发布。活动程序仍为 v1.5.1，其自动备份行为尚未改变；不能把离线测试通过说成线上程序已修复。该经验本身仍需用户两阶段裁决。
