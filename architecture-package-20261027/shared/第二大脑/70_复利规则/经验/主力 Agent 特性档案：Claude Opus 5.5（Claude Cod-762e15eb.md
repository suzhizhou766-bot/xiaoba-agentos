# 主力 Agent 特性档案：Claude Opus 5.5（Claude Code 桌面端）

用途：其他 Agent 遇到自己干不了的活时，对照本档案判断是否该转给主力 Agent。配套阅读《大工程拆分与按模型特性派工》（ecfaa454-8860-4acb-b054-6a437eea1251）和《辅助模型实测评分记录（2026-10-07）》（候选 529a540e-137a-4e12-8967-472905c767fd）。

本档案由 Claude Opus 5.5 自己撰写。自述不等于评分：下面每一条都标了依据类型，没有依据的写在"未验证"里。本机没有对 Opus 5.5 跑过那套评分题。

## 什么活该转给它

| 情况 | 是否转交 | 依据 |
|---|---|---|
| 报错原因不明，需要翻本机日志、配置、网络状态来定位 | 转 | 本次会话实测，见"实测记录"第 1 条 |
| 需要出题、跑测试、写判分脚本来核实别的模型的产出 | 转 | 实测记录第 2 条 |
| 跨多个文件须保持一致、需要整体理解和设计取舍 | 转 | 派工规则第 2 条既定分工；公开资料 |
| 涉及小八AgentOS 候选目录、验收、发布流程的改动 | 转 | 它持有该流程的跨会话记忆，并走过 v1.4.10 的发布 |
| 需要同时用到命令行、文件编辑、浏览器、联网检索的任务 | 转 | 桌面端自带这些工具，本次会话都用过 |
| 小而边界清楚、可机器验收的编码或提取任务 | 不必转 | 辅助模型实测已能满分完成，转给它是浪费 |
| 需要输入密码、密钥、支付信息，或创建账号 | 转了也做不了 | 它的安全规则禁止，须用户本人操作 |

## 长处

- **用证据定位问题。** 实测：先读日志拿到真实报错，再逐项排除，而不是凭印象下结论。
- **工具齐全。** 在 Claude Code 桌面端可运行命令、读写文件、操作内置浏览器、联网检索、派生子 Agent。
- **上下文大。** 公开资料称 100 万 token 上下文、单次最多 12.8 万 token 输出。本机未验证上限。
- **编码能力。** 公开资料称 SWE-bench Pro 89.9%、Terminal-Bench 4.0 66.4%，均为 Anthropic 自报，多在最高推理档下测得，本机未复现。
- **有跨会话记忆。** 记忆存在 `~/.claude/projects/-Users-suzhizhou-Documents/memory/`，记录了用户的工作方式、AgentOS 变更流程和交付约定。

## 短处与限制

- **AgentOS 后台调不到它。** 目前只启用了 `agy_review` 和 `dsh_review` 两个后台；本机 PATH 上也没有 `claude` 命令。其他 Agent 无法直接调用，只能由用户在 Claude Code 桌面端转交。
- **贵。** 公开价格为每百万 token 输入 4 美元、输出 20 美元，是这批模型里最贵的。小活不要派给它。
- **会话之间不自动记事。** 只有写进记忆文件或第二大脑的内容能带到下一次会话。
- **会出错，需要核实。** 本次会话里它自己出过三处错，见"实测记录"第 3 条。
- **有不做的事。** 不输入密码和密钥、不创建账号、不执行转账交易、不改系统安全设置、不绕过验证码；发消息、提交表单、发布内容、下载文件之前要用户在对话里明确同意。
- **知识截止 2026 年 6 月。** 之后的事要靠联网检索，检索结果它会标注来源。
- **评测别的 Claude 模型时不是中立方。** 辅助模型评分记录里 Claude Sonnet 4.6 的分数由它判出，判分依据是脚本和标准答案，可复算，但读者应知道这一点。

## 实测记录（2026-10-07，本次会话）

1. **定位 Antigravity 报错。** 用户截图只有 `Agent execution terminated due to error` 和一个错误 ID。它在 `~/Library/Logs/Antigravity/language_server.log` 里按 ID 找到真实原因 `User location is not supported`，再核查 FlClash 的节点、分流规则、出口 IP 和 IPv6 泄漏，把范围缩小到"当前节点 IP 被判为不支持地区或账号地区限制"。用户换到日本节点后恢复正常。
2. **组织模型评测。** 出了两轮共 16 道题，写了出题、运行、判分脚本和隐藏测试，用自己的参考实现先验证了标准答案，再跑 3 个模型共 64 次调用并判分。
3. **它自己出的错。**
   - 第一次推断"Google 流量被分到香港节点"是错的，核查配置后自己推翻。
   - 判分脚本把注释里的 float 一词当成违规，误扣了 Claude Sonnet 4.6 一项，人工核对后改正。
   - 第二轮评测把 Antigravity 里 Claude 与 GPT-OSS 的额度跑光，事先只说了"会多消耗一些额度"，没有预估到会耗尽。

## 怎么把活转给它

1. 由用户在 Claude Code 桌面端发起会话，把任务贴给它。
2. 任务说明里写清：目标、涉及的目录、已经试过什么、失败时的报错原文或日志位置、验收标准。
3. 涉及小八AgentOS 源码的改动，它会按候选目录、双后台验收、发布脚本的流程走，提升和重启 Worker 前会等用户明确同意。
