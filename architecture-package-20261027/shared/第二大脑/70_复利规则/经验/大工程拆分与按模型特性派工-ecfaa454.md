# 大工程拆分与按模型特性派工

## 规则

1. **主动拆分。** 主力 Agent 判断一项工作明显超出单次会话能稳妥完成的量时，不等用户提醒，先拆分再动手，并向用户说明：拆成哪几块、每块由谁做及理由、先后顺序与依赖。
2. **按任务内容与辅助模型特性的匹配度分工。** 逐块对照三个辅助模型有依据的长处和短处，匹配的派给最合适的那个模型；三个辅助模型都无法胜任的工作，由主力 Agent 完成。
3. **先弄清模型特性再派工。** 对辅助模型的能力判断必须有出处：第二大脑里的评分记录优先，其次是带来源的公开资料，并标明是哪一种。没有依据的写“未知”，先派小而可验证的任务取得实测，不凭印象安排。
4. **外派以任务卡交付，由用户转交。** 每个模型的任务在对话里用一个可一键复制的文本块给出，简洁明了，不写成长文档。每张卡自成一体，包含：目标、允许修改的文件、具体步骤、验收命令与预期结果、停止条件、固定格式的完成报告。任务卡不含凭据，不含需要登录的操作。
5. **一个文件同一时间只归一方。** 派单时声明各方正在改的文件，互不触碰。
6. **主力 Agent 核实后才算完成。** 辅助模型交回的完成报告只是线索；主力 Agent 必须自己重跑验收、检查改动，核实通过后才能合并和报告完成。核实不过由主力 Agent 修正或重派。
7. **核实后评分并记入第二大脑。** 每项外派任务核实结束后，主力 Agent 给出评分并经第二大脑规定的写入入口记录。每条记录包含：模型、任务类型与规模、是否一次通过、出了什么问题、评分（1–5 分）及理由、证据位置。评分依据是核实结果，不是完成报告的自述。
8. **用累积的评分改进分工。** 派工前先查该模型在同类任务上的历史评分；随着任务数量增加，逐步细化每个辅助模型适配的工作内容，让任务完成得更高效。

## 适用范围

主力 Agent 主导、辅助模型协助的编码、文档与资料整理类工作。不替代 AgentOS 的双后台验收与发布门禁。当前辅助模型：DeepSeek V4.1 Flash、Qwen 3.8 Flash、Gemini 3.8 Flash；更换模型时规则不变，只更新评分记录。

## 来源与依据

用户（苏之舟）2026-10-06 在小八 3D 导演台优化工作中的指示，原话：

- “工程量大的话，可以分配出来一些工作交给 DeepSeek v4.1 flash 模型去做，你把工作内容发给我，我发给 DeepSeek harness 去做。”
- “分出来的工作要符合 DeepSeek v4.1 flash 模型特性，擅长什么不擅长什么，这你都要明白后，再安排工作。”
- “遇到工程量大的工作，就主动拆分工作内容，然后阐明哪些工作适合哪些模型去做。”
- “还有一个 gemini 3.8 flash 模型，这三个辅助工作模型。”
- “生成工作分配清单的时候直接给我简洁明了的可以直接点复制的方式给我。”
- “判断依据缩小一点，根据任务内容与三个辅助模型的特性匹配度进行分工，这三个辅助模型都无法胜任的工作内容都由主力 Agent 完成。”
- “还可以加一条验收，根据辅助模型完成工作后提交的完成报告核实后由主力 Agent 进行评分并记录进第二大脑，这样的话，随着任务完成数量的叠加，能够更加详细的了解到各个辅助模型所适配的工作内容，从而让任务更加高效的完成。”

规则正文由主力 Agent（Claude Code）按上述指示整理，用户当日审阅后确认提交。

## 提交时的证据状态（如实说明）

- 这是用户确立的工作方式，不是从多次实践中归纳出的经验。提交时第一批外派任务（小八 3D 导演台，4 张任务卡，派给 DeepSeek V4.1 Flash）已发出，尚无完成报告，因此还没有任何评分记录。
