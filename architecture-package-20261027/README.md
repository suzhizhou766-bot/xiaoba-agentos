## 三种状态须分别理解

- `implementation/active-v1.6.4/`：本机当前不可变发布目录中的源码材料。原有 RELEASE 文件的历史测试结论只代表原发布时证据；本次上传未重跑这些测试、未切换生产。
- `implementation/candidate-v1.6.5/`：当前候选源码、脚本、文档和测试。候选仍未完成正式集成、打包与生产切换；不能据目录名宣称已经上线。
- `design/`：最新架构与设计上下文。初审待验证索引、交付回流增补和双审模块无绑定契约是最新设计要求，尚未据此改造运行代码。

## 两项最新设计裁决

1. 初审通过的经验进入独立“待验证”索引。后续相似真实任务可检索并应用；用户对本次成品说“交付”即视为验收。按既有交付流程收齐证据，把验证评分和应用记录附回原经验，自动进入人工终审；Agent 或脚本不能替用户终审。新的经验仍须先初审。检索、技术通过、模型自评均不等于用户采用。
2. 双审协作模块不持有固定后台名、模型值、默认组合或主备绑定。外部已准入插件池与每次任务的审查计划选择参与方和策略。执行贡献者与独立审查者可以不同；保留身份、计划版本、证据与裁决审计。旧文档和现有源码中的 AGY/DSH 固定关系属于历史实现，不覆盖最新无绑定设计。

## 源码组织

`shared/` 保留私人助理内相关模块的相对结构：技能、模块注册与接口、治理源码、Playbook、第二大脑文档、监看与裁决页面、工具入口、媒体工作流集成和审美方法。第三方工具源码保留其原有许可证；学习安装的项目仍只是学习材料，不据此升级为正式能力或已验收实现。

这是源码材料包。操作系统解释器、虚拟环境、已安装依赖、缓存与本机登录状态不在包内；依赖声明和锁文件保留。源码中的 macOS 路径、端口和本机程序依赖是原始部署事实，云端应先设计适配边界，再另行获得部署授权。

按用户要求排除音效/BGM 素材库、项目大视频、导出成片、大型图片/字体/模型和归档包；同时排除实际认证材料、运行配置与数据库、日志和重复审查运行目录。小型 UI 资源及源码、规则、文档保留。排除项详见清单。本次未修改本机生产源文件、认证、路由、模型或开关。

云端接续位置为现有对话“检查仓库中的小八1.6.1”（`01a178f5-05ed-71ee-8c05-dadcfe7be03b`）。本目录提供原始文件和哈希，用于云端获取与核对；是否保存成功，以云端实际文件的核对回执为准。
