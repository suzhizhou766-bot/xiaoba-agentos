# 在 Codex Cloud 接续

先读本目录 README，再完整阅读 `design/cloud-design-handoff/` 内五项设计材料；需要核实历史事实时查看 `shared/第二大脑/` 原文和两个 implementation 目录。

当前目标是继续设计小八 AgentOS，而不是直接发布或更改生产。优先完成：

1. 把整体架构中的模块、接口、数据所有权、状态机、索引边界与审计事件展开成可实现规格。
2. 设计待验证索引与已发布经验索引的隔离、检索条件、应用记录、交付事件关联、验证评分来源、原候选回流和人工终审入口。
3. 为双审模块定义 Agent 中立的插件准入契约、单次审查计划、独立性约束、失败恢复与审计格式；模块不能持有固定后台/模型/主备值。
4. 对照 v1.6.5 候选提出迁移步骤、兼容边界与验收证据，并逐项标明“已实现 / 待实现 / 待用户裁决”。

“用户说交付”的作用是确认当前成品验收，并触发已规定的交付记录与验证回流；它不授权 Agent 代替用户批准经验初审/终审、改生产认证路由、进行正式发版或把所有新经验直接发布。

本机部署路径在云端不可直接沿用；素材、数据库及认证材料已排除，不能据此宣称端到端运行通过。设计遇到资料缺口时列明缺口，先推进不依赖缺口的部分。
