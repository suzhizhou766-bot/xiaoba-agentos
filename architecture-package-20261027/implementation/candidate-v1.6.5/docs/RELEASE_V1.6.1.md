# v1.6.1 发布说明

日期：2026-10-13。基于 v1.6.0。数据库结构版本仍为 7。

## 这一版做了什么

技能和价值文件索引搬出发布包。

| 内容 | 现在的位置 | 怎么改 |
|---|---|---|
| 技能（各技能目录、`catalog.json`、`index.json`） | `私人助理/skills/` | 草稿 → 审查 → `xiaoba skill-publish`。不发版 |
| 价值文件索引（`catalog.json`、`index.json`） | `私人助理/系统/价值文件索引/` | 改原文或目录 → `xiaoba knowledge-index-rebuild`。不发版，不过后台 |

运行包不再含 `skills/` 与 `knowledge/` 两个目录；两份索引不再写软件版本号。

## 改一个技能：草稿、审查、发布

正式位置的技能不就地改。就地改了，索引里的哈希对不上，技能自检不通过，系统会拒绝接任务。

```sh
cp -R 私人助理/skills/<技能名> /某处/草稿/<技能名>          # 草稿目录，放在正式技能目录之外，在这里改
xiaoba skill-review-prompt <技能名> --draft /某处/草稿/<技能名> > /tmp/review.txt
xiaoba submit "$(cat /tmp/review.txt)"                      # 提交给两个后台，记下任务编号
xiaoba skill-publish <技能名> --draft /某处/草稿/<技能名> --review-task <任务编号>
```

- 审查说明由工具从草稿生成：开头是每个文件的哈希和技能条目摘要，后面是每个文件的全文。同一份草稿，生成结果逐字节确定。
- 发布时核对三样：任务已完成；启用的两个后台各自给出唯一一行通过结论；任务里存的说明与工具对当前草稿重新生成的说明逐字节相同。审查之后草稿又动过、说明是手写的、拿别的技能的任务来用，都对不上，拒绝，什么都不改。
- 核对通过后把草稿装到正式位置（草稿里没有的旧文件被移除），更新技能目录和索引，把任务编号记进该技能的索引条目，再同步第二大脑里的技能卡。
- 新增技能或要改触发词、说明等条目内容时，用 `--entry <条目.json>` 给出条目；条目也在审查说明里。
- 从目录里移除技能，这一版没有提供命令。

## 改价值文件

改原文或 `catalog.json` 后运行 `xiaoba knowledge-index-rebuild`。不过后台。

## 手改索引为什么没用

索引在包外，谁都能改。运行时除了比对文件哈希，还核对每个技能的来历，必须满足其一：

- 内容与随包基线 `config/content_baseline.json` 里该技能自己的那一组指纹逐行完全相同。基线是技能出包那一刻、已随历次发布审过的内容，受发布绑定保护。
- 索引条目里记着审查任务，且用磁盘上当前的文件重新生成的审查说明，与数据库里那条任务存的说明逐字节相同，两个后台各自通过。

都不满足的技能，自检不通过，不使用。带发布清单的运行目录里如果缺了基线文件，同样按不通过处理。`scripts/create_skill_index.py` 只保留校验，不能写索引。

## 切换时发生什么

- 技能和价值文件索引在切换之前已经放到新位置（内容操作，不影响旧版本运行）。
- 切换用三条带编号的配置步骤把 `skills.root_dir`、`skills.index_path`、`knowledge.index_path` 指过去。切换脚本只接受这三个字段，值只能是助理目录下的固定位置；新位置没有内容就拒绝切换。
- 运行目录里原来的技能与索引文件被移除，失败时原样放回；成功后清掉留下的空目录。
- 受管目录清单不变：运行目录里若再出现 `skills/` 或 `knowledge/` 下的文件，发布校验会报不一致。

## 随之变化的保证

- 协作技能里必须带有与后台一致的用户规则原文，这一条原先由包内测试断言。技能出包后，包内测试不再读它；改为在生成技能索引时机械核对，缺了这段原文就拒绝生成索引。
- 审美技能的“共享实体与发布副本一致”校验仍在，但两处现在是同一个文件。相关代码与测试下次再收。
