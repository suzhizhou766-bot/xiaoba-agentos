# v1.5.2 候选：经验标题与无备份发布

核对时间：2026-10-10 17:47（+0800）。本文件只说明 2026-10-10 用户指定的两项修复（P01、P02），不代表 v1.5.2 全部范围已完成或已发布。当前活动程序仍是 v1.5.1，这两项修复只存在于 `candidate/` 源码里。

## 候选标题（P01，已实现）

此前 `memory-candidate-create --title` 把标题放在任务记录中，却没有写入候选文件。正文没有一级标题时，发布只能回退为「经验」，文件名和检索都失去关键字。

创建宿主编写的候选时，将显式标题写入候选 frontmatter 的 `title`（JSON 字符串）。发布在正文没有有效一级标题时读取此字段；原有自带标题的正文和自动任务候选保持其标题识别顺序。标题随候选文件参与审批哈希，不能在初审之后偷偷换题。发布正文和文件名沿用同一标题。

标题识别的三层顺序（围栏外一级标题 → 审批哈希覆盖的候选 `title` → 「任务」节 → 兜底「经验」）由后续 P06/P10 专卡在同一个 `memory.py` 里改写，属于另一项范围，不在本文声明的两项之内。

## 经验发布不自动备份（P02，已实现）

删除发布时无条件创建 `backups/memory-publication/<任务编号>/experience-catalog.md` 的步骤。目录索引原文已经在内存中，失败时用它原位恢复；已有备份不删除、不覆盖。

索引更新也不再把旧索引复制到临时 `previous-graph` 目录，旧字节和权限保留在内存中；最终索引校验失败时恢复原字节和权限，并删除本次新增的索引文件。构建新索引仍使用临时工作文件，它们是新输出，不是旧数据副本。

自动备份不存在默认开启的配置项。用户单独明确要求备份时应作为独立操作执行；一般修复、审批和发布授权不会触发备份。
