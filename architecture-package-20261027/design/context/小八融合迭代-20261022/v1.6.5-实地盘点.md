# v1.6.5 实地盘点（2026-10-23，Claude Code）

起因：线上 v1.6.4 的 AGY 从 Antigravity 桌面界面读模型，Antigravity 升到 2.25.0 后读不出（实测见第 1 节），worker 因此拒绝所有双后台任务。用户在决策卡上选了“AGY 改用 CLI 上次选定的模型，进 v1.6.5 发版”。

本轮只做发版流程的第一步：只读盘点。没改 AgentOS 源码，没动候选、provider 和模型配置，没发版，也没读任何 CLI 设置文件的内容。

## 1. 线上为什么停了（实测）

- worker（pid 1519）一直活着，但每次轮询都返回 `blocked_configuration`。日志 `小八AgentOS/.runtime/logs/worker.out.log` 里连续 51 条相同错误：`agy_review: Antigravity 桌面模型读取失败…读不到 Antigravity 界面里的模型选择`。DSH 正常。
- 门禁位置：v1.6.4 `orchestrator.py` 的 `run_once` 调 `local_cli_readiness`，它再经 `gateway.py` 的 `_read_agy_desktop` 调用 `scripts/agy_desktop_route.cjs`。这个脚本通过 DevTools 调试端口，在页面的 React 树里找同时带有 `userStatusProvider` 和 `modelPreferencesProvider` 的节点，从中读取 `lastSelectedAgentModel`。
- 2026-10-23 16:52 只读诊断：调试端口通，只有 1 个页面，React 树能读到（1787 个节点），但上面两个 provider 的数量都是 0。说明 2.25.0 改了内部结构，用户在界面上怎么操作都修不好。
- 影响范围：所有双后台任务，包括这次排队的 7 个技能审查任务（还是 pending，没失败、没过期）。日常单 Agent 任务不受影响。
- Qoder：v1.6.4 里还没有 qoder_review，所以不存在 Qoder 读桌面的问题。

## 5. 风险

1. **鸡生蛋**：线上 AGY 坏了，可是发版审查本身也要双后台。好在验收现场跑的是候选代码，AGY 走 CLI 设置，应该不受影响。这要靠续审前的健康探针确认，没测过就不能这么断言。
2. **候选一改就全部重审**：往第 37 轮再并入任何一条（哪怕只是 B20 文案或 shebang），都要冻结第 38 轮，126 份以上的题面全部重跑。按以往节奏，一轮要大半天到一天，期间线上双后台一直不能用。
3. **Qoder 备用的额度**：10-21 健康记录里 Qoder 因“当日额度用尽”失败过。AGY 和 DSH 任一方中途故障时可能补不上，导致一轮作废（第 25、26 轮都是这样停的）。
4. **排队任务的兼容性**：线上数据库里 7 个技能审查任务带的是 v1.6.4 的执行快照（`local_agy` 是旧写法）。切换到 v1.6.5 后它们能不能直接跑，没验证过；最坏情况是作废重提（重提成本很低）。
5. **偏好表自相矛盾**：`Playbook/偏好/README.md` 第 61 行“三 Agent 共用等待与备用规则”里还写着“三者均跟随各自桌面”，和第 7 行（10-20 最终定的改用 CLI）冲突。建议用户确认后把第 61 行这半句改掉，免得下一个 Agent 读错。
6. 候选文件现在可写（见第 2 节），续审前要逐文件核对哈希、设回只读。
