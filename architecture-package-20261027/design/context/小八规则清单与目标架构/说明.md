# 规则提取说明（所有任务卡共用）

目标：把散在测试、踩坑、入口文件里的“小八必须遵守的规则”提取出来，供主力合并成一份总清单。

## 边界

- 只读。唯一允许写的文件是任务卡指定的那一个回执文件。
- 不改任何代码、测试、笔记，不运行会改动系统的命令，不新建备份。
- 不确定的地方不要猜：打开原文件看；看了仍拿不准，在“存疑”列写明拿不准什么。

## 怎么提取

1. 一条规则写成一句完整的中文，用“必须……”或“不得……”的句式，说的是小八的行为，不提函数名、变量名、文件名。
   - 好：后台超时后不得自动更换模型。
   - 不好：test_timeout_does_not_switch_model 通过。
2. 多项测试守的是同一条规则，就合并成一条，把这些测试都列进来源。
3. 测试函数名看不出规则时，必须打开对应测试文件读函数体再写。
4. 每条规则标一个类型，三选一：
   - 守规则：换一套实现也必须成立的行为约束（安全、诚实、不越权、失败即停、数据不被篡改等）。
   - 功能细节：只跟当前这个功能的具体做法有关，实现换了就该重写。
   - 退役守卫：保证某个已删除的东西不会回来。
5. 输入里的每一项都必须出现在某一条规则的来源里，不许漏。

## 回执格式

回执文件是一个 Markdown 文件，内容依次是：

1. 一张表，列为：`编号 | 规则 | 类型 | 来源 | 存疑`
   - 编号用任务卡给的前缀加三位序号，例如 `T1-001`。
   - 来源写 `文件名::函数名`，多个用 `<br>` 分隔；文档类来源写 `文件名 > 小标题`。
   - 没有存疑就留空。
2. 一行统计：`输入 N 项，已归入规则 N 项，规则共 M 条`。两个 N 必须相等。
3. 一节“我没有做到的”：读不了的文件、没看懂的测试、跳过的内容，如实写；没有就写“无”。
