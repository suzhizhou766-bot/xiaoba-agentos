# 后台双审协作：无具体后台绑定的模块契约

## 1. 职责与边界

双审协作模块仅负责：接收本次审查计划、核验独立性与能力、调度独立执行、汇总可追溯结果、按本次策略判定材料是否齐备、返回审计证据。

模块不内置任何具体后台名、厂商、驱动白名单、模型、设置文件路径、账号、上游、固定主备组合或自动选择默认组合。不能把真实名字换成内部固定的 reviewer_1/reviewer_2 槽位后继续按槽位绑定实现。

审查数量、预算、并发、等待与替换策略由外部已授权的任务策略传入；模块不再各自重复写一组默认值。双审任务由外部策略表达需要两份独立审查，模块按通用策略核验。不能借此取消既有独立性、证据、权限和用户裁决门禁。

## 2. 三个分离的对象

| 对象 | 负责什么 | 不负责什么 |
|---|---|---|
| 后台插件注册表 | 发现已登记插件、接口版本、能力、依赖、健康入口、实现指纹与实际身份来源 | 不指定谁永久是主审或备用 |
| 本次任务审查计划 | 引用本次选择的参与者及策略，携带任务输入/产物摘要、计划版本与选择来源 | 不改变模块代码或客户端认证 |
| 通用双审协作引擎 | 消费注册表与计划，执行与校验，返回各来源原始结论和回执 | 不按后台名字、厂商或模型做业务分支，不内置失败时默认换谁 |

模型与客户端读取方式归具体插件；核心只校验插件接口、能力、批准状态和执行证据。缺少明确计划或未知插件时返回可诊断错误，不默认当作任何已有后台。

## 3. 接口形状（无预置实例值）

```text
BackendRegistry.discover(required_capabilities) -> BackendDescriptor[]

BackendPlugin.run(task_input, execution_policy) -> RunReceipt

ReviewPlan:
  participant_refs[]
  policy_ref / policy_snapshot
  input_evidence_refs[]
  artifact_digests[]
  selection_provenance
  plan_revision / plan_digest

ReviewEngine.execute(review_plan) -> independent_results[] + receipts
ReviewEngine.evaluate(review_plan, independent_results) -> validation_record
ReviewEngine.replace_participant(previous_plan, replacement_request) -> new_plan_revision
```

以上字段是概念契约，不是可以直接写进生产的配置格式。没有插件目录、模型、后台实例或阈值默认值；具体配置结构由有权限的实现者同批设计、审查和迁移。

## 4. 自由更换与证据稳定

- 新任务可从已启用且满足能力要求的插件池选择任意合格组合，不以历史默认组合限制用户。
- 工作阶段的贡献者与审核阶段的审查者分别记录；移除“审查必须使用工作阶段同一完整名单”的身份绑定，改核验真实贡献与集成证据。
- 已启动任务的参与者写入本次计划，目的是追溯执行来源，不是把后台绑定到模块。任务中途换人要生成新计划版本并记录原因、旧调用处置和实际新执行。
- 不把旧后台的 PASS、身份、模型或哈希改标成新后台。可沿用的未变证据必须按依赖关系说明来源，新增/替换来源必须真实执行。
- 同一实际审查来源不能通过改名、别名或重复登记充当多份独立意见。独立性核验不依赖字符串名字不同。
- 已有实质 FAIL、分歧、失败历史保留，不能通过无痕换人抹掉。
- 插件的工具、联网与权限能力显式声明；不能因为换一个 backend_id 就继承旧后台权限。

## 6. 插件与配置变更的发布边界

先进行一次核心解除耦合的正常发版；之后新增或替换符合既定接口且已审核的后台插件、用户调整任务参与者，不应重发核心。插件采用自己的审核、指纹与启停流程；审核来源也由当次计划选择，不写死某两家。

本次只修改架构阅读材料、预览与任务卡。正式配置、规则、技能与相应运行改造按 AGENTS.md 第 6 节交由能弹需确认的 Agent；不由 Codex 绕过权限实施。版本归属由用户安排，不擅自解除现有 v1.6.5 候选冻结或生产切换边界。

## 7. 验收条件

1. 换成任意另一组已登记、满足能力与独立性要求的后台，无需改核心源码或模块常量。
2. 模块中没有具体后台名、模型、客户端路径、驱动白名单、固定主备或默认接替组合；缺计划时报错。
3. 一个新测试插件能通过注册后参与审查；未知插件不回落到已有驱动。
4. 工作与审查阶段可选择不同来源，证据和真实身份仍可追溯；别名重复来源不能凑独立票。
5. 构包、切换、经验验证与页面均认可相同的任务计划和实际证据，不再依赖包模板名单。
6. 中途换人、并发与重试保留原历史，租约、B19、B20、配置一致性和用户人工裁决不变弱。
7. 没有外部调用成功、必要审核和正式发布证据前，只报告实现/测试所在阶段，不宣称线上已可随意更换。
