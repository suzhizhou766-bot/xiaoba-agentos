通用双审协作：后台可自由更换

已确认架构 · 模块不添加具体绑定值 · 正式运行改造待实施
  1. 1
    已审核后台插件池
    按接口、能力、依赖、健康和真实身份发现可用参与者；不设固定客户端名单
  2. 2
    外部本次任务审查计划
    选择参与者与审查策略；数量、权限、预算、并发、接替条件均由计划传入
  3. 3
    通用引擎执行
    按计划分派、维护租约、验证能力与执行权；未知插件或缺计划时明确报错
  4. 4
    独立结果与证据核验
    核对真实身份、实际运行、输入/产物摘要与 B19 输出，按本次策略判断审查齐备
  5. 5
    汇总与原子结算
    保留各方结论、分歧与替换历史；结果＋审计/候选只结算一次
模块边界从哪里取得
具体后台与实现外部已登记插件池
本次参与者用户授权的任务审查计划
数量、独立性、主备/替换策略本次外部策略；模块不内置默认组合
模型、客户端命令、设置来源各插件按用户选择解析；通用模块不指定
证据与回执实际运行、真实来源和任务计划版本
分工协作与集成审核
工作计划→实际贡献与回执→宿主集成＋测试→新审核计划→独立审查
  • 贡献者和审查者分别选择，不要求固定同一完整名单。
  • 新审查核对真实工作和集成证据，不能把工作建议当作审核结果。
自由更换与独立性
  • 新任务可选择任意满足能力与独立性要求的已启用后台组合，核心无需因换人改代码。
  • 中途换人形成新任务计划版本，记录原因、旧调用处置与新执行；不无痕改写历史。
  • 同一实际来源不能通过改名或别名算成多份独立意见。
  • 合格 FAIL、分歧与旧来源保留，不能通过换人抹掉。
  • 替换条件从外部策略传入；能力和授权不因换一个 ID 自动继承。
外部等待策略、租约与恢复
现有等待策略连续 300 秒未观察到真实进展；这是当前共享策略口径，通用模块不再另设内置阈值
进展非空模型流增量、可识别阶段推进；PID/心跳/续租不算
执行权按 attempt 核对和续租；失权就停止旧进程，不代替新执行者结算
健康恢复更新健康不会自动解冻；新鲜探针来自用户重新上班
显式恢复按本次计划与恢复授权核验来源、旧证据和实际新执行
当前代码与本次架构的差距
候选代码仍有具名驱动白名单、固定备用限制、工作/审核同名单要求及发布切换的具名成功集合。本次已改架构与预览，运行改造尚未实施；解除点与正反例验收已写入工作区任务卡。不能将页面更新称为生产后台已可任意切换。

分类流程
audit 技术审计结果与审计回执原子结算，不生成经验卡
rule 用户规则有用户明确依据，初审与终审由用户作出
method 方法经验初审 → 真实执行与独立验证 → 用户终审 → 发布
两套检索范围
正式经验索引已发布且有效；回读原文后作为正式经验复用
待验证索引初审有效、仍需验证；只作为本任务内的待验证资料，不混入正式长期记忆
交付与回流的判断边界
  • 旧经验实际使用后回原卡；新经验仍从初审开始。
  • 仅检索、仅阅读、旧版本或无证据不能算验证完成。
  • 匹配分与回答排名分不能代替经验验证分；具体量表尚未确定。
  • 重复口令和回调只结算一次；内容/初审/成品变化使不匹配的旧证据失效。
  • 本次成品验收不会自动批准经验初审或终审。
  • 本次设计尚未替换现行隔离试验门禁，需代码与验证同批接入。
