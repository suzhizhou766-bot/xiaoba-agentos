## 4. 已核实的实施阻断

| 阻断 | 源码定位与结论 |
|---|---|
| 两套验证未贯通 | 原生 `experience_workflow.trial_summary/require_final_trial` 读取试验、agent_runs 与 judge 事件，不读取 review-ingress；接入回执不能自动赋予终审资格 |
| 两轮状态机缺失 | `link_trial_tx` 无轮次上限，`trial_summary` 取最后一个有效绑定试验；尚未实现两轮结算与第二轮失败退役 |
| 发布中断无受控恢复 | 中心先记录 running/publishing 再执行 apply；进程崩溃可能遗留全局发布锁，缺少受控现场核对恢复入口；普通超时能返回失败，但未知结果未得到独立强制阻断 |
| 新旧规则生成冲突 | agentos_version、build_second_brain、build_release 仍有旧后台/协议说明及旧验收约束；必须检查生成后的最终产物 |
| 协作及证据治理 | 初审约束、回执证据绑定、计划替换与接收端失效传播需统一；只读 GET 不应触发转换或投递 |
| 本机安装链不完整 | 新模块正式包布局、迁移、首次安装、自更新控制进程与回执持久化需要受审方案 |
| UI 安装冲突 | review_ui_install.prepare 对现场摘要不属于 before/after 的资产报错；整批 prepare 完成前不能进入安装，不能只处理页面而忽略其它资产 |

需避免扩大结论：原生 switch_release 已校验包内容、版本与切换脚本一致性，不能称完全无正式包校验；候选 `expected_version=v1.6.5` 本身不证明已发布；模块目录仅规划而未实现和八视图/九模块不是数量错误；守门代码写入候选不等于已覆盖当前执行器，但其受审升级边界仍需建立。
