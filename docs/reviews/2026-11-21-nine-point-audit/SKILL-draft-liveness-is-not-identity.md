# 存活不是身份

## 触发条件

准备把下面任一信号当成“就是它”或“这里没有它”时先停下来：

- `kill -0`、进程还在、PID 文件里有数字
- 命令退出码为 0，或退出码非 0 但没有读到错误文本
- 探测超时、命令不存在、输出为空

小八 AgentOS 里已经发生过两次同类分叉：端口探测把 lsof 失败当成没人监听（活动树后来分成三态）；监管进程把任意存活 PID 当成看护，关闭脚本还会向它发信号（2026-11-21 审查复现并收口）。

## 检查步骤

1. 写出这个信号的三种结果：确认是、确认不是、不知道。
2. 找到真正拥有状态的那一层（写 pid 文件的进程、发信号的脚本、记成功的事务），不只看最外层提示。
3. “不知道”时不要发信号、不要接管、不要再启动一个、不要记成成功。
4. 若同一规则在 shell 和 Python 各写一份，改成同一个函数，或加一条测试锁住两边的关键字。
5. 用一个无关但仍存活的进程做反例。不要只用“进程已退出”当反例。

## 证据要求

- 指出文件、符号和引入该判定的提交。
- 至少一条不依赖生产机器的复现：无关存活 PID，或探测命令缺失。
- 写明没有跑过的环境。小八监看的固定解释器在用户 Mac 上，云端通过不能写成 Mac 验收。

## 边界

- 这个草稿只概括上述两处已核对的代码路径。它不证明经验结算、死信或评分门也有同样的洞。
- 固定解释器路径是发版约束，不是探测失败。不要为了让测试在 Linux 上变绿而换掉它。
- 关闭脚本在 lsof 退出码既不是 0 也不是 1 时打印“查不了”并退出 0，是现有测试锁住的行为。改变退出码要单独取得同意，不能借这条草稿直接改。
- 不要把本草稿写进 `release/second-brain/`。那是 v1.6.1 发布快照，不是现行知识库。
