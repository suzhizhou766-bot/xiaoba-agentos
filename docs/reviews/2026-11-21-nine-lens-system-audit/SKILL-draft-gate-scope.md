# 新门默认最小范围

## 触发条件

准备加入或收紧以下任一机制时使用：

- 价值分 / 干活分 / 复用分
- 发布验收 / 宿主补票
- 工作日台账、死信、旁路投影
- 回执页眉或合同新字段
- “缺 X 就失败”的结算前置条件

## 已付过的学费（仓库内）

- v1.6.10 卡 57/58：价值分门打到普通任务 → 热修两轮，改回“无审查来源则旧路径”。
- v1.6.12 卡 64：台账曾影响结算观感 → 改为纯旁路。
- 卡 56：回执页眉字段写入与读取不同步，演练才发现。

## 检查步骤

1. 列出**适用任务类**（例如：仅宿主审查 / 宿主补票 / 发布验收）和**明确不适用类**（例如：普通交付、无节点任务）。
2. 写出不适用时的行为：失败 / 跳过 / 走旧路径。默认选**走旧路径**，不要默认失败。
3. 找到真正写状态的一层（结算事务、事件链、评分账本），确认外层提示与写层谓词一致。
4. 投影层（台账 Markdown、监看卡片）不得反写控制谓词。
5. 新字段：同一变更里同时改写入点、读取点、合同文档、至少一条正测与一条“不适用”测。

## 证据要求

- 测试名或用例需覆盖“适用”与“不适用”各至少一条。
- 提交说明写清门的适用范围，避免只写功能名。

## 边界

- 用户已裁定的经验双审与终审门槛不在此技能里放宽。
- 高风险硬底线（凭据、付款、删除、对外发送、发版）不因“最小范围”被绕过。
- 不要为了让 Linux 云端测试变绿而放宽固定解释器或端口隔离。
