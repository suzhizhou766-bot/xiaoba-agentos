# 拓扑的工程展开

2026-10-30 起草。拓扑是一张图，有些规则画不出来，这里写清楚：审查怎么调用、经验卡有哪些状态、交付怎么结算、自动步骤谁来跑、数据以谁为准。和拓扑冲突时以拓扑为准。用户 2026-10-30 定的裁决已写入，见 `DECISIONS.md`。

## 1. 审查是一个子流程

身份任务卡到实际来源确认这一段被三种用途共用。把它当成一次调用：调用方说清审查类型，结果按类型回到各自的下一步。

| 审查类型 | 什么时候发起 | 回执里什么说了算 | 结果去哪 |
|---|---|---|---|
| 新经验价值分 | 交付后，或试错放弃后 | 评分（0–10）；结论只用来标 NEEDS_INFO | 评分中心 |
| 复验 | 待验证经验在真实任务里用完后，通常在交付前 | 结论（通过 / FAIL / NEEDS_INFO） | 验证材料 → 第 N 轮结果 |
| 复用改动 | 复用正式经验时有改动或不适用 | 结论，加改了哪里、补充了什么、摒弃了什么 | 验证材料 → 复用计分 → 裁决中心 |

宿主既没产生新经验、也没用经验时，不发起审查。协作员的工作回执面向宿主，不属于审查。

**回执字段（合同第 2 版）**：回执 ID、任务卡摘要、审查请求 ID、任务卡 ID、审查类型、审查员、结论、理由、证据引用（必须指向任务卡给的材料）、评分（0–10）、适用条件与限制、与已有经验重复（可空）、开始和结束时间。缺字段或证据引用指不到任务卡材料，算不合格：不算完成、不计分，按 NEEDS_INFO 处理。

**盲审**：审查期间回执先放各审查员自己的目录，齐了才收进共用的 `回执/`。任务卡里不放别的审查员的结论。

**迟到回执**：换人后，旧任务卡的回执不再计入，但保留记录。

**独立性**：看“入口程序＋模型”。同一个入口用 A 模型、B 模型算两个；改名字不算。

**宿主算一票的条件**：这次没亲自干活、也不是这条经验的作者。全部审查员不可用时可以兜底，但要在终审材料标明“无独立审查”。

**掉线判定**：默认连续 300 秒没有工作进度，可按节点调；人工转交的外部 Agent 不自动判。工作进度看工作日志有没有变化，不靠 JSON 事件（卡 11）。用户在场通道（tmux）等待用户和 Agent，也不自动判。

**用户在场通道（tmux）**：上下文不隔离，只能当协作员，不计入独立审查。只认文件回执，不读屏幕，不替用户确认，发送后不重发。

## 2. 判定边界

| 回执情况（等全部到齐） | 复验结果 | 新经验 |
|---|---|---|
| 全部通过 | 本轮通过 | 看分数 |
| 第一轮有 FAIL | 本轮未通过，进第二轮 | 看分数，FAIL 不单独起作用 |
| 第二轮全部 FAIL | 未通过，退役 | 同上 |
| 第二轮有人通过、有人 FAIL | 有分歧，带着分歧交用户终审 | 同上 |
| 第二轮有 FAIL 也有 NEEDS_INFO，没人通过 | 暂停补材料，不耗轮次；补完再判（全部 FAIL 才退役） | 同上 |
| 没有 FAIL，有 NEEDS_INFO | 暂停补材料，不耗轮次 | 暂停补材料 |
| 审查员掉线 | 只停这次审查，任务不停，用户说“交付”照常有效；问用户换人，全部不可用时把宿主兜底作为一个选项 | 同左 |
| 协作员掉线 | 暂停任务，问用户换人 | 不适用 |
| 调用故障（网络、认证、工具） | 暂停，不耗轮次，不算失败 | 同左 |
| 合格回执少于 2 份 | 不判定 | 不判定 |

**新经验判定顺序**：先看分歧（最高最低相差 ≥ 4），分歧大就交用户初审；不分歧再看平均分，≥ 6 进初审，否则丢弃：不进用户队列、不留正文，事件链留摘要和各审查员分数。这两条线先用 2–4 周，看过滤记录再调。与已有经验重复的，交用户初审。分数线写进带版本的策略文件，每次判定记下所用版本。

**输出验收**：DSH `--json` 必须有结束事件（`final` 或 `turn_end`）才算答案；协议坏行不判成功，横幅行允许；进程退出码非 0 时由 stderr 决定重试还是停止。

## 3. 经验卡状态

| 状态 | 什么事件 | 条件 | 下一状态 |
|---|---|---|---|
| 待审查 | 分数判定 | 放行 | 待初审 |
| 待审查 | 分数判定 | 不放行 | 已丢弃 |
| 待审查 | 用户选宿主兜底 | 全部审查员不可用 | 待初审（标明无独立审查） |
| 待初审 | 用户批准 | | 待验证第一轮 |
| 待初审 | 用户拒绝 | | 已退役 |
| 待验证第一轮 | 本轮结果 | 通过 | 待终审 |
| 待验证第一轮 | 本轮结果 | 未通过 | 待验证第二轮 |
| 待验证第 N 轮 | NEEDS_INFO、掉线或调用故障 | | 暂停（记下原轮次，恢复后回原轮次） |
| 待验证第 N 轮 | 任务放弃 | | 回到本轮等下一个相似任务，不耗轮次 |
| 待验证第二轮 | 本轮结果 | 通过 | 待终审（带两轮差异） |
| 待验证第二轮 | 本轮结果 | 有分歧 | 待终审（带分歧和两轮差异） |
| 待验证第二轮 | 本轮结果 | 全部 FAIL | 已退役 |
| 待验证第二轮 | 第二轮前改了正文 | | 待初审（新版本，已用轮次不清零）；通过后回待验证第二轮 |
| 待终审 | 用户批准 | 发布检查通过 | 正式 |
| 待终审 | 用户批准 | 发布检查未过 | 待终审（带失败原因） |
| 待终审 | 用户退役 | | 已退役 |
| 正式 | 复用有改动，用户批准 | 发布检查通过 | 正式（新版本，旧版本保留） |
| 正式 | 14 天未用，用户保留 | | 正式（重新计时，永久总分不清零；下次间隔依次延长到 30 天、90 天） |
| 正式 | 14 天未用，用户删除 | | 已删除 |
| 已退役 | 用户确认删除 | | 已删除 |

待验证经验由宿主或协作员使用，用的时候告诉用户；带命令的经验先进沙箱；审查员必须看到应用记录和产物；30 天没碰到相似任务就提醒用户，不自动退役。

退役不复活（B12）：要重新启用，作为新候选从头走。每张卡绑定：经验卡 ID、正文摘要、初审回执、轮次、任务 ID、应用记录。正文或初审变了，旧证据失效；已用轮次不重置。

一条经验在同一轮里被多个任务应用时，本轮绑定最先发起审查的那次应用；终审按绑定的应用检查，不按“最新一条”。

## 4. 任务与交付结算

任务状态：进行中 → 待交付 → 已交付；或进行中 → 已放弃（只有用户试错放弃才有）。面向用户的任务没有“失败”结局。

一次交付结算（键：任务 ID＋成品版本），在同一事务里写：交付事件、归档待办、新经验登记、应用记录核验、计分待办。后续动作按待办逐个完成，失败只补失败的一项。

- 重复说“交付”不重复结算；引用、否定、讨论“交付”不触发；任务或版本不明确时先问。
- 同一任务多次交付（改了新版本），每条经验最多 +1 一次。
- 用户撤回验收：记撤回事件，撤销这次带来的 +1。
- 事件链损坏时：交付记录照常（用户不被拦），经验和计分待办排队，修好后补做。

**汇合规则**：验证材料节点等“审查结论”和“交付事件”都到才写本轮结果，谁先到谁等；重复到达不重复结算。

**收据门禁**：普通任务结算前必须验证收据；损坏的收据不覆盖；只比较这次新跑的收据，旧数据不追溯。经验审查回执核不过时暂停（`external_receipt`），不判失败。

**状态转换**：任务状态转换是原子的，租约和次数以数据库为准。

## 5. 自动步骤谁来跑

宿主只是一个会话，交付后可能已经退出。

| 步骤 | 谁来跑 | 宿主不在线时 |
|---|---|---|
| 入口校验 | `xiaoba` 入口，只在上班和派后台任务时 | 日常任务不经过 |
| 新经验审查派活、分数判定 | Worker | 照常跑；要用户处理的进“待你处理” |
| 掉线判定 | Worker | 照常判；进“待你处理” |
| 用户在场回执收取 | 监看服务，每 2 秒一次，页面关着也收 | 服务重启后继续收，绝不重发 |
| 回执校验、独立性核对 | Worker | 照常 |
| 协作员产出核验、宿主兼任审查 | 宿主 | 等下一个宿主接手（接续清单） |
| 14 天未用检查、待验证经验老化提醒 | 上班时批处理；没说上班就在下一次写台账时补做 | 不需要宿主判断 |
| 台账建立和索引写入 | `xiaoba` 工具命令 | 不依赖模型手写 |
| 检测报告 | 上班时本地检查，落文件；运行总览只负责显示 | 总览没开也能读文件 |

## 6. 数据以谁为准

| 数据 | 权威 | 台账里的角色 |
|---|---|---|
| 任务、经验卡状态、事件 | SQLite 和事件链 | 只读视图 |
| 回执、审查证据 | 结算时按哈希入库（长期存储） | 工作副本，可被用户清理 |
| 索引 `_索引.jsonl` | 只负责定位文件 | 工具追加写入，多宿主写时加锁 |
| `台账.md` | 不是权威 | 从索引生成，给人看 |
| 评分三本账 | SQLite，和事件同一事务 | 导出到 `工具/模型综合数据` |
| 经验最后使用时间 | 长期库 | 不靠台账反查 |
| 成品 | 项目目录 | 只记路径 |

## 发布与切换

- 构包：源目录任何层级有软链就拒绝；先写同级临时目录，校验后改名；schema 版本从进包代码读。
- 经验发布：底层函数也要求已批准状态；记录阶段，重试能认出自己上次写的文件。
- 版本切换：持久记录阶段，`recover` 查询，`resume` 续跑。现场和记录对不上时拒绝续跑，转人工；不自动回滚。
- 发布中心：用文件锁分清持有者是否还在；确认接口固定记为页面用户。

## 7. 评分三本账

| 账 | 记什么 | 怎么算 | 用途 |
|---|---|---|---|
| 价值分 | 一条新经验值不值得进初审 | 每个审查员 0–10 | 准入判定，一次性 |
| 干活分 | Agent＋模型＋角色这周干得怎样 | 宿主核实后好 +1、不好 0；不合格回执不计；同任务只算一次；同时显示任务数和成功率；只按周，不设永久总分 | 宿主选人时参考 |
| 复用分 | 正式经验实际用得怎样 | 原样好用且交付 +1；改过或不适用记 0、不扣分，并送终审；永久累计 | 检索排序 |

检索排序：先按相关性筛出匹配的，再按复用分从高到低取前几条；新入库、分数低的留少量位置。

## 8. 经验卡最少字段

标题、问题标识（problem_key）、任务类型、做法、适用条件、排除条件、必要环境、证据引用、来源任务、作者、版本摘要、状态、轮次、初审回执、复用分、最后使用时间。

## 9. 不在这张图上的

软件发版和生产切换（发布包、预检、切换、回读）不在拓扑上，图上的「终审通过后」只是经验发布检查。流程见第二大脑 `40_工作流/AgentOS发版流程.md` 和 `development/architecture-center/`。
