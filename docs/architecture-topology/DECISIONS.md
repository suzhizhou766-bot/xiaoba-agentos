## 三、三端调用方案

用户 2026-10-31 定：“cli用tmux，那web和desktop呢”“用户可以介入的”。原话和问题记在「用户在场通道」节点。

| 端 | 用户在场 | 无人值守 |
|---|---|---|
| CLI | tmux：发送读卡的话，权限框由用户批，写文件自动收 | 一次性调用 |
| 桌面 | 读卡、写文件，自动收回执；App 写不了时退回贴回 | 不接 |
| 网页 | 用户发送、贴回，小八校验 | 不接 |

下面三条是卡 11 真实调用的结论（只有一次样本，且这轮被中断），不是用户裁决：

- 无人值守的 AGY 节点只接不用跑命令的活：命令会被权限系统自动拒绝，整轮中断。要跑命令走 tmux，不用 `--dangerously-skip-permissions`。
- 判断掉线只看工作日志有没有变化：JSON 事件到进程退出才一次性出现。
- 派工卡要求分步写日志，掉线时限按节点调：模型读卡就用了 52 秒。

用户 2026-11-01 定：“配置里的模型名就是实际使用的模型”“Agent节点配置信息都是用户自己设定，测试连通通过即可，小八只需要读Agent节点配置信息以及调用Agent发任务卡读回执”。所以小八不确认模型，也不设模型比对门禁；独立性按配置的入口程序＋模型判断。
