# 小八架构拓扑

用户维护的小八架构设计底座。用户在交互页面上增删节点、接入或断开连线、写下每个模块的意图和问题；这里是它的快照，供所有接入的 Agent 读取。

## 先读哪个

| 文件 | 是什么 |
|---|---|
| [AGENT_READER.md](AGENT_READER.md) | 文字版：每个分组的节点、状态、用户意图、代码位置、问题与待办、全部连线和按日期的变更历史。**Agent 从这里开始读** |
| [topology.json](topology.json) | 拓扑原始数据：`groups`、`nodes`、`edges`，`savedAt` 为快照时间（毫秒） |
| [changes.json](changes.json) | 变更记录（新→旧）：`op` 为 add / edit / del / link / unlink / submit / agent；删除和断开的原内容在 `before` 里 |
| submissions.json | 用户的提交记录（有提交后才出现）：每轮的大白话原话、期间改动、整理状态 |
| [topology-page.html](topology-page.html) | 交互页面源码，留作维护 |
| [render_reader.py](render_reader.py) | 由两个 JSON 重新生成 `AGENT_READER.md` |
| [DECISIONS.md](DECISIONS.md) | 已定的裁决、旧规则覆盖表、哪份文档说了算 |
| [CONTRACTS.md](CONTRACTS.md) | 图上画不出来的规则：审查调用、状态表、交付结算、谁来跑、数据以谁为准 |
| [scenarios.json](scenarios.json) | 设计场景，也是页面“模拟运行”的来源 |
| [module-map.json](module-map.json) | 节点到九模块的归属 |
| [check_topology.py](check_topology.py) | 同步后运行：查悬空连线、分叉说明、场景能否走通、读本是否最新。不查页面内置的基线（BASE）、文字语义，也不查和代码是否一致 |

## 规则

- 实时版本在用户的 claude.ai 页面里（由用户本人打开和修改）。本目录是同步快照，以 `AGENT_READER.md` 开头的快照时间为准；用户在页面上的修改要再同步一次才会出现在这里。
- “用户意图”写的是用户想要的样子。代码和它不一致时，向用户报告差异，不要自行改图，也不要直接改这里的 JSON 冒充用户修改。
- 状态为“待用户裁定”的节点，裁定前不要实现。
- 动手前先看变更历史，避免重做用户已删除或已改掉的东西。
- 用户在对话或语音里定的事，也要写进 `submissions`：记原话和当时问的问题。只回答“5、b”“可以”时，把问题一起记下，否则别的 Agent 看不懂。
- 标“待确认”的不是用户决定，括号里只是建议。

## 用户提交与 Agent 整理

用户在节点的“我的想法”里用大白话写，点“提交本轮修改”后：原话进入该节点的 `history`（`by: "user"`）和变更记录，节点标 `pending: true`，并生成一条 `submissions` 记录（`status: "pending"`）。用户说“整理拓扑”时，能读写云端数据的 Agent（目前是 Claude）按下面的规则整理：

1. 读全部 `status: "pending"` 的提交和当前拓扑。
2. 逐个节点按用户原话改写名称、一句话说明、用户意图、详细说明、位置、问题与待办。只表达用户说过的意思，不添加用户没说的方案；拿不准的写进“问题与待办”，以“待确认：”开头。需要时可以补代码位置等事实，但要能核实。
3. 每个改写过的节点追加一条 `history`：`by: "agent"`、`agent`（谁整理的）、`text`（改了什么、为什么）、`before`（被改字段的旧值）；`pending` 改回 `false`。原话不删、不改。
4. 写回拓扑时带上读到的版本号，避免覆盖用户刚做的修改；把提交记录改为 `status: "done"`，填 `result`、`doneAt`、`agent`；每个节点在变更记录里写一条 `op: "agent"`。
5. 向用户逐条说明整理结果，再同步本目录和 `私人助理/工作区/小八架构拓扑/` 两处快照，运行 `check_topology.py`。

## 页面上的辅助功能

- **树状视图**：工具栏「树状视图」把拓扑按连线一层层展开成工作树。同一节点只在离起点最近的位置展开一次，别处显示「↪ 见上方」，点击跳过去；默认展开前五层，悬停看上下游，点节点在右侧检视。
- **悬停看上下游**：鼠标停 0.25 秒后，详解停靠在画面四角里遮挡最少的一角（不贴着节点），列出上游（从哪里来，橙色）和下游（往哪里去，蓝色），图上对应的线和节点同时高亮；停在收起的分组上，列出进出这个组的节点；停在连线上，显示从哪到哪。工具栏「悬停详解：开 / 关」可关闭弹框，只保留高亮。
- **模拟运行**：工具栏「▶ 模拟运行」让一个虚拟任务沿预设链路走一遍，经过有问题或待裁定的节点时闪红框。只是演示，不改数据。预设链路来自 `scenarios.json`，同步到页面的 `SCEN`；图改动后 `check_topology.py` 会报出走不通的场景。
- **保存防覆盖**：页面保存前比对云端保存时间。如果 Agent 或其它窗口刚改过，不会覆盖，页面顶部让你选“载入云端最新”或“用本页覆盖云端”。页面写入本身没有版本校验，两个窗口同一瞬间保存仍可能互相覆盖。
- **跟讲**：讨论时 Agent 往云端 `topology/pointer` 写 `{at, nodes, edges, text}`，页面自动把镜头移过去、标紫色并显示这句话；可带 `questions: [{n, title, text, nodes}]`，点框里的节点名会聚焦该节点并展开与它有关的完整问题。只在文字对话里能用。
