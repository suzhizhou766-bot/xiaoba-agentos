# v1.6.5 关键集成契约草案

日期：2026-10-27（Asia/Shanghai）。源码审计基线：`9c6360a3ede8a05ba80bf1549aba76e1ad4662fc`。

本文件将已确定业务规则展开为工程建议，供本地实施和独立审查。业务规则沿用用户裁决；以下新增状态名、字段与接口是草案，不表示已实现、已批准迁移或可以正式切换。

## 1. 唯一核验结论与两轮状态机

**已定业务规则**：初审有效后最多两轮；第一轮通过待终审，第一轮失败进入第二轮，第二轮通过须展示差异，第二轮失败退役；异常暂停，不冒充经验验证失败；终审批准由用户作出。

**工程建议**：由核心经验状态机作为唯一核验结论权威。review-ingress 负责接入、任务计划与证据归集；原生隔离执行负责运行证据；两者不得各自独立授予终审资格。裁决中心、CLI、待验证索引、交付回流及终审入口调用同一查询与转换服务。

每个验证批次绑定：candidate_id、candidate_sha256、有效 initial_review_id、验证谱系 ID、round（1/2）、task_id、plan_revision/digest、执行证据摘要、DSH 和第二方 assignment/receipt、验证策略版本。记录事件和事务性状态，不能只靠“最近一次试验”推断轮次。

建议状态：待第一轮、第一轮执行中、待第二轮、第二轮执行中、待终审、已退役；另有调用暂停状态，保存原轮次和暂停原因。命名在实现时统一映射原状态，不能新增另一套平行批准路径。

| 输入 | 状态变化与约束 |
|---|---|
| 有效初审通过 | 建立第一轮待验证；已有谱系不因重复回调重建 |
| 当轮证据齐备且必要检查/审查通过 | 第一轮进入待终审；第二轮还须有有效差异说明 |
| 当轮已完成且明确验证失败 | 第一轮进入第二轮；第二轮退役并从可用索引移出 |
| 工具、认证、网络异常或证据不齐 | 暂停或保持未完成，保留轮次；不扣作有效失败、不自动重试 |
| 同轮重复回执/并发结算 | 幂等处理；同一绑定内容冲突拒绝，保留冲突事件 |
| 用户终审 | 重新检查候选、初审、轮次和全部必要证据，只有同一权威门禁通过才允许批准 |

**正文/初审改变的建议处理**：旧证据立即不再赋予当前版本终审资格，失败及已用轮次历史保留。第二轮整改形成新的正文版本时，须有该版本有效初审并继续关联原验证谱系和轮次，不能用编辑正文重置次数。新建候选、撤回初审和重新开启谱系的权限/迁移规则需明确审查，不能自动“换卡重试”。

验收：第三次试验关联被拒；开放侧实质 FAIL 不能由原生成功绕过；历史 PASS 不能盖过当轮失败；异常不进入第二轮；第二轮差异缺失不能待终审；正文漂移不能批准；旧数据迁移不猜测成功或批准。

## 2. 开放审查、证据及交付回流

固定 DSH＋开放第二方。用户已给出的 Agent、桌面/Web/CLI 形态、入口、模型直接绑定计划；不再次核实模型。证据完整性检查针对任务材料与执行结果，不重新引入模型来源自证。

建议：方法经验的验证请求要求当前有效初审；若未来需要初审前辅助审阅，应显式采用不同用途，不得计入正式验证轮次。回执检查字段格式、冻结输入引用、实际输出摘要与当轮任务关联；允许本次执行产生的新证据，但必须解释其来源并绑定，不能只要求“引用与冻结输入有交集”就判有效。

参与者变更生成新计划版本。已提交材料需要可追溯的 supersede/revoke 传播及接收端确认；接收端同一验证批次仅一份当前有效材料。若保留未变 DSH 回执，须显式列出沿用依据和旧版本来源；不得改写旧回执 plan_revision。

真实任务交付提供应用、成品验收与评分证据。只有满足当轮隔离验证契约的证据才可用于当轮结算；不满足时回写原卡并展示缺口，保持待验证。引用“交付”不触发，重复交付按任务＋成品版本幂等。新经验仍先初审。

只读 GET 不准备任务、不改变状态、不投递。状态转换和投递采用明确写入动作或已授权后台作业；返回值区分请求已接受、投递成功、等待和失败。

验收：无关证据 PASS 被拒；替换后旧材料失效可回读；传输重试不重复执行 Agent；GET 前后库状态不变；retry 返回真实状态；每条实际使用经验独立关联效果与限制。

## 3. 跨模块发布批次与守门组件更新

建议新增 ReleaseBatch，关联多张模块提案的确定修订，不使用无限写入范围总卡。批次冻结：各模块 change_id/revision、文件前后摘要、依赖版本、测试/审查证据、目标版本、包内容摘要、安装路径及迁移方案。

聚合文件清单时检测同一路径冲突、遗漏依赖和映射不完整。任何成员卡、源文件或策略变化都使批次的旧预检失效。逐模块接续权限保持原范围；跨模块依赖用明确关联任务处理。

MODULES 的规范版本、实现状态、源码根、规范根、包内位置、现场安装位置及依赖应分别声明。`contract_version: 1` 只能表示格式版本，不能证明模块完整实现。八个视图与九个模块是不同粒度，补充多对多映射即可，无须强行一一对应。

守门组件（中心 core、模块范围注册表、确认接口、原生执行器）的修改可以提出受审候选；但当前候选不能改写正在使用的验收策略来给自己授权。宿主固定的可信执行入口、策略摘要及必要独立审查来自候选之外；升级这些可信根需单独的安装步骤与验证，不能用目标包自报的指纹充当信任来源。

验收：九模块同一批次完整入包；单卡改变使旧批次失效；冲突路径阻断；候选不能扩大当前执行权；当前守门实现仍能拒绝篡改的候选包；安装和移除范围可审查。

## 4. 首次部署、持久发布作业与中断恢复

首次部署由明确的本地安装任务建立监看入口和更新工作区，先在独立目录验证；此时不调用生产配置初始化数据库。随后通过受审安装方案接入实际服务。后续正式切换由用户在页面查看具体批次并确认。

建议页面向独立于被更新监看进程的发布执行器提交持久作业。作业 ID 在服务端分配，浏览器刷新后按批次查询同一作业。执行器的生命周期、可信路径、进程身份和回执位置在安装方案中明确，不能依赖浏览器连接存活。

建议发布状态分为：待确认、执行中、成功、已证实无改动的失败、已证实退回、结果未知/需现场核对。结果未知必须阻止新切换，不可仅凭超时或 PID 消失释放发布锁。

恢复入口只核对已存在作业：原生事务/回执、活动索引、源码/配置指纹、Worker、迁移进度和实际版本。充分证据决定成功、已退回或允许再次预检；没有证据则保持阻断并报告人工处理事项。恢复动作留审计，不自动再次执行 apply。

非零退出不得丢弃“需人工回读”信息。执行器超时和强杀可能发生在已部分写入后，不能归为普通干净失败。当前进程内撤销日志不提供掉电恢复保证；如方案需持久保存旧字节作为恢复副本，应明确其范围并取得所需备份授权，不能以改名规避用户备份边界。

正式包检查仍由受信原生流程承担；中心应保存并展示完整结构化结果，区分未登记、登记、核验通过与已发布。目标版本必须在用户确认前从经校验正式包绑定，基线从真实现场回读；未知基线可以保存草稿，但不能进入正式预检确认。

验收：网页刷新、网络断开、监看重启不重复发版；执行器崩溃保持阻断且可核对恢复；未知混合状态不能重发；干净失败和实际退回可区别；包校验及脚本一致性未通过不能执行；不人工删数据库锁来“恢复”。

## 5. 评分与选择策略

任务综合评分服务记录任务类型、经验实际应用、参与组合、用户给定模型、执行质量、验证结果、时长、返工、介入和可取得成本。保留原始观察、评分理由、量表/策略版本和缺失字段；避免把复用次数或一次总分当作普遍能力。

策略应分别定义资格过滤、评分维度/归一化、权重、数据新鲜度、最少证据要求、冷启动与同分排序。用户尚未指定数值，本草案不写入默认合格线。评分可在规则明确后排序，经验终审资格仍由第 1 节门禁判断。

冷启动工程建议：先按授权、任务适用条件和已登记调用能力筛选；历史不足明确标记，使用已审的确定性排序或显式任务计划，不伪造历史分，也不要求用户每个任务重新挑模型。任何探索性额外调用需有任务授权，不用探针补齐评分。

验收：无评分数据能解释选择来源；不同任务类型不会直接混比分数；缺成本不记为零成本优势；失败记录不因一次成功消失；策略改变能追溯当时选择；总分高不能绕过验证 FAIL。

## 6. 生成器、版本与运行环境闭环

同批更新 agentos_version、build_second_brain、build_release、协作契约、VERSIONING、配置模板及最终发布说明。生成后回读产物，验证旧后台拓扑、旧探针/补位行为和错误协议版本不会重新生成。候选目标版本、活动版本和正式发布日期分别记录；构包不可伪造 `agentos_multi_adjudicated` 来源以适配旧门禁。

解释器的开发兼容声明、固定生产解释器及测试环境分别记录。Mac 本地必须按实际受审解释器复跑；云端 Python 3.12 结果不能称为 3.14 验收。浏览器路径由本地测试配置提供。

监看进程检查至少区分“确认无监听”“存在监听”“检测不可用”；lsof 缺失/权限错误不能返回空结果伪装进程已死。UI 安装前应列全受影响资产的 before/现场/after 摘要，一处冲突按原生门禁阻断整次安装，先集成修正，不跳过哈希检查。

生产数据库变更通过独立迁移计划与显式安装阶段执行。未来运行器应有不写生产库的盘点/计划入口；开发试运行默认独立库。迁移包含旧数据兼容、事务边界和失败处置，不能把导入模块或查看页面作为隐含升级动作。

## 7. 实施顺序与完成定义

1. 统一经验权威门禁、两轮状态机与旧数据迁移契约。
2. 发布结果未知状态、恢复入口、独立执行器和守门组件升级边界。
3. 跨模块发布批次及生成器/构包/版本契约一致性。
4. 开放审查、交付回流、评分索引及规范补全。
5. 本机解释器、监看、资产安装、完整回归及正式包演练。

每批产出实际代码、正反例、迁移与兼容说明、绑定源码的独立审查；本文件本身不构成上述实现或验收证据。
